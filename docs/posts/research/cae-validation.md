# 模态试验与 CAE 对标怎样组织验证记录

> 有限元（FEA）模型能否真实反映结构的动力学特性，必须通过模态试验对标来回答。一套可追溯、可复用的验证记录，既是模型可信度的证据，也是后续设计迭代和问题排查的基础。本文整理 CAE 模型验证的完整流程、关键参数和报告结构。

## 一、验证流程总览

CAE 模型验证不是"算完对一下频率"就结束，而是一个闭环流程：

```text
试验规划 → 测点布置 → 模态试验 → 参数提取
    ↕
模型构建 → 边界/材料 → 求解 → 频率/振型提取
    ↘___________________________↙
         相关性分析 (MAC / 频率对比)
              ↕
        偏差定位 → 模型修正 → 复核
```

::: tip 核心原则
验证记录的目标是"让别人能复现你的结论"。每一步的输入、参数、输出都要落地为文件，而不是存在分析师的脑子里。
:::

## 二、边界条件与材料参数

边界条件和材料参数是 CAE 结果偏离试验最常见的原因，必须显式记录。

| 类别 | 需记录字段 | 典型问题 |
| --- | --- | --- |
| **约束边界** | 自由/固支/弹性支撑、约束位置 | 自由边界用悬挂，弹性支撑需测刚度 |
| **连接** | 焊点、螺栓、胶接、铰链的等效方式 | 螺栓刚度简化过度导致局部模态偏移 |
| **材料** | 密度 ρ、弹性模量 E、泊松比 ν、阻尼 | E 取名义值而未用实测，频率整体偏移 |
| **网格** | 单元类型、尺寸、质量指标 | 网格过粗使高阶模态漏掉 |
| **求解** | 特征值方法（Lanczos/Subspace）、频率范围 | 截断频率不足，遗漏目标模态 |

::: warning 常见陷阱
阻尼参数在模态分析阶段通常不输入（求无阻尼特征值），但在频响（FRF）验证时必须给出。阻尼来源（材料/连接/声辐射）不同，等效方式也不同，不能一概用 0.5%。
:::

## 三、模态试验与参数提取

试验侧需记录的关键信息：

```python
# 模态试验记录数据结构示例
modal_test_record = {
    "test_date": "2026-08-05",
    "specimen": "前副车架焊接总成",
    "boundary": "自由-自由（橡皮绳悬挂）",
    "excitation": "力锤（8 kHz 采样，硬塑料锤头）",
    "reference_points": ["P03", "P07"],   # 至少 2 个参考点
    "response_points": 42,                 # 总测点数
    "bandwidth_hz": 2000,
    "lines": 3200,
    "averages": 8,
    "window": "force/exponential",
    "extracted_modes": [
        {"mode": 1, "freq_hz": 86.3,  "damping_pct": 0.42},
        {"mode": 2, "freq_hz": 134.7, "damping_pct": 0.61},
        {"mode": 3, "freq_hz": 212.5, "damping_pct": 0.88},
    ],
}
```

::: tip 参考点选择
参考点必须避开目标模态的节点位置。建议先用两个不同位置的参考点预试验，确认各阶模态在两个参考点下都能被激发，避免"漏模"。
:::

## 四、相关性分析：MAC 与频率对比

### 4.1 MAC（Modal Assurance Criterion）

MAC 是衡量试验振型与计算振型一致性的核心指标：

```text
              | φ_testᵀ · φ_cae |²
MAC = ─────────────────────────────────
      (φ_testᵀ·φ_test)(φ_caeᵀ·φ_cae)
```

- **MAC > 0.9**：振型一致性好
- **0.7 < MAC < 0.9**：基本一致，需检查局部
- **MAC < 0.7**：振型不一致，可能模态顺序错乱或模型有误

### 4.2 频率偏差

```text
Δf% = (f_cae − f_test) / f_test × 100%
```

| 模态 | 试验频率 (Hz) | CAE 频率 (Hz) | Δf% | MAC | 判定 |
| --- | --- | --- | --- | --- | --- |
| 1 | 86.3 | 88.1 | +2.1% | 0.95 | 通过 |
| 2 | 134.7 | 131.2 | -2.6% | 0.88 | 关注 |
| 3 | 212.5 | 198.4 | -6.6% | 0.52 | 不通过 |

::: warning MAC 高 ≠ 频率对
MAC 只反映振型形状的相似度，不含频率信息。可能出现 MAC=0.95 但频率偏 15% 的情况，说明刚度或质量分布有系统偏差。必须频率和 MAC 同时看。
:::

### 4.3 频响函数（FRF）对比

除了模态参数，直接对比频响曲线能发现局部动力学问题：

```python
# FRF 对比的简化记录
frf_comparison = {
    "driving_point": "P07+Z",
    "f_test":  "frf_test_P07z.txt",    # 试验 FRF
    "f_cae":   "frf_cae_P07z.txt",     # 计算 FRF
    "freq_range": [0, 2000],           # Hz
    "metrics": {
        "peak_freq_error_pct": 2.3,
        "peak_amp_error_db": 1.8,
        "freq_domain_assurance_criterion": 0.87,  # FDAC
    },
}
```

## 五、验证报告结构

一份可追溯的 CAE 验证报告应包含以下章节：

1. **试验概述** — 对象、日期、设备、环境
2. **测点布置图** — 坐标、编号、参考点标注
3. **CAE 模型说明** — 软件/版本、网格统计、材料、边界、单元类型
4. **频率与振型对比表** — 含 Δf% 与 MAC
5. **FRF 曲线对比** — 关键测点，含峰値与相位
6. **偏差分析** — 不通过项的原因定位（连接？材料？边界？）
7. **模型修正记录** — 改了什么、为什么改、改后结果
8. **结论与置信度** — 模型在哪个频段可信、可用于哪类分析
9. **附件** — 原始数据文件、求解输入文件、脚本

::: tip 沉淀为模板
建议把上述结构固化成报告模板（Word 或 Markdown），每次验证直接填充。长期下来，模型修正经验和常见偏差原因也会积累成知识库，新人能快速上手。
:::

## 六、工程意义

CAE 模型一旦通过验证，其价值远超单次分析：

- **设计阶段** 预测结构动态特性，减少物理样机
- **问题排查** 基于可信模型做灵敏度分析，定位优化方向
- **传递路径分析（TPA）** 用验证过的模型生成逆矩阵
- **优化迭代** 在可信频段内做拓扑/尺寸优化

::: warning 范围声明
模型验证结论有**频段适用范围**。在 0–500 Hz 验证通过的模型，不代表 2000 Hz 的局部模态可信。每次使用都要声明模型的验证频段。
:::
