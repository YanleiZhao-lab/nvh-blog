# 专业 NVH Skill 与 MCP 服务的边界规划

> 随着大模型（Large Language Model，LLM）Agent 和 MCP（Model Context Protocol）生态的发展，把 NVH 工程能力封装成"AI 可调用"的服务成为可能。但专业工程计算与通用 AI 的文本生成之间有本质区别：前者是确定性算法，后者是概率性生成。本文梳理两者的职责边界，并以 FFT 链路参数、模态分析指标为例说明"哪些计算必须交给确定性工具、哪些解释可以交给模型"，表述对齐相关公开技术资料与相关技术手册的术语体系。

一个耐人寻味的现象：让同一个大模型算三遍"采样率 2048 Hz 时最大分析带宽是多少"，三次回答可能是 1024 Hz、1024 Hz 和 1023.5 Hz——前两次碰巧对了，第三次连"碰巧"都算不上。更麻烦的是，它每次都答得理直气壮，语句通顺、逻辑自洽，不给任何"我不确定"的信号。工程师拿到这样的回答没有任何办法复核对错，因为模型不给出推导过程，只给出"生成"的结果。这不是哪个模型的缺陷，而是这类技术的固有属性：它学到的是"语言的长什么样"，不是"数值的算出来"。于是一个现实问题摆在面前：当 Agent 生态开始承接 NVH 分析任务时，到底哪些环节可以放心交给模型、哪些必须守住"确定性计算"这条底线？

把这套分工想象成一家医院的架构：大模型是问诊台的分诊医生，擅长听病人描述症状、翻病历、判断"这大概要看哪个科"，然后把病人引导到正确的科室；但化验单上的血糖值、血常规计数，必须由检验科的仪器测出来——分诊医生再能说会道，也不能"估计"一个血红蛋白数值填进报告。NVH 工程里同理：模型可以判断"这是升速数据，该做阶次分析"，但 colormap 上那个峰在几阶几赫兹、幅值多少，必须由确定性算法从原始数据中算出。问诊与化验各有各的专业，越界就会出医疗事故——本文讨论的就是这条"科室边界"怎么划。

## 一、通用 AI API 与专业 NVH 能力的区别

| 维度 | 通用 AI API（LLM/多模态） | 专业 NVH Skill/MCP |
| --- | --- | --- |
| **能力定位** | 自然语言理解、通用推理、文本生成 | FFT 计算、模态分析、TPA、指标计算 |
| **输入** | 文本/图像 | 时间序列、频响数据、CAE 模型 |
| **输出性质** | 概率性生成，逐次调用结果可能不同 | 确定性算法，相同输入得到相同输出 |
| **错误后果** | 文本错误，人工阅读可识别 | 数值错误，可能误导工程决策 |
| **验证方式** | 人工阅读 | 与试验数据、标准判据对标 |

::: warning 核心区别
通用 AI 的输出是"看起来合理"，专业 NVH 工具的输出必须"数值上正确"。让 LLM 直接"算"FFT 或"估计"模态频率，本质上是让概率模型生成数字，结果不可复现，不能用于工程决策。
:::

## 二、为什么数值计算必须交给确定性工具

以 FFT 链路中最基础的三个关系为例。这三个关系在公开技术资料中被整理为数字信号处理的"黄金方程"（golden equation），每一步都可以从定义严格导出，也正因如此，它们必须由确定性代码执行，而不是由模型"估计"。

<strong>第一步：带宽由采样率决定。</strong> 奈奎斯特（Nyquist）判据要求采样率至少为最高分析频率的两倍，因此分析带宽（Bandwidth）为

这个公式回答的问题是：**采样率定了之后，我最多能"看"到多高的频率？** 它是采集参数链条的第一环， ADC 之前抗混叠滤波器截止频率的设定依据。

$$
F_{\max} = \frac{f_s}{2}
$$

物理意义：采样率确定后，可分析频率范围的上限随之确定，高于该上限的成分必须在 ADC 之前由抗混叠滤波器去除。

![带宽为采样率的一半：奈奎斯特判据要求采样率至少为最高分析频率的两倍（图源：网络官方公开资料）](/images/mcp-boundary/fig-bandwidth-nyquist.png)

<strong>第二步：谱线数由数据块大小决定。</strong> 对实信号做傅里叶变换，结果共轭对称，有效谱线数（Spectral Lines）为

这个公式回答的问题是：**频率轴上一共能落下多少个取值点？** 每条谱线是一对"幅值 + 相位"，谱线数在采样那一刻就已锁定，后续任何算法都无法凭空增加。

$$
SL = \frac{N}{2}
$$

物理意义：每条谱线携带一对幅值与相位，频率轴上的取值点个数在采样那一刻就已锁定。

![每条谱线含幅值（上）与相位（下）两个量；谱线数等于数据块大小的一半（图源：网络官方公开资料）](/images/mcp-boundary/fig-spectrum-amp-phase.png)

<strong>第三步：频率分辨率由帧长决定。</strong> 相邻谱线间距为带宽除以谱线数，等价于帧长（Frame Size）的倒数：

这个公式回答的问题是：**两个频率靠得多近时还能分得开？** 注意它揭示的硬约束：分辨率只认采样时长，想让 100 Hz 和 100.5 Hz 分开，唯一办法是采够 2 秒数据——任何算法技巧都替代不了时间。

$$
\Delta f = \frac{F_{\max}}{SL} = \frac{f_s}{N} = \frac{1}{T}
$$

物理意义：要分辨更靠近的两个频率成分，唯一办法是加长单帧采样时间——这是采集参数选择中的根本性权衡，任何模型都无法绕过。

![100 Hz 与 101 Hz 两个正弦：频率分辨率不足时两峰合并（左），分辨率足够时分开为两个独立峰（右）（图源：网络官方公开资料）](/images/mcp-boundary/fig-two-tones-resolution.png)

::: tip 数字与解释的分工示例
用户问"这段数据里有没有共振"。LLM 的职责是解析意图、按上下文选择分析带宽与帧长、调用 FFT 工具、拿到谱线后指出哪个峰值得关注；上式中的三个数值必须来自工具的计算，而不是模型的生成。
:::

## 三、专业 NVH MCP 服务应覆盖什么

MCP 作为 Agent 调用外部工具的标准协议，专业 NVH 服务应封装确定性算法，而非依赖模型"猜"结果：

- **频域分析** — FFT、阶次分析、倍频程、频响函数（Frequency Response Function，FRF）计算
- **模态分析** — 工作变形（Operating Deflection Shape，ODS）、模态参数提取、MAC 计算
- **心理声学指标** — 响度（如 Zwicker 响度，单位 sone）、尖锐度、粗糙度
- **报告生成** — 基于结构化数据生成标准化报告模板
- **数据管理** — 测试数据的元信息管理、版本、可追溯

其中模态分析一类的输出必须给出可核查的量化指标。以模态置信判据（Modal Assurance Criterion，MAC）为例，它是衡量试验振型与计算振型一致性的核心指标（相关技术手册第 18.2 节，Eqn 18-5）：

这个公式回答的问题是：**试验测出的振型和仿真算出的振型到底像不像？** 分子是两向量的内积平方，分母是各自模长平方的乘积——即夹角余弦的平方，只比"方向"不比"长短"，所以对振型的任意复数缩放天然免疫。

$$
\mathrm{MAC}_{tc} = \frac{\left|\phi_{t}^{H}\phi_{c}\right|^{2}}{\left(\phi_{t}^{H}\phi_{t}\right)\left(\phi_{c}^{H}\phi_{c}\right)}
$$

其中 $\phi_t$、$\phi_c$ 分别为试验与计算振型向量，上标 $H$ 表示复共轭转置。物理意义：MAC 等于两向量夹角余弦的平方，取值范围 $[0,1]$，且对振型的任意复数缩放不敏感——这正是它适合作对标指标的原因。相关技术手册给出的判据是：两相对应模态的 MAC 应接近 100%；线性独立时 MAC 接近零。这类数值结论必须由封装的算法计算并输出，LLM 只负责解释其工程含义。

::: tip 正确的分工
LLM 负责"理解需求 + 编排流程 + 解释结果"，MCP 工具负责"执行确定性计算"。计算由工具做，解释由模型做，两者边界不重叠。
:::

## 四、关注点分离

边界规划的核心是<strong>关注点分离（Separation of Concerns）</strong>：

```text
用户需求
   ↓
LLM（意图理解、流程编排、结果解释）
   ↓
MCP 工具（确定性计算：FFT / 模态 / 指标）
   ↓
结构化结果 → 报告 / 决策
```

::: warning 不要越界
- LLM 不应直接输出数值计算结果（如"这个信号的主频是 120 Hz"），除非结果来自 MCP 工具调用
- MCP 工具不应负责自然语言解释——那是 LLM 的职责
- 两者职责清晰，才能保证结果可追溯、可复现
:::

以旋转机械阶次分析为例说明这条边界的实际意义：四缸四冲程发动机每转发生两次燃烧事件，故二阶（2nd order）成分通常是车内噪声的主要贡献者；colormap 上阶次亮带与结构共振线（如 450 Hz、750 Hz）的交点，才是需要关注的转速区间。这些判读规则来自相关公开技术资料（旋转机械方向），属于"解释规则"，可由 LLM 掌握；但阶次谱和 colormap 本身必须由工具从转速跟踪数据计算得到。

![四缸发动机车辆驾驶人右耳处噪声的 colormap：二阶成分幅度最大，是主要声学贡献（图源：网络官方公开资料）](/images/mcp-boundary/fig-second-order.png)

![colormap 上阶次亮带与 450 Hz、750 Hz 结构共振线的交点指示需要关注的转速区间（图源：网络官方公开资料）](/images/mcp-boundary/fig-order-colormap.png)

## 五、工程工作流的封装

专业 NVH 服务不仅是单个算法，更是工程工作流。一个完整的 NVH 分析任务通常包括：

1. **数据校验** — 采样率、通道、单位、时间对齐
2. **信号处理** — 滤波、加窗、FFT、平均
3. **特征提取** — 峰值、阶次、指标
4. **对标分析** — 与目标值/试验数据对比
5. **报告生成** — 结构化输出，含图表和结论

::: tip 封装为链式 MCP
把上述流程封装成链式 MCP 工具，LLM 只需调用"NVH 频谱分析"高层接口，内部自动完成校验→处理→提取→报告。降低 Agent 编排复杂度，同时保证流程一致性。
:::

## 六、边界红线

::: warning 不可逾越
1. **涉及安全/法规**的 NVH 结论（如噪声合规认证）必须人工复核，MCP/LLM 只做辅助
2. **模型未验证频段**的结论不可直接用于设计决策
3. 涉及**商业机密的测试数据**不应经过通用 AI 网关
:::

## 七、演进路线

- **阶段一**：封装基础算法（FFT、指标计算）为 MCP 工具
- **阶段二**：组合成工程工作流（模态分析、TPA 流程）
- **阶段三**：接入 CAE 模型和试验数据库，支持自动化验证
- **阶段四**：与社区论坛和知识库打通，形成"计算-验证-沉淀"闭环

::: tip 价值定位
专业 NVH MCP 服务的价值不在于"让 AI 更聪明"，而在于"让正确的工程方法被 AI 可靠地调用"。先确保算法可信，再谈智能化。
:::

## 一句话记住

LLM 是分诊医生，MCP 工具是检验科仪器：意图、流程、解释交给模型，带宽、谱线、分辨率、MAC 这类数值必须由确定性算法算出——语言可以生成，数字只能计算。
