# 站群建设记录：从内容前台到工程社区

> NVH Test 站群的建设遵循"内容先行、逐步服务化"的路径。本文记录架构演进、部署方式和各服务边界，作为后续迭代的基线。

## 一、演进路径

站群按三个阶段推进，每个阶段对应不同的架构重点：

```text
阶段一：内容前台        阶段二：工程社区        阶段三：专业服务
─────────────────     ─────────────────     ─────────────────
静态门户 + 博客   →    论坛 + 知识沉淀   →    NVH API + MCP 工具
（输出研究内容）        （聚拢工程师）         （提供计算能力）
```

| 阶段 | 核心载体 | 目标 | 当前状态 |
| --- | --- | --- | --- |
| 一 | Astro 门户 + VitePress 博客 | 持续输出研究笔记、工程案例 | 进行中 |
| 二 | Discourse 论坛 + GitHub 收藏 | 社区问答、案例沉淀、工具分享 | 规划中 |
| 三 | 专业 NVH API + MCP 服务 | 把工程方法封装为可调用服务 | 规划中 |

::: tip 节奏原则
先有内容再建社区，先有社区再开服务。没有持续内容输出的社区是空壳，没有用户基础的服务是自嗨。各阶段有重叠但不跳步。
:::

## 二、当前架构

```text
                    www.nvhtest.cn (Nginx)
                          │
        ┌─────────────────┼─────────────────┐
        ▼                 ▼                 ▼
   / (8090 Astro)    /blog/ (8092)    /forum/ (规划)
   主门户 + 卡片       VitePress 博客     Discourse
        │
        ├─ /nvh/github/   收藏页（静态）
        └─ /docs/ /channel/ /skill/   （待清理/合并）
```

### 各服务职责

- **Astro 门户（:8090）** — 首页入口、导航、最新文章聚合
- **VitePress 博客（:8092）** — 研究笔记、测试方法、工程案例，支持分类目录
- **论坛（规划）** — Discourse，社区讨论与问答
- **收藏页** — GitHub 项目和工具资源整理

::: tip 边界清晰
每个服务独立部署、独立域名路径，通过 Nginx 反向代理统一入口。任何一个服务下线不影响其他服务。
:::

## 三、部署方式

当前采用 Docker Compose 统一编排：

```text
services:
  web:     Astro  门户   → 8090
  blog:    VitePress    → 8092
  nginx:   反向代理      → 80/443
  (规划) forum: Discourse
  (规划) nvh-api: 专业 NVH API
```

::: tip 统一入口策略
对外只暴露 Nginx（80/443），内部服务通过 Docker 网络互通。好处是：TLS 集中管理、路径路由灵活、单个服务可独立重启。
:::

## 四、服务边界规划

随着站群复杂度增加，必须明确边界，避免耦合：

| 服务 | 数据归属 | 更新方式 | 依赖 |
| --- | --- | --- | --- |
| 博客 | Markdown 文件（Git） | 内容提交即构建 | 无 |
| 门户 | 静态页面 | 内容变更触发 | 博客 API（聚合） |
| 论坛 | Discourse 数据库 | 用户 UGC | 独立 |
| NVH API | 工程数据/算法 | 独立部署 | 无前端依赖 |

::: warning 避免耦合
博客不应依赖论坛数据库，门户不应硬编码 API 地址。各服务通过约定接口或静态聚合松耦合，保证可独立演进。
:::

## 五、下一步

- **近期** — 完善博客内容体系（研究笔记、测试方法、工程模板），清理门户冗余导航
- **中期** — 上线 Discourse 论坛，打通博客与社区的内容流
- **远期** — 封装专业 NVH API 和 MCP 工具，接入 AI Agent 能力

::: tip 内容优先
技术架构可以快速搭建，但真正吸引工程师的是内容质量和社区氛围。把精力放在持续产出有价值的研究笔记和工程案例上，基础设施服务于内容，而不是反过来。
:::
