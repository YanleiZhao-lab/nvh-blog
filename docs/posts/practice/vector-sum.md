# 矢量合成：把三向振动变成一个可读数

> 一只三向加速度计测出 X、Y、Z 三条曲线，报告里却常常只需要一个数。矢量合成（Vector Sum）对三个方向的频谱逐谱线做平方和开根号，得到与方向无关的总振动量级——悬置两侧读数打架、人体振动评价、多测点横向对比，都靠它收敛成一条曲线。这篇讲公式、讲 Simcenter Testlab 里的两条设置路径，也讲那个最容易做错的顺序问题：先 FFT 还是先合成。

## 一、三个方向各说各话，报表只要一个数

悬置被动端做一次升速，X 向在 2800 rpm 附近冒头，Z 向过了 3000 rpm 才是主角——三个方向的主导转速段不重合是常态，不是异常。看图的人得在三条曲线之间来回切换，脑内拼出一个总量级；要是再碰上左右两个悬置共六个方向，一张图就糊了。

零件疲劳和人体舒适都不挑方向。不管振动是横向还是纵向，该疲劳还是疲劳，该不适还是不适。所以很多评价场景（整车路试验收、供应商对接、人体振动暴露量）需要的恰恰是一个**与方向无关的总量**。

矢量合成干的就是这件事：对三向数据逐谱线取平方和开根号。以官方文档的例子——X=5 g、Y=7 g、Z=12 g——合成值 14.76 g。一个数，三向能量尽收其中。

::: info 核心概念
- **矢量合成（Vector Sum）**：逐谱线对 X、Y、Z 三向做平方和开根号，得到与方向无关的振动总量级，永远不小于最大的单方向分量
- **作用对象是频率函数**：谱（Spectrum）、自功率谱（Autopower）、阶次（Order）、频率剖面都在列；Testlab 里它是导出通道，不在时域原始数据上算
- **复数谱线**：含相位的谱线按模平方逐项相加，即模长平方和再开根，相位只进幅值不进方向
:::

## 二、物理本质：正交方向的能量相加

为什么是平方和开根号，而不是 5+7+12=24？因为三个方向是同一测点上相互正交的坐标分量，合成的是**矢量模长**——几何上就是勾股定理推广到三维。能量层面，正交方向互不贡献，各自能量简单相加，这与分贝一篇里的能量叠加、谱总级的 RSS 求和是同一条物理。

对数值要有手感：合成结果由大分量主导，小分量是添头。还是 5/7/12 这组数，分步叠加看 dB：

```python
import numpy as np

# 悬置被动端一次升速测试的三个方向总级（RMS，单位 g）
X, Y, Z = 5.0, 7.0, 12.0

vs = np.sqrt(X**2 + Y**2 + Z**2)          # 矢量合成
print(f"矢量合成 = {vs:.2f} g")
for name, combo in [("仅 Z", (0, 0, Z)),
                    ("Z + X", (X, 0, Z)),
                    ("Z + Y", (0, Y, Z)),
                    ("X + Y + Z", (X, Y, Z))]:
    v = np.sqrt(sum(c**2 for c in combo))
    print(f"{name:8s}: {v:5.2f} g  (比仅 Z 高 {20*np.log10(v/Z):+.2f} dB)")
```

运行结果要点：12 g 的 Z 向已经是主导，再把 5 g 和 7 g 全加上，总量级也只从 12 涨到 14.76 g（+1.80 dB）；只加 X 一个方向更是只多 0.70 dB。合成值被大分量锁死，这正是它稳健的原因——换一个人装传感器、轴向偏了几度，总量级几乎不动。

| 分量组合 | 合成值 | 相对仅 Z |
| --- | --- | --- |
| **仅 Z = 12 g** | 12.00 g | 0 dB |
| **Z + X（12, 5）** | 13.00 g | +0.70 dB |
| **Z + Y（12, 7）** | 13.89 g | +1.26 dB |
| **X + Y + Z（5, 7, 12）** | 14.76 g | +1.80 dB |

::: tip 什么时候用、什么时候别用
- 报告给非 NVH 背景的人看、多测点横向排序、人体振动评价 → 用矢量合成
- 诊断哪个方向有问题、ODS / 模态动画、传递路径分析 → 保留三向原始数据，合成会把方向信息抹掉
- 传感器轴向一致性没把握时 → 合成值反而是最稳的量（对轴向偏差不敏感）
:::

## 三、先 FFT 还是先合成？顺序做错结果就脏

官方知识库评论区有个高频问题：计算顺序到底是先对时域数据做合成再 FFT，还是 FFT 之后再合成？Siemens 工程师的回答很明确：先 FFT，再对频率函数做矢量合成。VECTOR_SUM 本来就是挂在 Derived（导出通道）体系下的频域函数。

为什么顺序不能反？时域逐点取模是非线性运算。正弦的平方里出直流和二倍频，逐点求模再做 FFT，谱上会出现原本不存在的频率成分——原始信号里根本没有的能量，被造了出来。

```python
import numpy as np

fs, T = 1024, 1.0                          # 采样率 1024 Hz，时长 1 s
t = np.linspace(0, T, int(fs*T), endpoint=False)
# X 向 30 Hz 4 g，Z 向 80 Hz 3 g：不同方向、不同频率
acc = np.array([4.0*np.sin(2*np.pi*30*t),
                np.zeros_like(t),
                3.0*np.sin(2*np.pi*80*t)])
N = len(t)

# 正确路径：先各自 FFT，再逐谱线三向 RSS（频域矢量合成）
spec = np.abs(np.fft.rfft(acc, axis=1)) * 2 / N
vs_f = np.sqrt((spec**2).sum(axis=0))
print("频域合成 -> 30 Hz: {:.2f} g, 80 Hz: {:.2f} g, 其余最大线: {:.1e}"
      .format(vs_f[30], vs_f[80], np.max(np.delete(vs_f, [30, 80]))))

# 错误路径：先在时域合成模长，再 FFT
vs_t = np.sqrt((acc**2).sum(axis=0))
sp_t = np.abs(np.fft.rfft(vs_t)) * 2 / N
print(f"时域合成 -> 直流分量: {vs_t.mean():.2f} g")
for f in (30, 60, 80, 160):
    print(f"           {f:3d} Hz: {sp_t[f]:.2f} g")
```

运行结果要点：频域路径干净利落——30 Hz 一根 4.00 g、80 Hz 一根 3.00 g，其余谱线在 1e-14 量级（数值零）。时域路径则是灾难现场：30 和 80 Hz 的真实谱线几乎消失，代之以 3.38 g 的直流、60 Hz 处 1.25 g 和 160 Hz 处 0.74 g 的**假线**（正弦平方产生二倍频和直流），一个没激励过的频段被凭空填满。

| 对比项 | FFT 后合成（正确） | 时域取模后 FFT（错误） |
| --- | --- | --- |
| **谱线位置** | 真实激励频率（30 / 80 Hz） | 直流加二倍频假线（60 / 160 Hz） |
| **幅值** | 各方向原始幅值逐线保留 | 非线性畸变，单根谱线无物理含义 |
| **宽频段总能量** | 与时域一致（Parseval 保证） | 与频域一致 |
| **适用场合** | 一切谱、阶次、剖面分析 | 不应使用 |

有意思的是最后一行：两条路径算出的全频段总 RMS 完全相等（本例都是 3.54 g）——能量没有丢，只是被搬去了错误的频率位置。所以如果只看总量级数字，时域合成看起来也对，这恰恰是它危险的地方：报表对得上，谱一细看全是假线。

::: warning 顺序坑
矢量合成的位置在 FFT 之后。对时域数据逐点取模再做谱分析，能量守恒但频率错位：真实谱线塌掉、直流和二倍频假线立起来。Testlab 把 VECTOR_SUM 放在 Derived 频率函数体系里，就是从软件层面替你锁死这个顺序。
:::

## 四、在 Simcenter Testlab 里怎么设

经典界面（Signature）和新一代界面（Neo）各有一条路，设置入口不同，公式内核一样。

### Signature：Derived 标签里的 VECTOR_SUM

两条时机都能算。测量中实时看：Signature 的 **Online Processing** 工作表，右上角切到 **Derived** 标签。事后补算：**Time Data Processing** 工作表，Channel Processing 区点 **Change Settings**，选 **Derived FS** 标签（这个工作表需要先开 Signature Throughput processing 插件：Tools 菜单的 Add-ins）。

在 Derived 标签里选中 Formula 列首个单元格，点上方的 **F(x)** 按钮，在 Select Function 菜单底部找 VECTOR_SUM——第一次用可能得点一下 New function，让菜单出现三个输入位。函数参数填三向的通道引用，两种写法都行：通道号 CH1 加 CH2 加 CH3，或者测点名加方向写全三向（通道号在 Channel Processing Settings 右上角下拉里可查）。设好后，该三向测点的所有频率函数——谱、自功率谱、阶次、频率剖面——都会自动多出一条合成曲线。

### Neo：Process Designer 里的 Block Calculate

在 Process Designer 里用 **Block Calculate** 方法。例如 Order Sections 先算出 18 阶，X、Y、Z 三向的输出分别是 R1、R2、R3，Block Calculate 的 F1 公式写 vectorsum 括号里放 R1、R2、R3（分号分隔）即可。上游接阶次就得阶次的合成，接谱就得谱的合成，流程搭好后批量处理吞吐数据很顺手。

| | Signature（经典） | Neo（Process Designer） |
| --- | --- | --- |
| **入口** | Online Processing 或 Time Data Processing 的 Derived 标签 | Block Calculate 方法 |
| **函数** | F(x) 菜单选 VECTOR_SUM | 公式 vectorsum 接 R1 R2 R3 |
| **通道引用** | 通道号 CH1 或测点名加方向 | 上游方法的输出编号 |
| **生效对象** | 该测点全部频率函数（谱、自功率、阶次、剖面） | 只算流程里接进来的函数 |
| **时机** | 测量中实时加事后吞吐 | 离线流程 |

::: tip 设置建议
- 现场要看实时趋势 → Online Processing 里就设好，测量中直接看合成曲线
- 数据已经采完 → Time Data Processing 补算，别为一条合成曲线重测
- Neo 里想把合成结果出成瀑布图 → 把 Block Calculate 放在 Order Sections 或谱方法之后，对瀑布数据逐帧合成
:::

## 五、小结

矢量合成的使用边界，三条判断标准：

- **看总量、排序、汇报 → 用**：与方向无关、对轴向偏差稳健，六个方向收成两条线（左右悬置各一条），图表立刻可读
- **查方向、做动画 → 不用**：合成抹掉方向信息，ODS、模态、TPA 一律回三向原始数据
- **顺序只有一个 → FFT 在前**：合成作用在频率函数上；时域取模会造出直流和二倍频假线，虽然总能量分毫不差，谱却已经不能看了

一个数收拢三个方向，换来的是可读性，代价是方向信息——什么时候肯付这个代价，取决于你是要向别人汇报，还是要向数据追问。
