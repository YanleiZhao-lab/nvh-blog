# 资格试验前能不能先把风险跑一遍？——虚拟振动台、限幅与 Notching 策略

> 航天器正弦振动资格试验的每一个决定，都是在风险、成本与进度压力最高的时刻做出的：飞行窗口不容更改，参试硬件价值连城，一旦试验中出现意外超差，工程师只能一边让产品继续振动、一边临场排查。Simcenter Testlab 2606 的虚拟振动台测试（Virtual Shaker Testing）给出的思路是"不要仿真试验，而是试验一个仿真"——用系统辨识数据导出能够实时运行的振动台+试件数字孪生，接到真实控制器上，把控制参数、限幅（limiting）与下凹（notching）策略先在虚拟环境里完整跑通，再让真件上场。本文用"飞行模拟器"这条线讲透：模型怎么来、在软件里怎么接、快扫欠幅与下凹深度这两笔风险账各有多大、以及模型可信度怎么用 Model Compare 收口。

::: tip 30 秒速览
- **一句话**：航天器上振动台做正弦扫频资格试验之前，能不能先把"试验会不会出事"用仿真预演一遍？
- **类比**：飞行员上真机之前先泡飞行模拟器——模拟器里坠机一百次都不心疼，练的是手感与应急预案；虚拟振动台就是振动试验的模拟器
- **关键数字**：阻尼只有 0.5% 的航天器典型模态（放大 100 倍），规范若允许 8 倍频程/分钟的快扫，共振峰只被激发出 62 g——比真值欠 38%；而下凹策略一出手，最深处的推力要压掉 18.4 dB（只剩约 1/8）
- **结论**：能。用以往模态/系统辨识数据导出台面+试件的实时数字孪生，接到真实振动控制器上，控制参数与限幅下凹策略先在虚拟环境跑通再上真件——学在试验前，而不是试验中
:::

## 一、为什么最贵的试验，偏偏是在信息最少的时候做的

先看一个真实的处境。某卫星结构即将进入正弦振动资格试验：台面按规范从 5 Hz 扫到 200 Hz，控制点盯规范谱，关键部位贴着响应监视通道。问题在于，航天器结构上总有几阶阻尼极低的模态——放大倍数上百倍，扫频经过时响应瞬间冲高。规范给了一条响应限值（比如关键部位不许超过 12 g），试验大纲因此要求配置限幅与下凹：一旦预测响应要越限，控制器自动把该频段的驱动量压下来。

这套策略本身没错，错在它第一次被验证的时机。扫频一启动，瞬态效应、控制器与结构的相互作用、下凹段与共振的相对位置全部同时登场；如果响应超差或者控制谱超差，试验只能中断，团队在参试件已经吃了一轮振动之后临场分析、改参数、再扫一遍。对航天项目，每一遍重复都意味着：宝贵的硬件多吃一轮循环，进度表再被咬掉一块，而发射窗口不等人。文献对这类场景的概括很直白：资格试验常常发生在风险、成本与进度压力同时最高的时刻，最有价值的认识往往是在试验进行中才获得的——而"在资格试验中学习"既危险又昂贵。

于是问题被倒过来问：**能不能在真件上台之前，就把"这次试验会怎么走"预演一遍？** 具体到三个最要命的未知数：

- 扫频扫过某阶关键共振时，系统（台面+试件+夹具+控制器闭环）到底会怎么动？
- 选中敏感部位会不会出现局部超差，超多少？
- 换一组控制参数、换一种下凹策略，结果会好多少？

历史上这三个问题的答案只能靠真件上一次一次试出来。Simcenter Testlab 2606 给出的替代路线，是把整个试验链搬进实时仿真环境——虚拟振动台测试。

## 二、飞行模拟器类比：练的是"人+机"的闭环，不是飞机本身

把虚拟振动台想成飞行模拟器，几乎每个部件都能对上：

| 飞行模拟器 | 虚拟振动台 |
|---|---|
| 模拟舱+视景系统（复现飞机的响应） | 振动台+试件的实时数字孪生模型 |
| 真实的操纵杆与仪表盘（飞行员用真设备） | 真实的 SCADAS 振动控制器与控制软件 |
| 风洞/飞行数据导出的飞行动力学模型 | 系统辨识数据导出的台面+试件动力学模型 |
| 模拟发动机失效、湍流等应急预案 | 预演限幅触发、下凹深度、控制参数调整 |
| 放心坠机一百次，练出手感再上真机 | 放心扫频一百遍，调好参数再让真件上场 |

关键在最后两行。飞行模拟器值钱，不是因为它能仿真一架飞机——风洞和离线仿真早就做得到——而是因为它把**真实的飞行员、真实的操纵设备**接进闭环，练的是"人+机"系统在突发状况下的整体行为。虚拟振动台同理：它不是离线算一条响应曲线，而是把**真实的控制器**（就是正式试验要用的那一台 SCADAS 与控制软件）接上实时运行的数字孪生，让控制回路、扫频逻辑、限幅与下凹策略全部真实地跑起来。离线仿真里"差不多"的控制参数，在闭环里可能振荡；离线仿真里看不出问题的下凹设置，在闭环里可能在共振处留下超差——这些只有闭环才暴露的问题，正是资格试验现场最不想第一次见到的问题。

这套思路被概括成一句话：**Instead of simulating the test, test a simulation——不是去仿真试验，而是去试验一个仿真。**

## 三、数字孪生从哪来：系统辨识数据导出实时模型

虚拟振动台的"模拟舱"是一套能实时运行的动力学模型，它的原料不是从头建模，而是试验室里本来就有的测量数据。工作流分三步：

1. **模型导出（Model derivation）**：用系统辨识数据（低量级正弦扫频、锤击或随机激励下的 FRF）导出一个**稳定**的状态空间模型，同时涵盖振动台（含功放-动圈-台面）与试件（DUT）的动力学。这一步在 Simcenter Testlab 动态环境试验产品的界面里加载模态分析插件即可完成——模态分析工程师熟悉的工具直接复用；
2. **实时执行（Real-time execution）**：导出的模型上传到 Simcenter Testlab RT，在实时环境中逐采样步进运行——对控制器来说，它与一台真实的振动台没有区别；
3. **虚拟试验执行**：SCADAS 振动控制硬件驱动这个"虚拟台"，Simcenter Testlab 冲击与振动试验产品提供完整的正弦/随机/冲击控制流程，虚拟试验就此开跑。

![虚拟振动台工作流的三大组成：系统辨识数据导出稳定模型、Testlab RT 实时执行模型、SCADAS 振动控制硬件闭环驱动虚拟试验](/images/virtual-shaker-testing-notching/fig2.png)

*（图源：网络 侵删）*

这条流水线里最值得强调的是第一步的"**稳定**"二字。系统辨识得到的模型要放进实时环境以固定步长推进，任何在低阻尼频段数值发散的模型都会让虚拟试验当场崩溃；公开技术资料对这一步的要求是模型必须从辨识数据直接导出且保证稳定运行——这也是为什么模型导出被做成模态分析工具链的一部分：辨识、极点选择、模型验证的整套质量控制手段都在手边。

::: info 核心概念
- **虚拟振动台测试（Virtual Shaker Testing）**：用实时数字孪生替换物理振动台与试件、保留真实控制器的半实物仿真试验方式，用于正式试验前的策略验证与风险排查
- **系统辨识（System Identification）**：用实测输入输出（如低量级扫频的 FRF）建立结构动力学模型的技术，是数字孪生的数据来源
- **限幅（Limiting）**：对试件关键部位响应设置上限，控制器据此压制驱动量的保护策略
- **下凹（Notching）**：在规范谱的目标频段上主动压低驱动量，使响应限值得到满足——频谱形状上表现为一个"凹坑"
:::

## 四、第一笔风险账：快扫经过共振，峰还测得准吗

虚拟振动台能预演的第一类风险，是**扫频速率与结构响应的相互作用**。正弦控制试验里，激励是瞬态的——频率一直在走，扫过共振时结构的响应来不及发展到稳态，就跟着激励继续往上走了。扫得越快，共振峰被"欠激发"越多。这笔账可以量化。

这个公式回答的问题是：**扫频以给定速率经过共振时，结构在共振带内一共能积累多少个激励周期**。

$$
N = \frac{60\, f_n}{Q \, \ln 2 \cdot \mathrm{rate}}
$$

其中 $f_n$ 是共振频率，$Q = 1/(2\zeta)$ 是品质因子（$\zeta$ 为阻尼比），rate 是扫频速率（倍频程/分钟，oct/min）。读法很直白：分子是"每分钟共振频率自己的周期数"，分母是"带宽换算与扫速"——扫速翻倍，带内周期数减半。经验上 $N$ 要有几百，响应才接近稳态。

用一个单自由度系统的数值实验把这笔账跑出来（80 Hz、阻尼 0.5%、$Q=100$——航天器结构典型量级；5→200 Hz 对数扫频，半隐式欧拉积分）：

<details>
<summary>数值实验：不同扫频速率下共振峰的激发程度（20 行，本机实跑）</summary>

```python
import numpy as np
def sweep(fn, z, rate, f0=5., f1=200., fs=8192.):
    wn = 2*np.pi*fn
    T = 60*np.log2(f1/f0)/rate              # 扫频总时长
    n = int(T*fs); t = np.arange(n)/fs
    ph = 2*np.pi*f0*60/(rate*np.log(2))*(2**(rate*t/60)-1)
    u = np.sin(ph)                           # 对数扫频激励
    v = 0.; x = 0.; dt = 1/fs; resp = np.empty(n)
    for i in range(n):                       # 单自由度响应，半隐式欧拉
        a_ = -wn**2*x - 2*z*wn*v + wn**2*u[i]
        v += a_*dt; x += v*dt; resp[i] = x
    f_t = f0*2**(rate*t/60)                  # 时刻 t 的瞬时频率
    k = int(np.argmax(np.abs(resp)))
    Q = 1/(2*z); N = 60*fn/(Q*np.log(2)*rate)
    return np.max(np.abs(resp)), f_t[k], N
fn, z = 80., 0.005
Q = 1/(2*z)
print(f"fn={fn} Hz, zeta={z*100:.1f}%, Q={Q:.0f}")
for r in (0.5, 1.0, 2.0, 4.0, 8.0):
    pk, fp, N = sweep(fn, z, r)
    print(f"rate={r:4.1f} oct/min  peak={pk:7.2f}  f@peak={fp:6.1f} Hz  "
          f"N={N:5.0f}  欠幅 {100*(Q-pk)/Q:5.1f}%")
```
</details>

运行结果：

```text
fn=80.0 Hz, zeta=0.5%, Q=100
rate= 0.5 oct/min  peak=  95.71  f@peak=  80.3  N=  138  欠幅   4.3%
rate= 1.0 oct/min  peak=  90.82  f@peak=  80.5  N=   69  欠幅   9.2%
rate= 2.0 oct/min  peak=  83.27  f@peak=  80.8  N=   35  欠幅  16.7%
rate= 4.0 oct/min  peak=  73.33  f@peak=  81.3  N=   17  欠幅  26.7%
rate= 8.0 oct/min  peak=  61.98  f@peak=  81.9  N=    9  欠幅  38.0%
```

三行结论直接从表里读出来：

- **扫速的代价是真实的**：同一阶 $Q=100$ 的模态，0.5 oct/min 慢扫能激发出 95.7 g，8 oct/min 快扫只剩 62.0 g——欠了 38%。试验大纲若为了省时间选快扫，测到的"合格"可能只是"没激发出来"；
- **响应峰滞后于激励频率**：峰值出现在 81.9 Hz 而非 80.0 Hz——结构还在"回味"刚才的共振，激励已经走远了。下凹凹坑的中心若按名义共振频率设置，实际可能错开整整一个共振带宽；
- **这两个效应叠加在闭环里更复杂**：控制器看到欠幅会自动加驱动试图追规范谱，而结构真实响应的发展又滞后于驱动——这正是"控制器本身是系统一部分"的含义，也是只有闭环虚拟试验才能暴露的行为。

对快扫欠幅的机制与控制参数（压缩系数、扫频速率）如何影响读数，《[做了上百次没事的正弦扫频，换个夹具为什么频繁中止？——正弦控制闭环参数](../../theory/vibration-basics/sine-control-loop.html)》一篇有更细的展开，可与本文互相印证。

## 五、第二笔风险账：下凹策略——保护试件，还是试验不足

第二类风险更微妙：**下凹本身**。规范允许的响应限值与规范谱的输入量级之间常有巨大落差——限值 12 g，而规范谱在共振处的"自然"响应可能是它的八倍。不下凹，试件可能当场损坏；下凹太深，试验量级在关键频段被压掉，资格试验的"严格性"打了折扣——产品通过了试验，但通过的可能是"打了折的试验"。

这笔账同样可以量化。设某关键通道的辨识模型由两阶模态叠加（80 Hz、阻尼 0.5% 与 130 Hz、阻尼 0.8%），规范输入 1 g 正弦、响应限值 12 g：

这个公式回答的问题是：**为把响应压回限值，每个频率点的驱动量需要压低多少分贝**。

$$
D(f) = \max\!\left(0,\; 20\lg\frac{A_{\text{ref}}\,|H(f)|}{L_{\text{lim}}}\right) \ \text{dB}
$$

其中 $H(f)$ 是关键通道的频响函数（辨识模型给出），$A_{\text{ref}}$ 是规范输入量级，$L_{\text{lim}}$ 是响应限值。$D(f)>0$ 的频段就是需要下凹的频段——凹坑形状不是拍脑袋画的，而是由限值与模型逐频点换算出来的。

<details>
<summary>数值实验：下凹深度与凹坑带宽逐频点换算（14 行，本机实跑）</summary>

```python
import numpy as np
f = np.linspace(20, 200, 1801)
def SDOF(fn, z, f):                          # 单自由度频响函数
    wn = 2*np.pi*fn; w = 2*np.pi*f
    return wn**2/(wn**2 - w**2 + 2j*z*wn*w)
H = np.abs(SDOF(80., 0.005, f) + 0.3*SDOF(130., 0.008, f))
Aref, Llim = 1.0, 12.0                       # 规范 1 g，响应限 12 g
resp = Aref*H                                 # 不限幅时的预测响应
depth = np.where(resp > Llim, 20*np.log10(resp/Llim), 0.0)
i = int(np.argmax(depth)); band = depth > 0.5
print(f"不限幅响应峰值 {resp.max():.1f} g（限值 {Llim} g，超 {resp.max()/Llim:.1f} 倍）")
print(f"最深下凹 {depth[i]:.1f} dB @ {f[i]:.1f} Hz")
print(f"下凹带宽（>0.5 dB）：{f[band].min():.1f} ~ {f[band].max():.1f} Hz"
      f"（宽 {f[band].max()-f[band].min():.1f} Hz）")
```
</details>

运行结果：

```text
不限幅响应峰值 100.0 g（限值 12.0 g，超 8.3 倍）
最深下凹 18.4 dB @ 80.0 Hz
下凹带宽（>0.5 dB）：76.7 ~ 131.1 Hz（宽 54.4 Hz）
```

三个工程判读值得逐条摆开：

- **凹坑深度**：80 Hz 处规范输入要压掉 18.4 dB——驱动量只剩约 1/8。这意味着该频段的试验严格性大幅下降，试验后签合格结论时，这 54 Hz 宽的凹坑必须写进报告并被评审方接受；
- **凹坑形状由两个限值共同决定**：80 Hz 凹得最深（模型主导），130 Hz 模态叠加处形成一个浅肩——真实结构的凹坑从来不是对称的碗，它逐频点跟随"模型预测响应/限值"的比值；
- **凹坑位置遇上扫频滞后就要重新审**：第四节已经算过，快扫下响应峰滞后到 81.9 Hz；如果凹坑按稳态假设设在 80 Hz 中心，深度又按稳态放大算，实际运行时缺口可能对不准——这正是虚拟振动台的价值：把"扫速+控制参数+下凹策略"三者放进同一个闭环里联调，而不是各自按稳态假设独立设定。

传统做法里，验证一套下凹策略只能上真件低量级试扫；虚拟振动台把这一步搬到闭环仿真里，limiting/notching 策略可以一版一版地改、跑、比，直到控制谱、响应限、凹坑宽度三者的折中可以接受，才让真件上场。

## 六、模型可信吗：Model Compare 收口

虚拟试验的结论要能支撑决策，前提是数字孪生"像"。Simcenter Testlab 2606 为此配套了 Model Compare 能力：把虚拟环境的行为与物理系统的实测行为并排对比，量化两者差异，让"看起来像"升级为"算得出像多少"。公开技术资料对这一环节的定位很清楚——虚拟验证的价值，最终取决于工程师愿意信任它到什么程度；Model Compare 提供的就是这份信任的定量依据。

值得指出的是，这条验证路线与试验-仿真对标的一般方法是同构的：低量级试扫实测一条、虚拟模型预测一条、对比模态频率/阻尼/振型相关性。对这套方法本身，《[仿真 31.2 Hz 对试验 29.4 Hz，模型到底能不能信？](../test-setup/test-simulation-correlation.html)》给出了 MAC 相关分析的完整操作，可直接迁移到虚拟振动台模型的可信度核验上。

## 七、从试验室到型号决策：虚拟振动台的更大图景

虚拟振动台最直接的收益在试验室：**在资格试验执行之前给它去风险**。控制参数调优、限幅下凹策略验证、异常工况预案，全部在虚拟环境完成；真件上台时，试验团队带进去的是一套已经被闭环验证过的配置，而不是"大概行"的初版参数。

但更大的机会在试验室之外。随着多物理场仿真模型在研制阶段越来越早可用，同一套虚拟振动台方法可以支撑**远在资格试验之前**的风险评估：设计还在迭代的阶段，试验决策（量级、扫速、下凹策略对结构意味着什么）就可以开始推演。对型号团队，这搭起一座试验与仿真之间的桥：仿真团队提前看到资格试验会发生什么，试验团队提前看到设计的薄弱环节，型号决策在更改成本最低的时刻做出——而不是等到真件上台、扫频过半才发现问题。

回到飞行模拟器类比：模拟器的终点不是替代飞行，而是让每一次真实飞行都 boring——所有意外都在地面练过了。虚拟振动台的终点也不是替代资格试验，而是让每一次资格试验都按计划走完：风险在虚拟环境里排过，参数在闭环里调过，真件只承担"验证"这一件事。

## 一句话记住

虚拟振动台 = 飞行模拟器：用系统辨识数据导出台面+试件的实时数字孪生，接上真实控制器把正弦扫频、限幅与下凹策略先在闭环里完整跑通——快扫欠幅（Q=100 时 8 oct/min 欠 38%）与下凹深度（最深压 18.4 dB 只剩 1/8 驱动）这两笔账都能提前算清、提前调和，让真件上场时只剩验证，没有意外。
