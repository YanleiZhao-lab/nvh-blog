# 实测数据怎样驱动虚拟模型？——Testlab Neo 与 FMI 联合试验

> 试验现场测到的永远是"装得下传感器的地方"：飞轮上的转速有了，扭振减振器里面的相对位移没有；悬置上的加速度有了，发动机气缸内的压力没有。而仿真模型恰好能算这些位置——只是模型住在另一个软件里，界面、格式、许可证都不通。本文回答一个联合试验中的核心问题：怎样让实测时间历程直接驱动一个动态仿真模型，并把模型的输出当"虚拟通道"和实测数据放在一起处理。用三笔数值账把机制讲透——通信步长选错让一个完全正确的模型输出翻倍误差（100%）、实测转速通道喂进模型"测"出装不了传感器位置的共振放大 23 倍、以及用实测数据把模型里猜的阻尼比从 0.5% 标定回 1.2%。

::: tip 30 秒速览
- **一句话**：测得到的地方装传感器，测不到的地方怎么办——能不能让实测数据去"驱动"仿真模型，替我们算出来？
- **类比**：像请了一位外地的翻译专家接进电话会议——你不需要飞过去、也不需要学他的语言，双方各说各的，标准接口负责传话；传话间隔太长（步长太疏），专家就跟不上对话了。
- **关键数字**：通信步长 1 s 对上时间常数 0.5 s 的模型，输出误差正好 100%——同一份模型，换一个步长结论天壤之别。
- **结论**：FMI 标准把仿真模型打包成"黑盒插件"，实测通道进、虚拟通道出；能不能用好，关键不在模型，而在通信步长、单位约定和参数标定这三件交接事。
:::

## 一、传感器装不上去的地方，数据从哪来

一个联合试验里的典型困境：项目要评估某弹性支承上支架的耐久性，最好的输入是**扭振减振器两侧的相对转角**——但那个位置既没有空间也没有办法贴应变片，实测通道表上永远是空的。团队手里有的是两样东西：飞轮上的**实测转速通道**（分辨率足够高），和一个能完整描述减振器动力学的**多物理仿真模型**（在系统仿真软件里搭建、已经过部件级验证）。缺的是一座桥：让实测转速时间历程实时流进模型、把模型的响应流回来，与实测通道同列、同采样、同一套处理流程。

过去这座桥有三种搭法，各有代价：导出实测数据为文本、切到仿真软件里做离线批处理——一次往返半天，参数一改全重来；自己写脚本调两个软件的接口——工程上可行，但换个模型版本接口就失效，维护成本高；让试验工程师去学仿真软件的图形界面——方向就反了，试验的价值恰恰在于他有数据而不是会建模。这三条路共同的病根是**没有标准**：每个模型、每个软件、每次合成都要重新发明一遍接口。

FMI（Functional Mockup Interface，功能模型接口）标准就是针对这个病根的解法：模型在建模软件里被打包成一个自包含的 FMU（Functional Mockup Unit，功能模型单元）文件，对外只暴露**时间历程输入、时间历程输出和若干可调参数**。宿主软件——这里是 Simcenter Testlab Neo 的 Process Designer——不需要知道模型内部用什么软件搭的、用什么求解器解的，插上就能跑。"仿真将取代试验"喊了很多年，这条路线的真实图景恰恰相反：**仿真跑在试验软件里，用实测数据喂它**——仿真不是取代试验，而是变成了试验流程里的一个方法块。

## 二、FMI 是什么：一个带标准插头的黑盒

::: info 核心概念
**FMI（Functional Mockup Interface，功能模型接口）**：2010 年首次发布的动态模型交换开放标准。任何支持该标准的仿真代码产出的模型，都可以打包成 FMU 文件在其它软件中运行。**FMU（Functional Mockup Unit，功能模型单元）**：按 FMI 标准打包的单个模型文件（`*.fmu`），对外接口只有三类——时间历程输入、时间历程输出、可调参数。使用者不需要了解建模软件的界面与求解器。
:::

把 FMI 想成**请外地的翻译专家接入电话会议**，这个比方贯穿全文：专家（模型）住在自己的城市（建模软件）、说自己的语言（内部求解器）；你（试验软件）不需要飞过去、也不需要学他的语言，双方各说各的，**标准电话线（FMI）负责传话**。这条标准线规定了三件事，恰好对应联合试验的三条生命线：

1. **进出线的物理量**——输入和输出都是时间历程。这正对试验数据的胃口：实测通道本来就是时间历程，模型的响应也按时间历程吐回来，两边天然同构，可以直接进同一张时序图、同一个 colormap。
2. **传话的间隔**——宿主与 FMU 按通信步长交换数据。步长怎么定、定错了会怎样，是第四节的数值主题。
3. **可调的旋钮**——建模者选择暴露哪些参数（刚度、阻尼、增益等），试验侧不碰模型内部就能改参数重跑。

有两条行业约定必须先交代，它们是后面所有工程操作的伏笔。**其一，FMI 接口不定义单位**：FMU 文件本身不携带输入输出的物理单位信息（g、rpm、psi 等），单位约定必须在建模时记录、随文件单独交接——忘了这一步，下游所有"实测数据"都是数值正确、量纲错误的废数据。**其二，许可边界**：视建模代码而定，运行打包后的 FMU 可能仍需要原仿真软件的运行时许可与最小安装包——系统仿真软件的场景下是一个运行时专用许可加最小安装；把 FMU 当成"彻底离开建模软件"的方案之前，先核许可证，别在试验前夕发现跑不起来。

## 三、模型的进出线怎么接：拔掉塞子，定义输入输出

在系统仿真软件（下文以 Simcenter Amesim 为例，任何支持 FMI 标准的代码同理）里把模型打包成 FMU，第一步不是"导出"，而是**给模型开口**。

系统仿真软件有一条能量守恒的硬约束：一个完整编译过的模型，不允许有能量"泄漏"的开放端口。因此凡是没接线的端口，软件会自动塞上**塞子（plug）**封住。要给 FMU 接线，先删掉塞子：右键删除对应端口的塞子，端口敞开，元件颜色随即反色显示——**反色就是"这里开了口"的视觉标记**，检查模型状态时一眼可辨。

![左：完全插塞的模型；右：两个元件已拔塞](/images/neo-fmi-hybrid-testing/fig2.png)

![右键删除塞子即可拔塞，所连元件颜色反色显示](/images/neo-fmi-hybrid-testing/fig3.png)

第二步在 Sketch 页签里点 Create Interface Block，类型选 Functional Mock-up Interface，然后在接口定义菜单里**增加输入数与输出数**、逐个命名。这里有一个反直觉的规定，接错线的人几乎都在这里栽跟头：**方向是反的**——在建模软件里定义为"输入"的量，将来在 Testlab 里用这个 FMU 时是"输出"；建模软件里的"输出"，到 Testlab 里是"输入"。记法只有一句：**站在模型的立场命名，站在宿主的立场使用**。建模时 FMU 定义窗口里的 input 是"流进模型的口子"；而宿主视角下，那个口子吐出数据，自然成了宿主侧的输出。

最后一步、也是最容易省略的一步：**在文档里记下每个输入输出的单位**。再强调一次，FMU 文件不带单位信息，Testlab 侧无法通过查询文件得知这个通道是 g 还是 rad 每秒平方。交接单上一个单位写错，虚拟通道从第一天起就是错的，而且错得非常安静——数值范围看起来一切正常。

## 四、通信步长：传话间隔决定结论生死

电话会议的比方在这里最要紧：专家再厉害，**传话间隔太长就跟不上对话**。FMI 联合运行时，宿主与 FMU 按通信步长交换一次输入输出；步长以内，模型按自己的内部时间步积分。通信步长选多大，不是精度细节，而是**结论生死**——这一节用最小模型把它算明白。

这个公式回答的问题是"宿主每交换一步数据，模型内部状态被推多远"：

$$y_{k+1} = y_k + \frac{h}{\tau}\left(-y_k + K u_k\right)$$

它是一阶系统 $\tau\,\dot{y} = -y + Ku$（时间常数 tau、增益 K、宿主步长 h）的单步显式更新——FMU 内部动力学最简形式。数值上它有一个众所周知的稳定性边界：h 与 tau 之比超过 2 时显式格式发散；但比发散更阴险的是**不发散但系统性错**的区间。直接跑一笔账：时间常数 0.5 s 的模型，宿主通信步长取 1 s（比值恰为 2，压在边界上），一个完全正确的模型、正确的输入，输出却**冲到精确值的整整 2 倍再不回来——稳态误差 100%**；同一份 FMU、同一步长，内部细分为 10 个子步积分，误差归零。结论先摆在这段代码跑出来的数里：
<details>
<summary>数值实验：通信步长 1 s 对时间常数 0.5 s 的模型，误差有多大（29 行）</summary>

```python
import numpy as np

# 账：通信步长选错，完全正确的模型输出也能错一倍
K, tau = 2.0, 0.5                        # 增益 K、时间常数 tau
def fmu_step(u, y, h, m=1):              # FMU 内部单步（m=子步数）
    for _ in range(m):
        y = y + (h/m/tau)*(-y + K*u)
    return y

h_host = 1.0                             # 宿主通信步长 1 s
t = np.arange(0, 60, h_host)
u = np.where(t < 10, 0.0, 1.0)           # t=10 s 输入阶跃（实测通道）

y_a, y_b = 0.0, 0.0
ya, yb = [], []
for k in range(len(t)):
    ya.append(y_a); yb.append(y_b)
    y_a = fmu_step(u[k], y_a, h_host)        # 每通信步内部只算 1 步
    y_b = fmu_step(u[k], y_b, h_host, m=10)  # 同一 FMU，内部 10 子步

ya, yb = np.array(ya), np.array(yb)
print("稳态精确值   :", round(K, 3))
print("单步耦合终值 :", round(ya[-1], 3), " 相对误差 %:",
      round((ya[-1]-K)/K*100, 1))
print("内部子步终值 :", round(yb[-1], 3), " 相对误差 %:",
      round((yb[-1]-K)/K*100, 1))
# 稳态精确值   : 2.0
# 单步耦合终值 : 4.0  相对误差 %: 100.0
# 内部子步终值 : 2.0  相对误差 %: -0.0
```

</details>

工程上这条账翻译成三句话：**第一**，通信步长不是"越粗越省"——粗到比值为 2 直接发散，粗到 1 附近就是 100% 级稳态误差；**第二**，模型内部时间步与宿主通信步长是两回事，FMU 内部细分子步可以在粗通信步长下保住精度（上例 10 子步误差归零）；**第三**，通信步长的选择依据是**模型最快动力学的时间常数**，不是实测通道的采样率——2048 Hz 采的实测通道喂给时间常数 0.5 s 的模型，瓶颈在模型侧不在数据侧。

## 五、虚拟通道：实测转速"测"出装不上传感器的地方

回到第一节的困境。桥搭好之后的工作流是这样的：实测转速通道（安装在飞轮上、采样率 2048 Hz）作为 FMU 的输入；FMU 里封着弹性支承支架的二阶动力学（质量 10 kg、阻尼 60 N·s/m、刚度 394784 N/m，固有频率 31.6 Hz）；输出就是**虚拟通道**——支架上那个装不了传感器的位置的位移响应。它在数据表里与实测通道同列、同采样率，后续处理一视同仁。

这个公式回答的问题是"转速扫过什么值时，支架会被共振放大"：

$$f_n = \frac{1}{2\pi}\sqrt{\frac{k}{m}}, \qquad n_{\text{共振}} = 60\, f_n$$

固有频率 31.6 Hz 对应**共振转速 1897 rpm**（不平衡激扰力按每转一个周期计）。这台机器从 800 rpm 匀加速升到 3200 rpm，途中必然扫过 1897 rpm——虚拟通道的价值就在这一刻兑现：实测转速通道本身平淡无奇，但喂进模型后，输出通道的 0.5 s RMS 包络在 **2.25 s 时刻冲到峰值**（正是扫过共振转速的时刻），比末段匀速段高出 **23 倍**。没有虚拟通道，这个放大过程在实测数据里完全不可见——不是信号弱，是根本没有传感器在那儿。

<details>
<summary>数值实验：实测转速通道驱动 FMU，虚拟通道抓出共振放大 23 倍（36 行）</summary>

```python
import numpy as np

# 账：虚拟通道——实测转速喂进 FMU，输出装不了传感器位置的响应
m, c, k = 10.0, 60.0, 394784.0           # kg, N*s/m, N/m
fn = np.sqrt(k/m)/(2*np.pi)
fs, T = 2048.0, 8.0
n = int(fs*T)
t = np.arange(n)/fs
# 实测输入：800 rpm 匀加速到 3200 rpm，后半程匀速
rpm = np.where(t < T/2, 800+(3200-800)*t/(T/2), 3200.0)
w = rpm/60*2*np.pi
phase = np.cumsum(w)/fs                  # 扫频的累积相位
F = 50.0*np.sin(phase)                   # 不平衡激扰力 50 N

y, v, h = 0.0, 0.0, 1/fs                 # FMU 内部 RK4 积分二阶系统
out = np.empty(n)
for i in range(n):
    out[i] = y
    def acc(y, v): return (-c*v - k*y + F[i])/m
    a1 = acc(y, v)
    a2 = acc(y+h/2*v, v+h/2*a1)
    a3 = acc(y+h/2*(v+h/2*a1), v+h/2*a2)
    a4 = acc(y+h*(v+h/2*a2), v+h*a3)
    y += h*v + h*h/6*(a1+a2+a3)
    v += h/6*(a1+2*a2+2*a3+a4)

win = int(0.5*fs)                        # 0.5 s 窗 RMS 包络（虚拟通道质检）
rms = np.array([np.sqrt(np.mean(out[i:i+win]**2))
                for i in range(0, n-win, win)])
tt = np.arange(len(rms))*0.5 + 0.25
print("共振转速     :", round(fn*60, 0), "rpm")
print("RMS 峰值时刻 :", round(tt[rms.argmax()], 2), "s")
print("峰值/末段    :", round(rms.max()/rms[-1], 1), "倍")
# 共振转速     : 1897.0 rpm
# RMS 峰值时刻 : 2.25 s
# 峰值/末段    : 23.1 倍
```

</details>

## 六、模型标定：实测数据反过来调模型的参数

虚拟通道的可信度取决于模型参数，而模型参数里有相当一部分是**猜的**——阻尼比就是典型：图纸给不出、有限元算不准、只有实测数据知道。这正是 FMI 联合试验的第二重价值：**实测数据不只被模型消费，还能反过来标定模型**。流程是一个闭环：给 FMU 暴露阻尼参数，用初始猜测值跑虚拟通道，与实测响应对比，改参数重跑，残差收敛即标定完成。全程在同一个处理流程里，不用切换软件。

这个公式回答的问题是"残差平方和最小时的参数就是最可信的参数"：

$$\hat{\theta} = \arg\min_{\theta} \sum_{i} \left[ r_{\text{sim}}(\theta, t_i) - r_{\text{meas}}(t_i) \right]^2$$

其中 theta 是待标定参数（这里是阻尼比 zeta），r 是响应的 RMS 包络。跑一笔最小账：实测数据由真阻尼比 1.2% 生成；标定前模型里猜的是 0.5%；在 zeta 网格上逐点跑 FMU、对残差平方和排序——**真值 0.012 处残差恰为零、被准确选中**，网格上偏离真值越远残差越大（0.005 时 1.6e-6、0.05 时 1.0e-6，呈典型的抛物线沟底）。标定后的模型才有资格承担第五节那样的虚拟通道任务——这是联合试验的完整闭环：**实测数据标定模型，标定过的模型再产出虚拟数据**。

<details>
<summary>数值实验：用实测数据把猜的阻尼比 0.5% 标回真值 1.2%（37 行）</summary>

```python
import numpy as np

# 账：模型标定——实测 RMS 包络 vs 虚拟 RMS 包络，残差最小者胜
m, k = 10.0, 394784.0
fs, T = 2048.0, 8.0
n = int(fs*T)
t = np.arange(n)/fs
rpm = np.where(t < T/2, 800+(3200-800)*t/(T/2), 3200.0)
w = rpm/60*2*np.pi
F = 50.0*np.sin(np.cumsum(w)/fs)

def run_fmu(zeta):                       # FMU：RK4 积分二阶系统
    c = 2*zeta*np.sqrt(k*m)
    y, v, h = 0.0, 0.0, 1/fs
    out = np.empty(n)
    for i in range(n):
        out[i] = y
        def acc(y, v): return (-c*v - k*y + F[i])/m
        a1 = acc(y, v); a2 = acc(y+h/2*v, v+h/2*a1)
        a3 = acc(y+h/2*(v+h/2*a1), v+h/2*a2); a4 = acc(y+h*(v+h/2*a2), v+h*a3)
        y += h*v + h*h/6*(a1+a2+a3); v += h/6*(a1+2*a2+2*a3+a4)
    return out

win = int(0.5*fs)
def rms_env(x):
    return np.array([np.sqrt(np.mean(x[i:i+win]**2))
                     for i in range(0, n-win, win)])

meas = rms_env(run_fmu(0.012))           # "实测"：真阻尼比 1.2%
zetas = np.array([0.005, 0.008, 0.012, 0.02, 0.03, 0.05])
errs = np.array([np.sum((rms_env(run_fmu(z))-meas)**2) for z in zetas])
for z, e in zip(zetas, errs):
    print(f"zeta={z:5.3f}  残差平方和={e:.3e}")
print("标定结果:", zetas[errs.argmin()], "（真值 0.012）")
# zeta=0.005  残差平方和=1.622e-06
# zeta=0.012  残差平方和=0.000e+00   <- 被选中
# zeta=0.050  残差平方和=1.036e-06
```

</details>

## 八、工程要点清单

把全文收进一张交接清单，联合试验前逐项打钩：

1. **单位交接单**：FMU 不带单位，逐通道记录（g、rpm、psi 等），随文件交付——这是第一优先级，错单位的数据安静地错下去。
2. **Final Time 加大**：默认 10 s 会静默截断输出，按最长测量时长设置。
3. **通信步长看模型不看采样率**：按模型最快动力学的时间常数定，比值到 2 即发散、到 1 附近稳态误差可达 100%；模型内部子步可以救粗通信步长。
4. **方向反转**：建模软件里的输入等于宿主里的输出，站在模型立场命名、宿主立场使用。
5. **许可证核查**：运行 FMU 可能仍需建模软件的运行时许可与最小安装包，试验前确认。
6. **虚拟通道命名对齐实测**：同列、同采样、同命名习惯，处理流程一视同仁。
7. **标定闭环**：暴露阻尼等不确定参数，用实测数据按残差最小原则标定后，模型才有资格量产虚拟通道。

FMI 把仿真模型变成带标准插头的黑盒：实测通道进、虚拟通道出——传感器装不上的地方从此有数据；但插头不传单位、传话间隔不能太长，标定过的模型才配量产虚拟数据。
