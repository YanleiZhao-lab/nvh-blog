# RS 适合路试，ES 适合什么？——SCADAS ES/RS 分布式采集架构与选型

> 同一家公司的新一代采集产品线里同时放着 ES 与 RS 两个系列，参数表乍看很像：都能接电压、ICP、电桥、电荷、脉冲与数字信号，都能跑同一套 Testlab 工作流。于是选型会上总有人问：既然 RS 那么"皮实"，全都买 RS 不就完了？答案是行不通的——RS 单元是按"搬到测点旁边"设计的，而实验室里上百通道围绕一台激振器、一个台架布点的场景，恰恰需要一台插满卡件、风扇散热、上架安装的主机来"坐镇中央"。本文把这对组合当成一套**工具箱**来讲：RS 是背出去的电动工具、ES 是车间里那台立式铣床——同为加工，一个赢在"哪里都能去"，一个赢在"精度与刚度"；然后用电缆、吞吐量、环境三笔账把"什么时候选谁、什么时候两个都要"算清楚。

::: tip 30 秒速览
- **一句话**：同样是采数据，为什么野外路试都用 RS、实验室台架都摆着 ES，能不能只用一种？
- **类比**：把它们想成一套工具箱——RS 是随手背出门的电动工具（防尘防水、哪里都能去），ES 是车间里的立式铣床（体积大、通道密、干精细活）；电动工具替代不了铣床，铣床也抬不到工地上
- **关键数字**：96 通道测同一台车，电缆从机柜拉到测点要 20 m 一路、总花费约 5.0 万元；把单元搬到测点旁只要 3 m 短线、约 0.78 万元——差出 84%
- **结论**：按**测点密度**和**环境**分工——测点围着台架转、环境可控，用 ES 机柜式；测点散在整机各处、日晒雨淋，用 RS 分布式；一台车从台架做到路试，两个都用、数据进同一个工作流
:::

## 一、为什么"参数差不多"，选型却不能只看参数表

先看一个真实场景。某重型工程机械的测试计划分两段：第一段在实验室做结构模态，激振器周围布 96 个加速度通道，所有电缆拉回控制室；第二段整车去矿区做作业载荷采集，同样的传感器要装到驾驶室、车架、液压管路上，设备只能塞进驾驶室随车颠簸。

第一段顺利收工。第二段出发前，团队照旧把实验室那套机柜式主机搬上车，结果第一天就出了三件事：机柜在矿区路面被颠得移位、凌晨气温降到零下二十度设备开不了机、96 根长电缆在驾驶室与车架之间拉得到处都是、一根被车门夹断。而隔壁车队的 RS 分布式设备，12 个小单元分三处绑在测点附近，每处只出几根 3 m 短线，链缆一根串到底，开机即采。

两套设备参数表上"每通道采样率、支持传感器类型"几乎一模一样，为什么现场表现天差地别？因为**参数表写的是通道能力，选型决定的是系统形态**。新一代 SCADAS 家族把这两件事拆给了两个成员：

- **SCADAS ES**：模块化主机形态，卡件插进主机框架、风扇散热、适合实验室与台架旁"坐镇中央"的高密度通道场景，也覆盖一般野外测试；
- **SCADAS RS**：分布式单元形态，每个信号调节单元（Conditioning Unit）自带外壳与防护、以菊花链级联，单元**搬到测点旁边**，专为严苛环境（冲击、振动、粉尘、水、极端温度）设计。

![新一代 Simcenter SCADAS 产品组合：ES 与 RS 两个成员构成同一采集家族](/images/scadas-es-rs-architecture/fig1-portfolio.png)

*（图源：网络 侵删）*

::: info 核心概念
- **机柜式/模块化采集（ES）**：卡件集中插在一台主机框架内，所有测点电缆汇聚到主机；通道密度高、上架安装、实验室环境
- **分布式采集（RS，Distributed Acquisition）**：多个信号调节单元分散布置在测点附近，单元间用一根菊花链电缆同时完成供电与数据传输，汇聚到记录仪单元（REC）
- **菊花链（Daisy Chain）**：设备首尾相连的总线拓扑——一根电缆既供电又传数据，单元在链上的位置有严格语法（详见《[链上再并一个适配器为什么会烧单元？](rs-daisy-chain-power.html)》）
:::

这一对组合真正的主张是"**一个家族、一套工作流**"：ES 与 RS 在 Testlab/Testlab Neo 里用同一套通道设置、监视、存储界面，数据格式一致——项目从实验室做到路上，工作流不用推倒重建。硬件层面也保留了对既有投资的兼容：支持的既有卡件、电缆与连接器可继续使用，已入列的机架式配置也能参与同步测量。选型不是"二选一"，而是"怎么分工"。

## 二、工具箱类比：电动工具与立式铣床

把这套家族想成一套工具箱。

**RS 是电动工具**：手电钻、角磨机，外壳防尘防水，背到工地、矿场、船上都行；但它一次只能装一根钻头，干不了五轴联动的精细活。RS 的每个调节单元就是一件电动工具——十几个通道、独立防护外壳、绑在被测机器上。发动机舱温度高的地方放一个、驾驶室放一个、车架尾部再放一个，各管各的测点，一根链缆串回来。

**ES 是车间里的立式铣床**：几吨重、搬不动，但工作台刚度大、主轴精度高、能同时挂多把刀，成批地干精细活。ES 主机插满卡件立在实验室台架旁，96 个通道的电桥、ICP、电荷信号全部拉回主机，风扇散热、上架供电，通道密度与调节精度都是"铣床级"。

物理上真正对应的是三件事：**第一，信号调节离传感器越近越好**——长电缆是噪声的收集器，差分与屏蔽能压一部分，但 20 m 与 3 m 的信噪比起点就不同；RS 把"话放"搬到测点旁，正是电动工具"就地解决问题"的电子学版本。**第二，散热决定形态**——高密度卡件堆在一起必须主动风冷，这就要求机柜与洁净空气，铣床必须待在车间里；RS 每个单元功耗低、靠外壳自然散热，才敢做防护等级。**第三，防护与带宽是一对取舍**——IP66/IP67 的密封壳（尘密、耐强喷水乃至短时浸水）天然限制内部空气循环，单个 RS 单元不可能堆出机柜级通道密度，就像电动工具再好也替代不了铣床的工作台。

所以"全都买 RS"行不通的地方在实验室：上百通道围着一个台架，用 RS 要串十几台单元、占掉一大片地面；而"只用 ES"行不通的地方在野外：机柜防护与温度范围根本不答应。**工具箱逻辑是按活选工具，不是用一件工具凑合所有的活。**

## 三、第一笔账：电缆——分布式最直接的收益

这个公式回答的问题是：**同一批测点，两种架构在电缆上到底差多少钱、多少公斤**。

$$
C_{\text{ES}} = N \cdot L_{\text{ES}} \cdot c_{1}, \qquad C_{\text{RS}} = N \cdot L_{\text{RS}} \cdot c_{1} + L_{2} \cdot c_{2}
$$

ES 机柜式：$N$ 个测点每个一根平均 $L_{\text{ES}}$ 米的低噪声电缆拉回主机；RS 分布式：每个测点只拉 $L_{\text{RS}}$ 米到最近单元，单元之间用便宜得多的链缆/网线串联（$c_1$、$c_2$ 为两类线缆单价）。以 96 通道、ES 平均 20 m 对 RS 平均 3 m、低噪声电缆 26 元/m 计：

![ES 机柜式：所有测点电缆汇聚回中央主机（自绘示意）](/images/scadas-es-rs-architecture/fig7-es-central.png)

*（图源：网络 侵删）*

![RS 分布式：调节单元贴近测点、菊花链串回 REC（自绘示意）](/images/scadas-es-rs-architecture/fig8-rs-distributed.png)

*（图源：网络 侵删）*

结论先摆在这段代码跑出来的数里：电缆一项 49920 元对 7844 元、省 84%，电缆重量约从 73 kg 降到 11 kg——装车布线时间通常也随电缆长度大体同比例下降：

<details>
<summary>数值实验：96 通道两种架构的电缆账（点击展开，12 行）</summary>

```python
import numpy as np

# ---- 账1：同一台车 96 通道，ES 机柜 vs RS 分布式的电缆账 ----
N = 96                      # 通道数
L_es, L_rs = 20.0, 3.0      # ES：传感器到机柜平均电缆长(m)；RS：到最近单元平均 3 m
L_trunk = 6.0               # RS：单元间链缆与网线合计(m)
cost_m = 26.0               # 低噪声电缆参考单价(元/m)
cost_cat = 8.0              # 链缆/网线单价(元/m)
es_cost = N * L_es * cost_m
rs_cost = N * L_rs * cost_m + L_trunk * cost_m + 25.0 * cost_cat
print(f"ES 机柜式:  {N}x{L_es:.0f} m 低噪声电缆        = {es_cost:8.0f} 元")
print(f"RS 分布式:  {N}x{L_rs:.0f} m 低噪声电缆+{L_trunk:.0f} m 链缆 = {rs_cost:8.0f} 元")
print(f"电缆一项省 {es_cost-rs_cost:.0f} 元（{(1-rs_cost/es_cost)*100:.0f}%），"
      f"电缆重量约从 {N*L_es*38/1000:.1f} kg 降到 {N*L_rs*38/1000:.1f} kg")
```
</details>

```text
ES 机柜式:  96x20 m 低噪声电缆        =    49920 元
RS 分布式:  96x3 m 低噪声电缆+6 m 链缆 =     7844 元
电缆一项省 42076 元（84%），电缆重量约从 73.0 kg 降到 10.9 kg
```

这笔账的另一面是**信号质量**：低噪声电缆每米都是天线，20 m 电缆在整车电磁环境里捡到的共模噪声，与 3 m 短线不在一个量级。分布式把"长距离"留给数字链缆——数字信号再生中继，不怕长；把"短距离"留给模拟小信号——越短越干净。这正是"话放搬到测点旁"的工程价值。

## 四、第二笔账：吞吐量——分布式的天花板要会算

这个公式回答的问题是：**一条菊花链、一台 REC 最多能扛多少通道多少采样率**。

$$
S_{\text{total}} = \sum_{i=1}^{N_{\text{ch}}} f_{s,i} \le \min\left( N_{\text{chain}} \times 1.7,\ 7.8 \right)\ \text{MSa/s}
$$

按公开技术资料：**每条菊花链支持最高 1.7 MSa/s 总吞吐量，REC 单元可处理的总累计吞吐量为 7.8 MSa/s**。一台 REC 通过电源输出链 1-4 连接器最多带四条菊花链（4 x 1.7 = 6.8 MSa/s，仍在 7.8 之内）。换算成通道：RS 卡件每通道采样率上限为 48 kHz（U12/U12-E/S24）或 24 kHz（B24）——**7.8 MSa/s 除以 48 kHz 约等于 162 通道全速**，第 163 个通道起就必须降采样率。

<details>
<summary>数值实验：192 通道挤 4 条链为什么不行、分 8 条链为什么还不行（点击展开，14 行）</summary>

```python
# ---- 账2：RS 吞吐量预算——单链 1.7 MSa/s、REC 总计 7.8 MSa/s ----
cap_chain, cap_rec = 1.7, 7.8
plans = [
    ("192 通道 @ 48 kHz 挤 4 条链", 4, 192 * 48e3),
    ("192 通道 @ 48 kHz 分 8 条链", 8, 192 * 48e3),
    ("204 通道 @ 48 kHz 分 8 条链", 8, 204 * 48e3),
]
for name, nchain, sa in plans:
    per = sa / 1e6 / nchain
    print(f"{name}: 总 {sa/1e6:5.2f} MSa/s、每链 {per:4.2f} -> "
          f"链上限{'OK' if per <= cap_chain else '超(>1.7)'} / REC 总量{'OK' if sa/1e6 <= cap_rec else '超(>7.8)'}")
n_full = int(7.8e6 // 48e3)
print(f"7.8 MSa/s / 48 kHz = 全速最多 {n_full} 通道；第 {n_full+1} 个通道起必须降采样率")
```
</details>

```text
192 通道 @ 48 kHz 挤 4 条链: 总  9.22 MSa/s、每链 2.30 -> 链上限超(>1.7) / REC 总量超(>7.8)
192 通道 @ 48 kHz 分 8 条链: 总  9.22 MSa/s、每链 1.15 -> 链上限OK / REC 总量超(>7.8)
204 通道 @ 48 kHz 分 8 条链: 总  9.79 MSa/s、每链 1.22 -> 链上限OK / REC 总量超(>7.8)
7.8 MSa/s / 48 kHz = 全速最多 162 通道；第 163 个通道起必须降采样率
```

三行输出正是三堂课：**挤 4 条链**每链 2.30 MSa/s 超单链 1.7 上限，链本身先堵死；**分 8 条链**每链 1.15 没问题，但总量 9.22 已超 REC 的 7.8——瓶颈从链转移到了 REC；要消化 192 通道，要么再加一台 REC 分片，要么把一半通道降到 24 kHz（总吞吐减半回到 4.61 MSa/s）。这正是铣床与电动工具的分工在数据率上的体现：**实验室里百通道高带宽的"铣削用量"，超出了单台移动"电动工具"的马力**。

ES 机柜式没有这条链上天花板（通道扩展走主机框架与上游接口），这就是高通道、高带宽试验首选 ES 的第二条理由。规划 RS 系统时，这笔吞吐账必须在配置阶段就算清楚——REC 面板上那颗"快闪红灯"的两种病因之一就是它（详见《[同一颗红灯快闪，为什么一台删数据能救、一台必须拆链？](rs-troubleshooting.html)》）。

## 五、第三笔账：环境——防护等级与温度范围是两张考卷

这个公式回答的问题是：**设备外壳的防护等级与工作温度范围分别防的是什么**。

$$
\text{IP}\ 6X\ (\text{尘密}) + X\ (\text{防水等级})，\qquad T_{\text{工作}} \in [-40, +85]\ ^\circ\text{C}\ (\text{RS 扩展温度})
$$

公开技术资料给出的 RS 侧答卷：按 IEC 60529，RS 单元异物防护达 **IP66 与 IP67**（IP66=尘密+耐强喷水，IP67=尘密+短时浸水），可承受 100% 相对湿度，室内外均可安全使用；扩展温度范围 **-40 至 +85 °C**；海拔 5000 m 之内安全运行。ES 主机则是机柜级防护（IP20 级别、靠机柜环境保护），工作温度适合受控实验室环境。

| | ES 模块化主机 | RS 分布式单元 |
|---|---|---|
| 形态 | 卡件插框架、上架安装 | 独立防护外壳单元 |
| 典型通道密度 | 高（框架内多卡） | 每 12/24 通道一个单元 |
| 防护 | 机柜级（IP20） | IP66/IP67 |
| 温度 | 受控环境 | -40 ~ +85 °C 扩展温度 |
| 散热 | 风冷 | 外壳自然散热 |
| 供电 | 机房/台架供电 | 菊花链供电+UPS 电池缓冲 |
| 典型场景 | 模态、台架、实验室验证 | 整车路试、户外、船上、机上 |

::: warning 两个常被低估的点
- **UPS 电池的低温降额**：-25 °C 以下满载、-30 °C 以下 3/4 负载、-35 °C 以下 1/2 负载时电池缓冲不适用；低温大负载工况要留功率余量或保温（详见《[链上再并一个适配器为什么会烧单元？](rs-daisy-chain-power.html)》的功耗账）
- **防护等级不等于免维护**：IP67 仍需按规程清洗（连接器盖盖好、限压限流）、按周期校准（详见《[IP67 的采集设备三年不保养，到底行不行？](rs-maintenance-calibration.html)》）
:::

回到开头的矿区场景：凌晨零下二十度，ES 机柜低于工作下限、必须整体搬进加热方舱；RS 单元在扩展温度范围内直接绑在被测机器上开机。**环境这一票，常常比通道参数更早否决选型。**

**机械与家电**——性能优化横跨振动、声学、转速、温度、功率与结构域，问题从排障变设计验证时信号组合跟着变，ES 的调节/连接器/通道密度选项吸收这种变化。

贯穿这些场景的是同一句话：**按环境选硬件、不按硬件改流程**。两个成员背后是同一个生态——浏览器端与桌面端的监视与验证工具内置在硬件侧、免许可使用；第三方信号与应用可以参与同步采集；既有卡件、电缆与机架配置在支持矩阵内继续融入同步测量。对已有 SCADAS 资产的用户，这不是一次"推倒重来"的换代，而是"往工具箱里再添一件工具"的扩展。

## 七、选型决策：四问定分工

把前面的三笔账压成四个问题，按顺序问：

1. **测点围着一个中心转吗？** 台架/激振器/消声室里，测点密集围绕设备，电缆 5-20 m 内可达——ES 机柜式，通道密度与调节精度优先。
2. **设备要跟着被测对象走吗？** 整车/整机/船上，测点散布且设备随行——RS 分布式，短电缆+链缆。
3. **环境有多狠？** 冲击振动、粉尘、水、-40 °C 或 +60 °C 以上的户外——RS 的 IP66/IP67 与扩展温度是硬门槛；受控环境两者皆可，按通道密度选。
4. **数据率有多大？** 通道数乘采样率算总吞吐：超过 7.8 MSa/s 或希望百通道全速 48 kHz——要么 ES 主机承担主力，要么多台 REC 分片，要么分层降采样率。

九成项目在第二问就有答案；剩下的一成是**两段式项目**（实验室到野外），答案本来就是"两个都用"——这正是这个家族"一个生态、两件工具"的设计初衷。

## 一句话记住

ES 是车间里的铣床、RS 是背出门的电动工具：测点围着台架转、环境可控选 ES，测点散在整机上、日晒雨淋选 RS——按测点分布与环境分工，数据率与电缆长度两本账验证，一个工作流贯穿始终。
