# 传感器都接对了，第一条时历为什么还是作废？——Testlab Neo 时数据采集从通道设置到存储

> 同一台车、同一批传感器、同一根线缆，老师傅采回的数据干净完整，新手采回的第一条时历却因为峰值贴顶、转速没接、文件碎成七段而作废——差别不在接线，而在按下 Start 之前把三张表依次填好：通道设置（Channel Setup）定准每个通道，采集监视（Monitoring）盯住现场，存储管理（Storage）安排好落盘。本文以 Testlab Neo 的 Time Data Acquisition 工作台为主线，把一次采集会话拆成"设置—监视—存储"三幕，量程怎么按工况分档、跟踪条图怎么按转速分箱盯越限、长会话怎么拆文件与配预触发，逐一给出可操作的规则与数值账。

::: tip 30 秒速览
- **一句话**：硬件全接对了，为什么按一下开始键还是能把一上午的数据采废？
- **类比**：像出国旅行前的三张单据——护照签证（通道设置）、登机口屏幕（采集监视）、行李托运（存储管理），一张没办对，后面全卡住。
- **关键数字**：40 通道、20480 Hz 采 1 小时就是 11 GiB；峰值 7.8 V 的通道在 ±10 V 量程占 78% 正合适，换 ±5 V 直接贴顶报废。
- **结论**：数据质量在按 Start 之前就定了：量程按"峰占六到八成"逐工况分档，监视页只盯三五个关键量，长会话拆文件、给触发留预触发缓冲。
:::

## 一、作废的时历，问题都出在按 Start 之前

一个新手工程师的真实一上午：路试车 40 个通道全部接好，万用表逐个量过供电，自检全部通过，八点半准时发车。中午回来看数据，四个通道的过坎波形齐刷刷削顶——量程还停在上一场台架冲击试验的 ±10 V，而这一场的怠速信号只有几毫伏，量化台阶把小信号啃得毛茸茸；转速通道根本没接到采集会话里，整套数据找不到按工况切段的依据；两个小时的连续记录被存成了一个 8 GiB 的大文件，传输、打开、回放样样费劲，中途软件一次卡顿，整段作废重来。

值得注意的是：**这上午没有任何硬件故障**。传感器是对的、线缆是对的、采集卡也是对的，作废的根源全部坐在按 Start 之前的几张设置表里。时数据采集（Time Data Acquisition，工程上常简称 TDA）是所有 NVH 工作流的入口——后面的谱分析、模态、耐久、声学全部吃这里录下的时历，这一步录坏，后面没有任何算法能救回来（过载削波与量化损失为什么不可逆，见《[信号过载：削波如何毁掉频谱](../../theory/signal-processing/overload-clipping-distortion.html)》与《[量化与量程](../../theory/signal-processing/gain-range-quantization.html)》）。

反过来，同一间试验室里的老师傅会怎么做：出发前把 40 个通道的量程按"怠速/匀速/过坎"三种工况分别预估峰值，逐一核对采样率与带宽，把转速通道设为跟踪源，监视页上只放五个真正要盯的量，存储按 10 分钟一个文件切好、预触发留 10 秒。同样是按一下 Start，数据质量的差距就是这么来的。

把一次采集会话想成**出国旅行前的三张单据**：第一张是**护照与签证**——通道设置，每个通道的身份（传感器型号、灵敏度、工程单位）、通行范围（量程、带宽）全在这里核定，一本护照填错了国名，后面机票再准也出不了境；第二张是**登机口屏幕**——采集监视，起飞前后你盯的不是整座机场，只是你自己那班航班的登机口和准点状态，监视页也只该盯三五个关键量；第三张是**行李托运**——存储管理，一个 40 公斤的超大箱不如分成四个托运箱，托运前还要留出"手提行李"（预触发缓冲）对付说变就变的行程（触发）。这张"三张单据"的比方会贯穿全文。

::: info 核心概念
- **时数据采集（Time Data Acquisition, TDA）**：把传感器输出的电压/电荷信号经调节、滤波、模数转换后按时间序列连续记录为文件的工作流，是一切频域分析的原始数据来源
- **采集会话（Acquisition Session）**：一次从按下 Start 到按下 Stop 的完整记录过程，含通道设置、监视与存储三部分配置
- **跟踪源（Tracking Source / Tracked Channel）**：被指定为"横轴"的通道（典型是转速），其他量的监视与后处理均按它分箱
- **预触发（Pre-trigger）**：按触发启动记录时，把按下触发之前一段时间的数据也写盘的循环缓冲机制
:::

## 二、第一张单据：通道设置，每个通道的身份与通行范围

### 2.1 量程：峰值落在满量程的六到八成

通道设置里最先要定的数字是**量程（Range）**。它和"位数"共同决定实际分辨率：24 位 ADC 的台阶总数按满量程算，信号峰值只占量程一小截时，真正用得上的台阶也只剩一小截。工程上的经验法则——**让预估峰值落在满量程的 60%～80%**：留出两三成余量接住偶发冲击，又不至于把台阶浪费在永远到不了的高区。

代入数字：路试车里振动最大的悬置通道，过坎工况预估峰值 7.8 V，选 ±10 V 量程，占比 78%，正合适；如果图省事沿用上一场台架试验的 ±5 V 档，7.8 V 直接贴顶，波形削平、频谱冒出成串假谐波，这条通道当场报废。反过来，怠速工况声压通道输出峰值只有 0.31 V，同样停在 ±10 V 档，占比 3%——有效位数掉一大截，谱底上毛刺密布（量化损失的账在《[量化与量程](../../theory/signal-processing/gain-range-quantization.html)》里算过：峰值占量程 1/8 等效丢 3 bit、约 18 dB）。

这个公式回答的问题是"换了量程档，信号到底用上了多少台阶"：

$$\text{占用率} = \frac{V_{\text{pk}}}{V_{\text{Range}}} \times 100\%$$

分子是信号峰值，分母是量程档。占用率低于 20% 是"台阶浪费"，高于 90% 是"贴顶风险"，60%～80% 是安全区。**换工况先重算占用率**——怠速、匀速、过坎是三个量级不同的世界，一张量程表走天下必然有一头出事。

### 2.2 采样率与带宽：关心到多高的频率

第二个数字是**采样率（Sampling Rate）**。奈奎斯特判据要求采样率至少是最高关心频率的 2 倍，工程上惯用 **2.56 倍**——因为抗混叠滤波器需要过渡带（混叠怎么把高频折成假低频，见《[混叠与抗混叠滤波器](../../theory/signal-processing/aliasing.html)》）。车载振动关心到 2 kHz，采样率就设 5120 Hz；关心到 8 kHz（含啸叫等空气声成分），就要 20480 Hz。带宽（Bandwidth）是采样率经抗混叠滤波后真正可用的分析频带，两者在设置表里成对出现。

硬件侧的对应关系（以 SCADAS RS 调节单元为例）：U12 卡每通道 0.2 Hz～48 kHz 可选、带宽至 8 kHz，U12-E 扩展带宽至 20.7 kHz，B24/S24 电桥与传感器卡至 4 kHz，24 位 ΔΣ ADC、带内混叠抑制优于 −110 dB。**采样率跟着卡件能力与关心频率走，不是越高越好**——它直接乘进存储体积的账单（见第四节）。

### 2.3 灵敏度与工程单位

第三件事是把"电压"翻译成"工程单位"（EU）。加速度计 100 mV/g、麦克风 50 mV/Pa、应变通道按桥路算 mV/με，录入灵敏度后软件直接以 g、Pa、με 显示与存储。这里最容易出的事故是**型号拿错**：库房领出外观一样的 10 mV/g 与 100 mV/g 传感器，灵敏度录成 100，读数整整小 10 倍——这种错误事后可以用比例因子修正（怎么救见《[校准因子事后修正](../data-processing/calibration-factor-correction.html)》），但前提是**当场发现**；把监视页的单位读数与预估量级对一遍，就是最便宜的当场发现手段。转速与脉冲通道在卡件里经"脉冲与转速转换"变成 RPM 或频率读数，计数与速率两条路都由硬件完成。

### 2.4 跟踪源与分组：会话的骨架

通道表填到最后一列，是给会话立骨架：把转速通道设为**跟踪源**，监视与后处理就有横轴可依（见 3.3 节跟踪条图）；按测点位置或方向把 40 个通道分成若干**组（Group）**，监视页按组切换，报告按组出图。骨架立好，后面两幕的每一屏都在正确的坐标系里。

## 三、第二张单据：采集监视，登机口屏幕只显示你的航班

### 3.1 电平表：第一眼先看谁贴顶、谁贴底

按 Start 后的第一屏是**电平表**：每个通道一根横条，实时显示峰值占量程的百分比。它回答两个问题——**谁贴顶**（过载，红色告警）与**谁贴底**（信号太小，量化吃亏）。2.1 节的占用率法则在这里兑现：条子常年停在 80% 以上的通道，换大一档量程；常年 10% 以下的，换小一档。40 个通道扫一眼电平表只要十几秒，却是整场试验里性价比最高的十几秒。

电平表判读也可以交给数据说话。把采集中记下的三个通道峰值与两档量程放进同一段核算：

<details>
<summary>数值实验：同一组峰值在两档量程下的占用率与判读（10 行）</summary>

```python
import numpy as np

Vpk = np.array([7.8, 4.2, 0.31])       # 三个通道的实测峰值 V
for Vr in (10.0, 5.0):
    pct = Vpk / Vr * 100
    print('±%.0f V 量程 -> 峰值占比: %s' % (Vr, ' '.join('%.0f%%' % p for p in pct)))
```

</details>

结论先摆在这两行跑出来的数：±10 V 档下三个通道分别占 **78%、42%、3%**——第一条正合适、第二条偏保守但可用、第三条信号太小该换档；换到 ±5 V 档第一条直接 **156%**，贴顶报废。同一段电压、两档量程、两种命运，这就是 2.1 节占用率法则在电平表上的日常用法。

### 3.2 条图与自定义监视页

**条图（Strip Chart）**让波形滚动起来，看的是形态：毛刺（接触不良）、慢漂（温漂、零漂）、突跳（掉线）都逃不过肉眼。屏幕上滚动 40 个通道的默认视图，真正要盯的往往只有三五个量——驾驶员耳旁声压级、三个悬置加速度、水温。把它们拖进**自定义监视页**，一屏只留关键读数，超限的量标红示警。相关技术资料把这叫"监控页只留你关心的量"：监视的目的不是看见一切，而是**在正确的时刻看见要动手的那个数**。

### 3.3 跟踪条图：把"随转速变化"变成"对格判越限"

振动量级随转速变，盯着时域波形看不出名堂。**跟踪条图（Tracking Bar Chart）**把横轴切成转速格（比如每 400 rpm 一格），每格里显示该转速区间的振动量级（RMS 或峰值）——于是一座座柱子直接对量级限值线判越限，哪一段转速危险一目了然，也顺手为下一场试验的量程分档攒了证据。

<details>
<summary>数值实验：八个转速格的 RMS 对 0.5 g 限值线判越限（9 行）</summary>

```python
import numpy as np

rpm = np.array([800,1200,1600,2000,2400,2800,3200,3600])
rms = np.array([0.21,0.24,0.27,0.31,0.58,0.86,1.02,0.77])
over = rms > 0.5
print('跟踪条图: %d/%d 个转速格越限, 最差 %.2f g (超限 %.0f%%)'
      % (over.sum(), len(rms), rms.max(), (rms.max()/0.5-1)*100))
```

</details>

结论先摆在这段跑出来的数：**8 格里 4 格越限**，最差 1.02 g 出现在 3200 rpm、超限 104%。同一条数据，时域波形看不出任何"越限"——因为限值本来就是定义在"转速格"上的。跟踪条图还顺手回答了下一场试验的问题：2800～3600 rpm 区段的量程要按 1.1 g 预估，其余区段 0.6 g 足够。

## 四、第三张单据：存储管理，托运行李的重量账

### 4.1 存储体积：一道乘法题

这个公式回答的问题是"这场试验要写多少字节到盘上"：

$$S = N_{\text{ch}} \times f_s \times T \times b$$

四个因子：通道数、采样率、时长、每样本字节数（float32 为 4）。代入第四节开头那场路试：40 通道、20480 Hz、1 小时——

<details>
<summary>数值实验：40 通道一小时录多少 GiB、拆文件与预触发的账（14 行）</summary>

```python
import numpy as np

fs = 20480.0                      # 采样率 Hz
n_ch, hours = 40, 1.0             # 通道数与时长
raw = n_ch * fs * hours * 3600 * 4 / 1024**3
print('40 通道 x %.0f Hz x %.0f h x 4 B = %.1f GiB' % (fs, hours, raw))
for minutes in (5, 10, 20):
    seg = n_ch * fs * minutes * 60 * 4 / 1024**3
    print('  每 %2d min 一个文件: %5.2f GiB, 共 %d 个' % (minutes, seg, 60//minutes))
pre = n_ch * fs * 10 * 4 / 1024**3
print('预触发 10 s 只多占: %.3f GiB' % pre)
```

</details>

结论先摆在这段代码跑出来的数：**11.0 GiB**；按 10 分钟一个文件拆成 6 个 1.83 GiB 的段，传输、回放、单段重采都轻便得多；预触发 10 s 只多占 0.031 GiB——**不到总量的 0.3%，却买回了"触发前 10 秒也在盘上"的保险**。三个杠杆里通道数与时长由试验方案定死，**采样率是唯一可调的**：关心频率从 8 kHz 降到 2 kHz，采样率 20480 降到 5120，体积直接砍掉四分之三。这就是 2.2 节"采样率不是越高越好"的定量版本。

### 4.2 文件切分与自动递增

长会话拆多文件不只是为了好搬运：单文件过大时，一次写入失败就整段报废，拆成 10 分钟一段，损失被隔离在单段里。设置表里的**文件名自动递增**（Run1、Run2……）配合时间戳，让六段文件在数据导航器里仍能按会话找回整体。这与"按工况切段"是两层操作：存储切分发生在采集时、按时间等宽；工况切段发生在分析时、按判据（转速窗、marker）灵活进行——后者的做法见《[一段长时历，怎样按工况切成可复用的数据块？](neo-segments-multi-processing.html)》。

### 4.3 触发与预触发：循环缓冲兜住"已经过去"的信号

很多事件（急加速、异响、冲击）等你看见再按记录，**事情已经结束了**。触发（Trigger）解决"什么时候开始写盘"：电平触发盯某通道越过阈值，转速触发盯跟踪源进入区间。预触发（Pre-trigger）解决"触发之前呢"——采集卡在内存里维护一个**循环缓冲**（先进先出的传送带），触发发生时把缓冲里"触发前 N 秒"的数据一并写盘。图 3 橙色斜纹那段就是预触发缓冲：15 s 的缓冲、10 s 的预触发量，异常事件**前因**与**后果**一起落盘。

![长会话按时间拆多文件 + 循环缓冲兜住触发前数据](/images/neo-time-data-acquisition/fig3-storage-buffer.png)

回到托运的比方：预触发就是**手提行李**——不管托运规则怎么变，最要紧的那 10 秒随身带，不怕转机失误。

## 五、把三幕串起来：一次会话的检查单

- **采集前（护照签证）**：逐通道核对灵敏度与工程单位；按工况预估峰值、量程落在 60%～80%；采样率=关心频率×2.56 且不超过卡件带宽；转速通道设跟踪源；按测点分组
- **采集中（登机口屏幕）**：电平表扫一遍贴顶/贴底；条图看毛刺与漂移；自定义页盯三五个关键量；跟踪条图对限值线判越限
- **采集后（行李提取）**：核对文件段数与体积与 4.1 节乘法账一致；确认预触发段包含事件前因；按会话归档

硬件侧的对应：REC 单元至少 220 GB SSD、支持记录模板与测量文件存储、以太网/Wi-Fi/USB 三路取数、菊花链最远 50 m 供电传数——链路怎么搭见《[SCADAS RS 调节单元选型与八大卡件](rs-conditioning-modules.html)》，独立值班怎么立规矩见《[SCADAS RS 实战技巧六则](scadas-rs-tips.html)》。

## 一句话记住

数据质量在按 Start 之前就定了：量程让峰值占六到八成、采样率取关心频率 2.56 倍、监视只盯关键量、长会话拆文件、预触发留足事件前因——三张单据办齐，按下去的那一下才只是走个流程。
