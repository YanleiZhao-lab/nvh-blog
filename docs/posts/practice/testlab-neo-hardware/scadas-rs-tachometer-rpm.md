# 光电、磁电与编码器都能测转速，接到 RS 后为什么结果不同？——SCADAS RS 转速通道实操

> 同样测一根旋转轴，光电开关读得稳稳的，磁电传感器一到低速就报 0 rpm，高线数编码器读出来的转速却毛茸茸——转速是旋转机械测试里一切阶次、角域分析的横轴，但它从来不是"接上就有"的通道。本文以 SCADAS RS 为对象，把数字转速（REC 单元 9 路输入）与模拟转速（U12 单元 12P 专属通道）两条接入路径的硬件接线、Recorder App 设置、Skip Pulses 平滑、阈值/迟滞/保持三参数与 Too Slow 告警逐一讲透，并补上齿数-窗口-分辨率的量化账。

::: tip 30 秒速览
- **一句话**：三类传感器测同一根轴，为什么接到采集器后读数各不相同？
- **类比**：转速通道像机场的行李计数器——光电开关是"每个箱子挡一下光"，磁电是"靠箱子自己蹭出电来"，编码器是"传送带自带刻度尺"；计数器本身没坏，坏的是"箱子还没蹭出足够的电"或"刻度太密读出毛刺"。
- **关键数字**：60 齿齿轮配 0.2 秒窗口，读数一格是 5 rpm；换成每转 1 脉冲，同样窗口一格跳 300 rpm——齿数差 60 倍，读数粗 60 倍。
- **结论**：方波信号走 REC 的数字转速输入（免设阈值），正弦/变幅信号走 U12 的模拟转速通道（阈值+迟滞+保持三参数），高线数编码器按需开 Skip Pulses 每转只取一次——路径选对、参数填对，转速通道才可信。
:::

## 一、场景：三台传感器测同一根轴，读数对不上

台架验收前一天下午，三通道的转速对不上账：光电开关接在 REC 的数字输入上，读数稳稳的；磁电传感器接到 U12 的模拟转速通道，怠速段整整齐齐一排 0 rpm，转速爬上去之后才"醒过来"；高线数编码器接的也是数字输入，读数倒是出来了——毛茸茸一条噪声带，明明轴在匀速转。三台传感器测的是同一根轴，问题显然不在"轴转没转"。

排查一圈下来，三个现象的病根各不相同：磁电传感器是感应式器件，输出幅值正比于磁通变化率——转速掉到零附近，输出电压跟着坍缩，低于检测阈值后一个边沿都抓不到，读数自然是 0，Recorder App 上会挂出"Too Slow"告警；高线数编码器的病根正相反——每转几千个脉冲，软件对每个脉冲都更新一次转速估计，单脉冲的计时时钟抖动被逐个放大，匀速轴读出一条毛带；光电开关之所以稳，是因为它的输出是只有两个电平的方波，幅值与转速无关，"波形变边沿"这一步在比较器硬件里就做完了。

这三件事的共同点是：**转速测量的第一性问题不是"算得准不准"，而是"信号走对路径、参数填对格子"**。本文沿着数字/模拟两条路径，把 SCADAS RS 转速通道的硬件接线、软件设置与量化账目一次讲清。

## 二、转速传感器与两类信号

转速计（Tachometer）指一切测量转速的传感器：磁电探头（magnetic pickup）、光电传感器、激光对射，高每转脉冲数的器件也常被叫作编码器（encoder）。磁电探头对准齿轮，金属齿从磁极前经过时在线圈里感应出一串电压脉冲，脉冲间隔与轴速成正比；采集硬件解读脉冲间隔，换算出 RPM。典型设置如图 1：

![磁电探头对准齿轮产生与转速成正比的脉冲串](/images/scadas-rs-tachometer-rpm/fig1-magnetic-pickup.png)

*（图源：网络 侵删）*

按输出信号形态，转速计分两类（图 2）：

![数字转速信号（左）与模拟转速信号（右）](/images/scadas-rs-tachometer-rpm/fig2-digital-vs-analog.png)

*（图源：网络 侵删）*

::: info 核心概念
- **数字转速信号（Digital Tachometer）**：只有两个电压电平的脉冲串，理想值 0 V 与 5 V，波形像方波，常称 TTL 信号——SCADAS RS 对其他电平也有一定容忍度。因为只有两个值，不需要设阈值。
- **模拟转速信号（Analog Tachometer）**：脉冲幅值任意、波形不必是方波，幅值随转速可变（磁电探头的典型形态），必须手工设一个电压阈值，信号每次越过阈值算一个脉冲。
- **每转脉冲数（Pulses per Revolution / PPR）**：传感器每转一圈输出的脉冲个数——60 齿齿轮是 60，高线数编码器可达数千。它直接决定转速读数的分辨率。
:::

这个公式回答的问题是：采集硬件数出脉冲之后，怎么把它换算成每分钟转数。

$$
\mathrm{RPM} = \frac{f_{\mathrm{pulse}}}{N_{\mathrm{ppr}}} \times 60
$$

$f_{\mathrm{pulse}}$ 是每秒脉冲数，$N_{\mathrm{ppr}}$ 是每转脉冲数——60 齿齿轮就是 60，高线数编码器可达数千。数字与模拟两条路径最终都汇到这一步：硬件解读脉冲间隔得到 $f_{\mathrm{pulse}}$，再除以填在通道属性里的每转脉冲数。每转脉冲数填错，读数整体成比例偏——这是"读数差一个整数倍"的第一嫌疑。

两类信号对应两套硬件：**数字转速走 REC 单元（9 路数字输入），模拟转速走 U12 调节单元的第 12 通道（12P 专属输入）**。这就是"同一个传感器接不同地方结果不同"的第一层原因——路径选错，后面的参数全白填。

## 三、数字转速路径：REC 单元的 9 路输入

### 3.1 硬件：三个连接器，九路转速

REC 单元有三个专用数字输入连接器（面板标注 DI1、DI2、DI3，亦称 1P、2P、3P），每个连接器支持三路独立转速信号，或一个增量编码器（A/B/INDEX 三信号占满），合计 9 路数字转速（图 3）。

![SCADAS RS REC 单元三个数字输入连接器（DI1/DI2/DI3）](/images/scadas-rs-tachometer-rpm/fig3-rec-panel.png)

*（图源：网络 侵删）*

数字输入使用一根开放式电缆（部件号 REC-DI-WIRE-3M），各色线芯与针位的对应关系如图 5：

![数字输入开放线缆的线色-针位对应（REC-DI-WIRE-3M）](/images/scadas-rs-tachometer-rpm/fig5-pinout-colors.png)

*（图源：网络 侵删）*

三路单端转速的接线口诀（不用采集器供电时）：转速 1 用 7（白）与 8（棕），即 A- 与 A+；转速 2 用 1（绿）与 2（黄），即 B- 与 B+；转速 3 用 3（灰）与 4（粉），即 INDEX- 与 INDEX+。增量编码器则把前八根线全用上：A 与 B 两相的高每转脉冲信号用来判旋转方向（顺时针或逆时针），INDEX 定每转零位——普通转速计判不了方向，这是编码器独有的能力（B 相接反时转速绝对值正确、方向相反，软件里反转方向设置即可救回）。

### 3.3 Skip Pulses：高线数编码器的降噪开关

高每转脉冲数的编码器有个反直觉的坑：脉冲越多，转速反而越"毛"。原因在更新策略——默认每个脉冲都更新一次转速估计，单脉冲的计时抖动被逐个放大。Skip Pulses 功能把更新率压下来：Pulse processing 里打开 Skip Pulses，把 Pulses to Skip 设成"每转脉冲数减一"（图 9），软件就每转只取第一个脉冲、跳过其余，转速每转更新一次。

![打开 Skip Pulses 并把 Pulses to Skip 设为每转脉冲数减一](/images/scadas-rs-tachometer-rpm/fig9-skip-pulses.png)

*（图源：网络 侵删）*

图 10 的对比一目了然：蓝线是逐脉冲估计的转速，毛茸茸一条噪声带；绿线是每转更新一次的转速，干净贴合真实匀速。

![逐脉冲估计（蓝）与每转一次估计（绿）的转速对比](/images/scadas-rs-tachometer-rpm/fig10-skip-compare.png)

*（图源：网络 侵删）*

要不要开 Skip Pulses，取决于编码器的用途：只关心总体转速（做跟踪、切段），开——读数干净；要看每转内部的扭振波动（扭振分析），不开——毛刺里藏的正是每转内的转速起伏。该功能对数字与模拟转速信号都有效。

## 四、模拟转速路径：U12 单元的 12P 专属通道

### 4.1 硬件与接线

U12 调节单元有一个专属模拟转速输入，面板标注 12P（三根开放线芯）。在 Recorder App 里把 U12 的第 12 通道切到 Tacho (Analog) 模式后，接线要用标 12P 的通道，而不是只标数字 12 的普通通道（图 14）：

![U12 调节单元的 12P 专属模拟转速输入与通道设置](/images/scadas-rs-tachometer-rpm/fig14-analog-setup.png)

*（图源：网络 侵删）*

设置流程与数字路径同构：Channels 图标 - U12 - 第 12 通道 - Conditioning 设为 Tacho (Analog)，再在 Pulse processing 里填 Encoder pulses per rev。

### 4.2 阈值三参数：检测电平、迟滞与保持

模拟信号幅值任意，所以多了 Pulse detection 一组参数（图 16）：

![Pulse Detection Level / Hysteresis / Hold-off 三个模拟转速专属参数](/images/scadas-rs-tachometer-rpm/fig16-pulse-detection.png)

*（图源：网络 侵删）*

- **Pulse Detection Level（检测电平）**：判定脉冲的电压阈值。信号每次从下往上越过它算一个脉冲。磁电信号幅值随转速坍缩（见第五节），这个值要压到最低工作转速的信号幅值之下，又不能低到被噪声顶穿。
- **Pulse Hysteresis（迟滞）**：给阈值加一个宽度——上穿算脉冲后，必须回落超过迟滞宽度才能再计下一个，滤掉信号在阈值附近抖动造成的多重计数。
- **Pulse Hold-off（保持）**：时间维度的过滤器——新脉冲必须与上一对脉冲的间隔保持一定百分比的距离，比这更近的越限一律忽略，抑制毛刺与振铃。

三个参数合起来，就是把"波形变边沿"这件事从硬件比较器搬到了软件参数表：调好了和数字路径一样稳，调不好就是 0 rpm 或者转速虚高。

## 五、两本量化账：幅值坍缩与分辨率

### 5.1 磁电幅值账：为什么低速必然报 0

磁电探头是线圈加磁芯，齿轮每转过一个齿，磁通变化感应出电动势。这个公式回答的问题是：感应电动势的大小由什么决定。

$$
e = -N_{\mathrm{coil}} \frac{d\Phi}{dt}
$$

线圈匝数 $N_{\mathrm{coil}}$ 固定，磁通变化率 $d\Phi/dt$ 正比于齿轮线速度，也就是正比于转速。设 1800 rpm 时输出 3 Vpp、阈值 1 V：转速降到 600 rpm 只剩 1 Vpp，恰好压线；300 rpm 剩 0.5 Vpp、150 rpm 剩 0.25 Vpp——阈值永远够不着，读数恒为 0。

![磁电信号幅值随转速线性坍缩：阈值定在哪里都有低速盲区（自绘示意）](/images/scadas-rs-tachometer-rpm/fig12-collapse.png)

*（图源：网络 侵删）*

这不是传感器坏了，是物理规律。对策三条：阈值压低（代价是噪声顶穿风险）、换更多齿的齿盘（抬高低速脉冲率）、低速段直接换光电或霍尔。怠速工况多的测试，一般直接避开纯磁电方案。

### 5.2 分辨率账：齿数乘窗口决定一格多大

边沿干净之后，脉冲率换算转速的账已经在第二节算过（RPM = 脉冲频率 ÷ 每转脉冲数 × 60）。计数式测量绕不开量化台阶：窗口 $T$ 秒内数出的脉冲只能是整数，差一个脉冲转速差一格。这个公式回答的问题是：转速读数的最小刻度由什么决定。

$$
\Delta \mathrm{RPM} = \frac{60}{T \times N_{\mathrm{ppr}}}
$$

60 齿配 0.2 s 窗口，一格 5 rpm；每转 1 脉冲配同样窗口，一格 300 rpm——读数要么 0 要么 300，完全没法用。想细化分辨率，要么加齿数，要么拉长窗口；窗口拉长更新率下降，急变速工况里转速读数会"迟到"。图 13 把这本账画成一张图：

![齿数与测量窗口共同决定转速分辨率的一格（自绘示意）](/images/scadas-rs-tachometer-rpm/fig13-resolution.png)

*（图源：网络 侵删）*

<details>
<summary>数值实验：阈值、量化、幅值三本账各算一遍（16 行）</summary>

```python
import numpy as np

fs = 10000.0; t = np.arange(0, 0.5, 1/fs)      # 0.5 s 仿真
rpm0, N = 1800.0, 60                           # 60 齿, 1800 rpm
meas = 3.0*np.sin(2*np.pi*(rpm0/60*N)*t)       # 磁电: 3 Vpp 正弦

# 账一: 阈值压到 0.2 V 后, 1.8 V RMS 大噪声多次顶穿
rng = np.random.default_rng(3)
noisy = meas + 1.8*rng.standard_normal(t.size)
c = ((noisy[:-1] < 0.2) & (noisy[1:] >= 0.2)).sum()
print(f"阈值0.2V+大噪声: {c} 沿 -> {c/0.5/N*60:.0f} rpm (真值 1800, 虚高 {(c/900-1)*100:.0f}%)")

# 账二: 量化台阶 = 60/(T*PPR)
for T, ppr in ((0.2, 60), (0.2, 1), (1.0, 60)):
    print(f"窗口{T}s x 每转{ppr}脉冲: 一格 {60/(T*ppr):.0f} rpm")

# 账三: 磁电幅值坍缩 -> 低速低于阈值全丢
for rpm in (600, 300, 150):
    v = 3.0*rpm/rpm0
    print(f"{rpm} rpm: {v:.2f} Vpp -> " + ("能触发" if v > 1.0 else "低于阈值, 读数 0"))
```

运行结果要点：

```text
阈值0.2V+大噪声: 1000 沿 -> 2000 rpm (真值 1800, 虚高 11%)
窗口0.2s x 每转60脉冲: 一格 5 rpm
窗口0.2s x 每转1脉冲: 一格 300 rpm
窗口1.0s x 每转60脉冲: 一格 1 rpm
600 rpm: 1.00 Vpp -> 能触发
300 rpm: 0.50 Vpp -> 低于阈值, 读数 0
150 rpm: 0.25 Vpp -> 低于阈值, 读数 0
```

三本账连读：阈值压得太低噪声顶穿（账一），齿数太少量化太粗（账二），磁电低速幅值坍缩（账三）——参数任何一本没算平，转速读数就从"可信"滑向"离谱"。

</details>

## 六、验证与告警：Monitor 视图和 Too Slow

设置是否正确，最终要看读数。Recorder App 的 Monitor 视图（主菜单左侧或首屏进入）选 Strip 显示，看转速随时间演化（图 17 对应的 run-up/rundown 曲线）。Custom 标签页提供 Line、XY、Numerical、Analog、Video 五种显示：Analog 是指针表盘，右下角竖排三个点可以调颜色限值、切换成数字读出。

测量结束后，时数据文件里保存的是换算好的转速通道，**原始脉冲串并不保存**——如果需要留存原始脉冲信号本身，应把它拆成普通数据通道并行记录一份。

最常见告警是 Too Slow（图 21）：通道上没有检出任何脉冲时，Channels 或 Monitor 界面会挂出这个提示。三种可能：线缆断线或接线不对；设备没转（没有 rpm 可读）；模拟转速的电压阈值设得不合适，信号根本够不着阈值。

## 七、转速之后：阶次分析的接力

转速通道的可信度直接决定阶次分析的质量。阶次是振动频率与转频的比值——转频是转速除以 60，转速读数抖，阶次谱线的位置跟着抖，平均次数一多糊成一片；干净的转速通道配上角域重采样，阶次线在变速工况里才保持清晰。转频、阶次提取与 colormap 判读在《[阶次到底是什么](../../theory/rotating-machinery/whats-an-order.html)》与《[扭振阶次实操三则](../test-setup/torsional-orders-tips.html)》展开。

把转速通道设为采集会话的**跟踪源**后，跟踪条图按转速分箱盯越限、切段按转速判据取段、阶次分析以它为横轴（跟踪源怎么用，见《[Testlab Neo 时数据采集](neo-time-data-acquisition.html)》）。转速通道错了，后面所有按转速组织的数据跟着错——这是它值得单独一篇的根本原因。

## 一句话记住

方波走数字（REC 九路免阈值），正弦走模拟（U12 12P 配阈值/迟滞/保持三参数），高线数开 Skip Pulses 每转取一次；磁电幅值随转速坍缩有低速盲区，齿数乘窗口决定一格 60/(T×PPR) rpm——路径对、参数平，读数才可信。
