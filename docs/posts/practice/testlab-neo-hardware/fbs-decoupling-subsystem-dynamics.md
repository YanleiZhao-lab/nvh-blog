# 装配体测完了，怎样把某个部件的动力学剥离出来？——FBS Decoupling

> 悬置总成装在整车上测得的频响函数，是"悬置+整车"两层的混合物；电机装上试验台架测得的，是"电机+台架"的混合物。下游的虚拟样机装配只认**部件自己**的频响模型，于是问题来了：部件离不开真实的边界条件（预载、滑移、旋转的轮胎），测出来又必然带着台架的印记——FBS Decoupling（基于频响函数的解耦）给出的答案是：把装配体和已知结构各测一遍，再用一次"频域减法"把已知那半从测量结果里**数学地减掉**。本文用"水果摊去皮"这一把刀讲透它：怎么测、在软件里怎么点、误差在哪里被放大、以及三个量产级应用（悬架台架、底盘测功机上的轮胎、带激励适配器的悬置）分别靠它拿回了什么。

::: tip 30 秒速览
- **一句话**：部件装在台架/整车上才测得成，可测出来的曲线混着台架的动力学——怎么把台架那半"减"掉，只留部件自己？
- **类比**：水果摊去皮——想称净果肉，不必把果肉单独挖出来，先称带皮重量、再称皮重，两数一减就是净重
- **关键数字**：部件共振处台架把它的"存在感"压掉 99.5%（装配体导纳只剩部件真值的 0.5%），同样的减法在这里把测量误差放大约 200 倍——解耦不是免费午餐
- **结论**：装配体（AB）与已知结构（B）各测一组界面频响，软件做一次频域减法即得部件（A）的频响；成败关键在"已知结构要相对刚硬、界面自由度要测全、误差放大的频段要心里有数"
:::

## 一、为什么部件的频响总是"测不干净"

先看一个真实的两难。某车型做结构 borne 路噪的虚拟样机预测，流程需要**悬架系统**的频响函数（FRF）模型。悬架的真实工作状态有两个硬条件：四分之一车身重量的**静态预载**把弹性衬套压到工作刚度，减振器低速滑移产生阻尼特性——这两个条件只有在**台架**上才能复现。于是悬架被装上液压试验台，预载、滑移都加了，锤击测得一组干净的 FRF。

问题是：这组 FRF 是"悬架+台架"的。台架夹具又重又硬，它的质量、刚度、阻尼全部混进了曲线里的每一个峰谷。把这样的模型喂给虚拟样机装配（把各部件 FRF 拼成整机预测），等于往天平上放了一个没去皮的秤盘。

反过来的路也走不通：把悬架单独吊起来自由悬置测 FRF？可以，但没了预载，衬套刚度完全不是工作状态的那回事——**边界条件一变，部件动力学就变**（柔性悬置在整车重量与行驶动载的静预载下会出现刚度强化效应）。单独测得到的是"另一种物理"，不是工程想要的那个部件。

这是一个普遍困局：

- **要真实边界条件** → 必须上台架/整车 → 测量结果**被外部硬件污染**；
- **要无污染** → 必须拆下来自由测 → **边界条件丢失**。

FBS Decoupling 正是为这个两难准备的：**带着外部硬件测，再用数学把外部硬件减掉**——边界条件保住了，污染也去掉了。Simcenter Testlab 2606 版把这个能力做进了标准工作流。它与《[两个部件隔着半个地球，装配体的频响凭什么提前算出来？](../../theory/modal-analysis/frf-based-substructuring.html)》正好是一对逆操作：那篇讲"拼"（FBS 耦合，把部件 A、B 的 FRF 加成装配体 AB），这篇讲"拆"（FBS 解耦，从 AB 与 B 反推出 A）。

## 二、去皮类比：先称带皮重，再称皮重

把整个方法想成水果摊老板称净果肉。

老板要卖的是**净果肉**（部件 A 的动力学），但果肉长在皮里（装在台架 B 上）才保得住形状（真实边界条件）。硬把果肉抠出来单称（自由悬置测量），果肉变形了（边界条件丢失），称出来的不是那回事。老板的办法是两步：

1. **先称带皮的总重**：果肉+皮一起上秤——这对应测**装配体 AB** 的 FRF；
2. **再称皮的重量**：把果肉切走，皮单独上秤——这对应把部件 A 拆下，单独测**已知结构 B** 的 FRF；
3. **两个数一减**：总重−皮重=净果肉——这就是解耦公式做的事。

这个类比里藏着方法成立的全部前提，值得逐条对上：

- **皮重必须已知**：你得**知道**要减掉的是什么。B 的动力学要么单独测过（拆掉 A 再锤一遍），要么有可信的仿真模型——不知道皮重，减法无从谈起；
- **秤要够准**：净果肉比总重小得多时，两个大数相减得到的小数对**读数误差极其敏感**。皮 500 g、果肉 5 g，两秤各差 1 g，净重误差就是 20%。解耦的误差放大正是这个机制（第四节定量算）；
- **果肉与皮的"连接面"要对齐**：称重只要一个数，频响减法要求装配体测量与 B 测量在**同一组界面自由度**上进行，界面信息残缺，减法就会在错误的维度上进行。

还有一个容易忽略的对称性：去皮与"拼果盘"互为逆操作。把苹果肉与梨肉拼盘（FBS 耦合）和从拼盘里减掉梨肉（FBS 解耦），用的是同一张界面频响表、同一套数学，只是一个加号一个减号。软件里它们也住在同一个地方——这也是为什么耦合玩得熟的团队，上解耦几乎零学习成本。

## 三、测什么：两组 FRF 与界面自由度

这个公式回答的问题是：**装配体与已知结构分别要在哪些自由度上测频响，减法才有得做**。

$$
[\boldsymbol{Y}^{\text{AB}}] = [\boldsymbol{Y}^{\text{A}}] + [\boldsymbol{Y}^{\text{B}}] \quad \Longrightarrow \quad [\boldsymbol{Y}^{\text{A}}] = [\boldsymbol{Y}^{\text{AB}}] - [\boldsymbol{Y}^{\text{B}}]
$$

最简形式的减法解耦：装配体 AB 与已知结构 B 在**同一组界面自由度**上的导纳矩阵，逐频率相减。工程实践用的是它的对偶式（LM-FBS 求逆形式，见第四节），但测量要求从这一式就能读出来：

- **装配体 AB 一组**：部件 A 装在 B 上、施加真实边界条件（预载、滑移、旋转……）时测；
- **已知结构 B 一组**：拆走 A，B 保持**完全相同的边界条件**再测一遍。

界面自由度（c）是减法的"对齐栅格"。最少要求：两组 FRF 覆盖部件与已知结构连接界面的全部自由度；工程上强烈建议在已知结构上加**额外观测自由度**（b）改善数值条件、在部件上加观测自由度（a）扩展所得模型。虚拟点变换（VPT）把物理上够不着的连接点换算成最多 6 个方向的虚拟点，锤击与激振器两条测量路线都支持。

![FBS Decoupling 的自由度布局：界面自由度 c 上必须两组都测，已知结构上的观测自由度 b 改善数值条件，部件上的观测自由度 a 扩展所得 FRF 模型](/images/fbs-decoupling-subsystem-dynamics/fig4-dofs.png)

*（图源：网络 侵删）*

::: info 核心概念
- **装配体/已知结构/部件（Assembly AB / Known Structure B / Component A）**：解耦的三位主角——AB 是"带皮总重"，B 是"皮重"，A 是想称出来的"净果肉"
- **界面自由度（Connection Interface DOFs）**：A 与 B 的连接点自由度，两组测量必须在其上完全对齐，是减法的作用面
- **虚拟点变换（Virtual Point Transformation, VPT）**：用连接点周围若干可达测点的响应，经最小二乘换算出虚拟连接点的 6 自由度频响——接口描述标准化，物理位置不可达也能测
:::

## 四、减法的代价：误差在哪些频段被放大

去皮类比已经提示：净重远小于总重时，减法把称量误差放大。这一节把这笔账定量算清——它直接决定解耦结果**哪些频段可信**。

这个公式回答的问题是：**装配体测量的相对误差，经过解耦减法后会被放大多少倍**。

$$
\boldsymbol{Y}^{\text{A}} = \boldsymbol{Y}^{\text{AB}} - \boldsymbol{Y}^{\text{B}} \quad \Longrightarrow \quad \frac{\delta \boldsymbol{Y}^{\text{A}}}{\boldsymbol{Y}^{\text{A}}} = \left( 1 + \frac{\boldsymbol{Y}^{\text{B}}}{\boldsymbol{Y}^{\text{A}}} \right) \cdot \frac{\delta \boldsymbol{Y}^{\text{AB}}}{\boldsymbol{Y}^{\text{AB}}}
$$

读法：误差放大倍数是 $|1 + Y^{B}/Y^{A}|$。当已知结构 B 的导纳远大于部件 A（皮很"活跃"）时误差被急剧放大；反过来 B 很刚硬（导纳小）时，$Y^{B}/Y^{A}\to 0$，放大倍数趋近 1——**减法几乎不伤测量精度**。这就是"已知结构要相对刚硬"的定量出处，也是解耦成败的第一判据。

用一组 2 自由度数值实验把这笔账跑出来（部件 A 弹性模态 123 Hz，已知结构 B 质量大 5 倍、刚度大 15 倍）：

<details>
<summary>数值实验：减法解耦的精度与误差放大账（16 行，本机实跑）</summary>

```python
import numpy as np
f = np.linspace(1, 300, 2999); w = 2*np.pi*f
def Y(m1, m2, k, c):              # 2 自由度链，界面在 m1：界面导纳
    K = k + 1j*w*c
    return K / ((K - m1*w**2)*(K - m2*w**2) - K**2)
YA = Y(2.0, 1.0, 4e5, 8.0)        # 部件 A：弹性模态 123 Hz
YB = Y(10.0, 1.0, 6e6, 30.0)      # 已知结构 B：重 5 倍、硬 15 倍
YAB = 1/(1/YA + 1/YB)             # 装配体：界面串联
Ydec = 1/(1/YAB - 1/YB)           # 减法解耦复算 A
err0 = np.max(np.abs(Ydec-YA))/np.max(np.abs(YA))
fa, fd = f[np.argmax(np.abs(YA))], f[np.argmax(np.abs(Ydec))]
print(f"无噪声解耦：与 A 真值最大相对偏差 {err0:.1e}，峰 {fa:.1f}/{fd:.1f} Hz 重合")
rng = np.random.default_rng(7)
noi = 1 + rng.normal(0,.05,f.size) + 1j*rng.normal(0,.05,f.size)
Ydn = 1/(1/(YAB*noi) - 1/YB)      # 装配体导纳含 5% 噪声再解耦
rel = np.abs((Ydn-YA)/YA)
print(f"装配体导纳加 5% 噪声：解耦误差中位数 {np.median(rel)*100:.1f}%")
for fq in (20., 123., 250.):
    k_ = np.argmin(np.abs(f-fq))
    amp = np.abs(1 + (1/YB)/(1/YA))[k_]
    print(f"{fq:5.0f} Hz：误差放大 |1+Z_B/Z_A|={amp:6.1f}，实际误差 {rel[k_]*100:6.1f}%")
```
</details>

运行结果：

```text
无噪声解耦：与 A 真值最大相对偏差 4.1e-16，峰 1.0/1.0 Hz 重合
装配体导纳加 5% 噪声：解耦误差中位数 15.5%
   20 Hz：误差放大 |1+Z_B/Z_A|=   4.8，实际误差  33.0%
  123 Hz：误差放大 |1+Z_B/Z_A|= 205.8，实际误差  98.5%
  250 Hz：误差放大 |1+Z_B/Z_A|=   0.3，实际误差    1.8%
```

三行输出对应去皮类比的三个区段，值得逐行读：

- **20 Hz（低频段）**：放大 4.8 倍，5% 的测量误差变 33%——中度失真。低频段 B 的导纳尚不可忽略，减法已经开始放大；
- **123 Hz（部件 A 共振处）**：放大 206 倍，误差 98.5%——完全报废。物理原因很直白：共振处 A 极"软"（导纳极大），装配体的一举一动都被 B 主导，A 的存在感被压掉——数值实验里装配体导纳只剩部件真值的 **0.5%**（被压掉 99.5%）。两个大数相减得到一个极小的数，任何噪声都把它淹没。这正是"皮厚果肉薄"区段；
- **250 Hz（高频段）**：放大 0.3 倍，误差反而缩小——B 的导纳远小于 A，减法近乎恒等操作。

结论落在两句话上：**解耦精度不是全频段均匀的**，它在"B 比 A 硬"的频段近乎免费，在"A 共振、B 主导"的频段灾难性放大；所以**判据频段图**（$|Y^{B}/Y^{A}|$ 随频率的曲线）应当在解耦前就画出来，心里有数再动手。工程对策也顺理成章：提高装配体 FRF 的测量质量（多次平均、相干把关）、在 B 上加观测自由度改善数值条件、必要时启用正则化——软件为"装配体对部件不敏感"的情形准备了正则化选项。

## 五、在软件里怎么走：从锤击到部件库

Simcenter Testlab 2606 把 FBS Decoupling 做进了 Virtual Prototype Assembly（VPA）工作流，全程不离开常规界面。

**第一步：测两组 FRF。** 锤击（impact testing）或激振器（shaker testing）两条路都支持，与常规模态测试同一个操作习惯。装配体状态测完 AB，拆下部件测 B，界面自由度通过 VPT 标准化为最多 6 自由度虚拟点——即便连接点物理上被夹具挡住也能换算出来。

![虚拟点变换（VPT）在锤击与激振器两条测量路线中处理界面数据：物理测点换算为最多 6 自由度的虚拟连接点](/images/fbs-decoupling-subsystem-dynamics/fig5-vpt.png)

*（图源：网络 侵删）*

**第二步：发布到部件库。** 两组 FRF 以标准化格式发布（publish）到**部件库**（component library）——装配体是一个库条目，已知结构是另一个。这一步的意义在于复用：同一台台架（B）测过一次，之后每个部件变型都只测装配体状态，B 直接从库里调。

**第三步：装载、连接、算。** 在 VPA 里把装配体与已知结构装载进来、在界面上连线，FBS Decoupling 计算自动执行。结果就是部件 A 的 FRF 模型，可直接进入下游的 FBS 耦合、部件级 TPA 等虚拟样机流程。正则化选项在计算设置里按需开启。

![VPA 装配器中的 FBS Decoupling：从部件库装载装配体与已知结构、在界面连线，解耦计算自动执行](/images/fbs-decoupling-subsystem-dynamics/fig7-vpa.png)

*（图源：网络 侵删）*

对熟悉 VPA 的团队，这个工作流的额外学习成本接近零——它就是"装配"界面上多了一种"反着接"的接法。

## 六、三个量产级应用：各自靠解耦拿回了什么

**应用一：悬架系统——台架预载下的 FRF。** 前文的两难就发生在这里。悬架装在液压台架上（四分之一车重静态预载+减振器低速滑移），测装配体 FRF；台架单独再测，解耦得到悬架在工作边界条件下的 FRF 模型。公开文献报告这一路线已用于整车路噪的虚拟样机预测：单独可测（自由悬置）得不到的"预载后衬套刚度"，与台架污染（夹具动力学）这对矛盾被同时解决。

![悬架在试验台架上测装配体 FRF：静态预载与减振器滑移是必须保留的边界条件，台架动力学随后由解耦减掉](/images/fbs-decoupling-subsystem-dynamics/fig8-suspension.png)

*（图源：网络 侵删）*

**应用二：轮胎-车轮——底盘测功机上的旋转状态。** 轮胎的动态特性与**是否旋转**强相关（离心力改变胎冠张力、胎面与滚筒的接触印迹随转速变化），静态不转的轮胎测出来代表不了行驶状态。解耦路线：整车开上底盘测功机（四分之一车重预载+可变转速），测"整车+轮胎"装配体 FRF；随后同车的轮胎部分再单独测（整车提供了静态预载、测功机提供了旋转），解耦剥离整车与测功机，得到旋转状态下的轮胎-车轮 FRF。

**应用三：带激励适配器的悬置——减掉那只"手"。** 测柔性悬置的 6 自由度界面 FRF 时，常在连接点加装**激励适配器**（excitation adapter）以便 VPT 换算。适配器本身的高频动力学又被混进了测量——解耦把适配器减掉，得到悬置主动侧/被动侧各 6 自由度虚拟点的完整 12×12 FRF 模型。这是"去皮"最纯粹的形态：那只帮你按住水果的"手"，用完就撤。

![柔性悬置的 12×12 FRF 模型：主动侧与被动侧各 6 自由度虚拟点界面，激励适配器的动力学由解耦减掉](/images/fbs-decoupling-subsystem-dynamics/fig10-mount.png)

*（图源：网络 侵删）*

三个应用共享同一个模式：**边界条件必须由外部硬件提供（预载/旋转/适配器），而外部硬件的动力学又被解耦减掉**。判断自己的项目适不适合，先问两句话：部件的工作状态是否离不开外部硬件？这套外部硬件是否已知（可单独测或有可信模型）？两问皆是，解耦就是对症的工具。

## 七、四条工程建议

1. **先画判据图再动手**：解耦前把导纳比（或动刚度比）随频率的曲线画出来，误差放大严重的频段要么改进测量，要么提前声明结果的有效频段；
2. **已知结构单独测时，边界条件要复现**：B 的"皮重"必须在与装配体测量**相同的状态**（同样的预载、同样的夹紧）下测，否则减掉的是另一种皮；
3. **界面自由度宁可多不可少**：最少界面 c 一组，但 B 上的观测自由度 b 显著改善数值条件——第四节 206 倍的放大就是"装配体对部件不敏感"的直接后果，多几个观测点是性价比最高的解药；
4. **部件库思维**：台架 B 测一次入库，后续每个部件变型只测装配体——解耦的复用红利来自"皮重称一次、反复用"。

## 一句话记住

FBS 解耦就是频域的"去皮称重"：带皮称一次（装配体 AB）、皮单独称一次（已知结构 B）、两数相减得净重（部件 A）——前提是皮要够硬（B 相对刚硬、导纳小）、秤要够准（装配体 FRF 质量）、界面栅格要对齐（自由度测全）；而在部件共振、台架主导的频段，减法把误差放大成百倍，那一段的结果要打折看待。
