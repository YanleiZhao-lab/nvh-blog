# Time Signal Calculator：时域公式处理实用技巧

> 采完数据才发现忘了滤低通、通道间要相减、转速通道有毛刺、频谱里混进了 8 Hz 电源谐波——重新跑车太贵，这一批数据还有救吗？Simcenter Testlab 的 Time Signal Calculator 用一行行公式对时域 trace 做加减积分、滤波、生成与转速换算，是测试工程师手里的"数据后厨"。这篇按工程问题组织，讲清楚每个高频函数怎么用、参数怎么填、坑在哪里。

## 一、它是什么：给时域数据一间公式厨房

Testlab 界面里大部分工作表是"流程式"的——选通道、设参数、点 Calculate。Time Signal Calculator 反过来：你在一张公式表里逐行写表达式，每一行的输入可以是原始通道，也可以是上一行的输出，像电子表格一样层层搭。

典型场景一眼就懂：

- 两个加速度通道相减，得到两点之间的**相对振动**；
- 对加速度做积分得到速度、再积分得到位移——但直接积分会漂，后面讲怎么处理；
- 对某段信号施加低通/带通滤波，只想"听一听"某个成分长什么样；
- 用公式**生成**一个并不存在的信号——正弦、方波、扫频，再换算成 RPM 通道。

启用路径固定两步：菜单 **Tools -> Add-ins** 勾选 **Time Signal Calculator**（占用 26 tokens），它就出现在 Time Data Selection 工作表下方。点 **f(x)** 按钮弹出函数选择器，左侧按用途分组：Conditioning（滤波类）、Tacho（转速类）、Trigonometry、Statistics 等。选完函数，参数在公式行内就地填写。

::: info 核心概念
- **Function1/Function2**：公式里引用的输入通道，可以填通道号（CH1、CH2）或通道名（Tacho、Acc_Left），也可以引用别的公式行的输出
- **f(x) 按钮**：函数选择器入口，按分组浏览所有可用函数
- **Save As**：把公式结果存成新 trace 而不覆盖原始数据——养成习惯，永远别在原始数据上直接动手
:::

::: warning 工程注意
公式计算默认在**整个 trace** 上执行。数据里若有坏段（过载、断线、毛刺），先用 Time Data Editor 处理干净再进公式表——数学运算不会替你发现数据是坏的，乘上一个错误因子只会错得更隐蔽。
:::

## 二、四个高频任务的做法

### 任务 1：滤波——低通去掉转速通道的高频噪声

Conditioning 组里的 FILTER_LP、FILTER_HP、FILTER_BP 分别对应低通、高通、带通。以 FILTER_LP 为例，添加函数后在菜单里指定滤波器类型（IIR 还是 FIR）、方法（Butterworth、Bessel、Chebyshev 等）、阶数与截止频率。

*（图源：Simcenter Testing Knowledge Base）*

![滤波函数的参数菜单：类型、方法、阶数、截止频率](/images/time-signal-calculator-tips/filter-formula-menu.png)

*（图源：Simcenter Testing Knowledge Base）*

两个容易踩的细节：

- 菜单里的 **Sample Frequency** 只用于"画滤波器形状"的显示范围，对滤波器本身的性能和属性**没有任何影响**——别指望调它改变截止特性；
- 点 **Show** 按钮可以预览滤波器的幅频、相位与群延迟形状，确认无误再执行。IIR 滤波器在截止频率附近群延迟最大，FIR 各频率延迟恒定——相位敏感场合的选型依据，详见《[FIR 与 IIR：滤波器怎么选](../../theory/fir-vs-iir.html)》。

### 任务 2：通道运算——相减、平均、积分

最朴素也最常用。两通道相减：`CH1 - CH2`，直接得到差分信号；多通道平均用求和除以通道数。

积分是大坑重灾区。加速度积分一次到速度，速度再到位移——理论上没问题，实际上积分是累积运算，信号里任何一点直流偏置、低频漂移都会被积分器放大成一条斜线，几秒后位移曲线就飘出画面。工程做法：积分前先高通（去直流与漂移），积分后检查曲线首尾是否闭合。Testlab 也提供了积分相关的内置函数，配合 FILTER_HP 一起用。

::: tip 相减与积分的组合拳
想看"底盘传递到方向盘的振动衰减了多少"，不必分别评估两个通道——先 `CH1 - CH2` 得到相对振动，或对加速度积分到位移后再比，一条曲线直接给出传递效果。相减要在同一坐标系、同一采样率下进行，不同采样率的通道先重采样再运算。
:::

### 任务 3：RPM 相关——毛刺清洗与转速生成

Tacho 组是旋转机械分析的后台功臣。上一篇讲过 TACHO_MOMENTS_SPIKEREMOVAL_TO_RPM 按统计判据剔除每转固定位置的毛刺（见《[RPM 信号去毛刺](./rpm-spike-removal.html)》），这里补一个更巧的用法：**用公式凭空造一个 RPM 通道**。

场景：台架数据频谱里混进了 8 Hz 及其倍频的干扰谐波——典型的电源或接地环路污染。想去掉它们需要 HARMONIC_FILTER 函数，而谐波滤除**必须有 RPM 通道**做基准，可这批数据根本没接转速。谐波是固定 8 Hz，那就造一个：第一步用公式生成 8 Hz 方波，第二步把方波换算成 RPM——一台"虚拟转速计"就有了，HARMONIC_FILTER 拿它当基准，把 8 Hz 基频及各阶倍频整族扣除。

![两行公式造出虚拟转速通道：先生成 8 Hz 方波，再换算成 RPM](/images/time-signal-calculator-tips/create-tacho-rpm.png)

*（图源：Simcenter Testing Knowledge Base）*

![上：原始数据 colormap 中 8 Hz 谐波族竖条带；下：谐波滤除后的干净图谱](/images/time-signal-calculator-tips/harmonics-removed.png)

*（图源：Simcenter Testing Knowledge Base）*

同样的套路换个基准就变出新玩法：数据被 50 Hz（欧洲）或 60 Hz（美国）电源谐波污染时，把方波频率改成 50 或 60；分不清某阶成分来自泵还是发电机时，只要两者转速比**不是整数倍**，分别以各自的转速为基准做谐波滤除，就能把阶次"归属"拆开。

::: warning 工程注意
谐波滤除按基准转速的"阶次"工作。8 Hz 固定频率谐波配上 8 Hz 方波生成的 RPM，等效于 1 阶及其倍数——族内所有谐波一次扣干净。但如果干扰频率会漂（比如变频器开关频率随工况移动），固定基准就扣不准了，得先确认干扰是"定频"再动手。
:::

### 任务 4：合成信号——正弦、扫频、噪声

Trigonometry 与信号生成函数可以按公式造出标准正弦、方波、扫频甚至随机噪声，用途比看起来广：

- **演示与培训**：给新人一组"成分已知"的信号练手，谱分析做完对照答案；
- **方法验证**：造一个 30 Hz 正弦加噪声，跑一遍自己的滤波流程，看幅值恢复得准不准——处理真实数据前先在已知信号上过一遍，是最便宜的质量控制；
- **缺失通道补位**：分析流程需要 RPM 而实车数据没测转速，虚拟转速（见任务 3）顶上。

## 三、Python 演示：毛刺剔除的统计逻辑

Tacho 组毛刺剔除函数的核心判据是**中值绝对偏差 MAD（Median Absolute Deviation）**：在滑动窗口内算出中值与 MAD，偏离中值超过阈值倍数（默认 3.5）的点判为坏点替换。整个逻辑用 numpy 二十行就能复现——拿来清洗自己的 CSV 数据同样成立。

```python
import numpy as np

fs = 2000.0
t = np.arange(0, 3.0, 1/fs)                  # 3 秒仿真振动数据
sig = 1.5*np.sin(2*np.pi*30*t) + \
      np.random.default_rng(7).normal(0, 0.2, len(t))  # 30 Hz 成分 + 噪声
x = sig.copy()
x[1500:1520] += 40                           # 注入一个毛刺（模拟转速尖峰）

win = 201                                    # 滑动窗口，约 0.1 秒
pad = np.pad(x, win//2, mode='edge')         # 边缘延拓，防越界
med = np.array([np.median(pad[i:i+win]) for i in range(len(x))])
mad = np.median(np.abs(x - med))             # 中值绝对偏差
thr = 3.5 * 1.4826 * mad                     # 3.5 倍 MAD，对齐 Testlab 默认阈值
x_clean = np.where(np.abs(x - med) > thr, med, x)  # 坏点替换为中值

print(f"毛刺段峰值 清洗前 {x[1500:1520].max():6.2f} -> 清洗后 {x_clean[1500:1520].max():6.2f}")
print(f"全信号 RMS 清洗前 {np.sqrt(np.mean(x**2)):6.3f} -> 清洗后 {np.sqrt(np.mean(x_clean**2)):6.3f}")
print(f"30 Hz 正弦的理论 RMS = 1.5/sqrt(2) = {1.5/np.sqrt(2):.3f}")
```

最值得看的是 RMS 的变化：清洗前 2.5 上下——毛刺虽短，能量全在平方里，把整体 RMS 顶得虚高；清洗后回到 1.07 左右，正好落在 30 Hz 正弦的理论值 1.06 附近。这就是统计判据的价值：不用人工圈毛刺，不用改原始数据主体，坏点自动出局。

## 四、函数选择速查

| 工程问题 | 函数/做法 | 关键参数 | 注意 |
| --- | --- | --- | --- |
| **去高频噪声** | FILTER_LP | 方法/阶数/截止频率 | Sample Frequency 仅影响预览显示 |
| **积分去漂移** | FILTER_HP + 积分 | 高通截止要低于信号最低频率 | 先滤后积，积分后查首尾闭合 |
| **相对振动** | CH1 - CH2 | 通道同采样率 | 采样率不同先重采样 |
| **每转毛刺** | TACHO_MOMENTS_SPIKEREMOVAL_TO_RPM | threshold 默认 3.5 | 换直线会抹掉真实扭振信息 |
| **接缝修正** | ZEBRA_MOMENTS_TO_RPM | Pulses_per_rev | 16A 起支持多接缝 |
| **定频谐波族** | 造 RPM + HARMONIC_FILTER | 方波频率等于干扰基频 | 干扰须定频，漂移的扣不准 |
| **成分归属** | 双基准谐波滤除 | 两转速比须非整数倍 | 整数比时阶次重叠不可分 |
| **无中生有** | 信号生成函数 | 频率/幅度/扫频范围 | 合成数据勿与实测混存 |

::: tip 三条工作习惯
- 公式表搭好后**保存为模板**：同一台架的固定处理链（滤波、相减、积分）下次直接调用，参数只改截止频率
- 所有结果走 **Save As** 存新 trace，原始数据永远只读
- 拿不准处理链是否可靠时，先造一段成分已知的合成信号从头跑一遍，输出对得上再喂真实数据
:::

## 五、小结

Time Signal Calculator 的价值不在函数多，而在"可组合"：滤波、运算、生成、转速换算在一个公式表里串成处理链，测试数据的绝大部分后天补救都能在这里完成。判断标准就一条——**能在数据端解决的，绝不动测试资源**：重新跑一次整车转毂的成本，够你把公式表玩熟十遍。
