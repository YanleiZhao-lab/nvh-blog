# 矢量合成：把三向振动变成一个可读数

> 一只三向加速度计测出 X、Y、Z 三条曲线，报告里却常常只需要一个数。矢量合成（Vector Sum）对三个方向的频谱逐谱线做平方和开根号，得到与方向无关的总振动量级——悬置两侧读数不一致、人体振动评价、多测点横向对比，都靠它收敛成一条曲线。这篇给出公式与数值示例、Simcenter Testlab 里的两条设置路径，也分析那个最容易做错的顺序问题：先 FFT 还是先合成。

悬置验收会上经常上演这一幕：同一台样车、同一段路面，甲方用 Z 向数据判合格、乙方拿 X 向数据说不合格——两个方向都没测错，只是各自挑了对自己有利的坐标轴。更麻烦的是，左右悬置各三个方向，一张图里六条曲线扭在一起，谁也没法在评审会上三分钟讲清"这台车到底抖不抖"。真正需要回答的问题其实很朴素：**不看方向，这台设备的总振动到底是多大？** 把三个方向的读数直接相加显然不对（5 g 加 7 g 加 12 g 等于 24 g，物理上从没见过这么算的），那正确的"合成"该怎么合、合完之后哪些信息丢掉了、软件里又该在哪一步做？这一篇就把这三个问题一次说清。

## 一、三个方向各说各话，报表只要一个数

悬置被动端做一次升速，X 向在 2800 rpm 附近出现峰值，Z 向过了 3000 rpm 才是主角——三个方向的主导转速段不重合是常态，不是异常。读图的人需要在三条曲线之间来回切换，自行估计一个总量级；如果再算上左右两个悬置共六个方向，一张图就难以阅读了。

零件疲劳和人体舒适都与方向无关。不管振动是横向还是纵向，该疲劳还是疲劳，该不适还是不适。所以很多评价场景（整车路试验收、供应商对接、人体振动暴露量）需要的恰恰是一个**与方向无关的总量**。

矢量合成做的就是这样一件事：对三向数据逐谱线取平方和开根号。以相关技术文档的例子——$X=5\ \mathrm{g}$、$Y=7\ \mathrm{g}$、$Z=12\ \mathrm{g}$——合成值 14.76 g。一个数，三向能量尽收其中。

::: info 核心概念
- <strong>矢量合成（Vector Sum）</strong>：逐谱线对 X、Y、Z 三向做平方和开根号，得到与方向无关的振动总量级，永远不小于最大的单方向分量
- **作用对象是频率函数**：谱（Spectrum）、自功率谱（Autopower）、阶次（Order）、频率剖面（Frequency Profile）都在列；Testlab 里它是导出通道（Derived），不在时域原始数据上算
- **复数谱线**：含相位的谱线按模平方逐项相加，即模长平方和再开根，相位只进幅值不进方向
:::

打个生活中的比方：三向加速度计就像挂在同一根绳子上的三个秤。想象你在超市买水果，一袋苹果同时往三个方向歪着拎——东边一股劲、北边一股劲、往上还有一股劲，三个弹簧秤各自显示一个读数。你关心的"这袋水果到底有多沉"，不是三个读数的算术和，而是它们的**平方和开根号**——因为三股力相互垂直，谁也不帮谁的忙，各自的"劲"要按能量（平方）记账后再合账。矢量合成干的就是这件事：把 X、Y、Z 三个方向各人手一本的能量账，合拢成一个总账。方向信息（哪边劲大）在合账时被抹掉了，这正是后面"什么时候别用"的伏笔——想知道哪股劲作怪，还得回头翻三本分账。

## 二、物理本质：正交方向的能量相加

为什么是平方和开根号，而不是 $5+7+12=24$？因为三个方向是同一测点上相互正交的坐标分量，合成的是**矢量模长**——几何上就是勾股定理推广到三维。在读公式之前先把它要干的活说白：下一行公式回答的问题是**"三个方向的读数怎么合成一个数"**——其中 $A_x(f)$、$A_y(f)$、$A_z(f)$ 对应物理里同一测点三个相互垂直方向上同一根谱线的幅值，开根号前的平方和就是三向能量的总账，与上一节"三个弹簧秤合账"的比喻一一对应。

设三个方向的谱线幅值分别为 $A_x(f)$、$A_y(f)$、$A_z(f)$（单位 g），则逐谱线的合成值为

$$
\text{VectorSum}(f) = \sqrt{A_x^2(f) + A_y^2(f) + A_z^2(f)}
$$

下面这个等价写法回答的问题是**"谱线带相位时账怎么记"**——其中 $|X(f)|$ 等复数谱线的模对应物理里该方向该频率上的幅值大小，而相位（各方向振动的先后）在这里被刻意丢掉：合成只合能量、不合相位，方向与相位信息都不进总账。

对含相位的复数谱 $X(f)$、$Y(f)$、$Z(f)$，等价写法是

$$
\text{VectorSum}(f) = \sqrt{|X(f)|^2 + |Y(f)|^2 + |Z(f)|^2}
$$

其中 $|X(f)|$ 为复数谱线的模（幅值），单位与单方向谱一致（本例为 g）。能量层面，正交方向互不贡献，各自能量简单相加——这与分贝一篇里的能量叠加、谱总级的 RSS（Root Sum Square，平方和开根）求和是同一条物理。

![三向分量与合成矢量：左侧为几何示意，右侧为分量幅值与合成值对比](/images/vector-sum/triaxial-geometry.png)

*（图示：按 5 g / 7 g / 12 g 三向分量绘制，合成值 $\sqrt{5^2+7^2+12^2}=14.76$ g）*

对数值要有手感：合成结果由大分量主导，小分量是添头。还是 5/7/12 这组数，分步叠加看 dB：

```python
import numpy as np

# 悬置被动端一次升速测试的三个方向总级（RMS，单位 g）
X, Y, Z = 5.0, 7.0, 12.0

vs = np.sqrt(X**2 + Y**2 + Z**2)          # 矢量合成
print(f"矢量合成 = {vs:.2f} g")
for name, combo in [("仅 Z", (0, 0, Z)),
                    ("Z + X", (X, 0, Z)),
                    ("Z + Y", (0, Y, Z)),
                    ("X + Y + Z", (X, Y, Z))]:
    v = np.sqrt(sum(c**2 for c in combo))
    print(f"{name:8s}: {v:5.2f} g  (比仅 Z 高 {20*np.log10(v/Z):+.2f} dB)")
```

运行结果要点：12 g 的 Z 向已经是主导，再把 5 g 和 7 g 全加上，总量级也只从 12 涨到 14.76 g（+1.80 dB）；只加 X 一个方向更是只多 0.70 dB。合成值被大分量锁死，这正是它稳健的原因——换一个人装传感器、轴向偏了几度，总量级几乎不动。

| 分量组合 | 合成值 | 相对仅 Z |
| --- | --- | --- |
| **仅 Z = 12 g** | 12.00 g | 0 dB |
| <strong>Z + X（12, 5）</strong> | 13.00 g | +0.70 dB |
| <strong>Z + Y（12, 7）</strong> | 13.89 g | +1.27 dB |
| <strong>X + Y + Z（5, 7, 12）</strong> | 14.76 g | +1.80 dB |

逐谱线合成之后再对频段内谱线做 RSS，得到的总 RMS 与把矢量合成的物理贯彻到底一致——这也是 Simcenter 知识库对"谱的 RMS"的定义方式：对关注频段内所有谱线幅值（RMS 格式、线性单位）做平方和开根。

![谱总级（RMS of a spectrum）：对关注频段内全部谱线做平方和开根得到单一总级](/images/vector-sum/rms-spectrum-overall.png)

*（图源：网络官方公开资料）*

这个公式回答的问题是**"合成的谱曲线怎么再收成一个总级数字"**——其中 $A_i$ 对应物理里关注频段内第 $i$ 根谱线的幅值（RMS 格式、线性单位），求和号就是把每根谱线的能量逐笔入账，开根号回到幅值口径。它与上一节的逐谱线合成是同一条 RSS 物理在"谱线之间"的再次应用：先横着合（三向），再竖着合（频段内）。

$$
\text{RMS} = \sqrt{\sum_{i=0}^{k} A_i^2}
$$

其中 $A_i$ 为频段 $f_1 \sim f_2$ 内第 $i$ 条谱线的幅值（RMS 格式、线性单位，本例单位 g），$A_0$ 为首条计入谱线，$A_k$ 为末条。手册特别强调两点：谱线必须先回到线性单位（$\mathrm{Pa}^2$ 之类的功率单位要先开根），且计算一律用 RMS 幅值格式，与显示格式无关。

::: tip 什么时候用、什么时候别用
- 报告给非 NVH 背景的人看、多测点横向排序、人体振动评价 → 用矢量合成
- 诊断哪个方向有问题、ODS / 模态动画、传递路径分析 → 保留三向原始数据，合成会把方向信息抹掉
- 传感器轴向一致性没把握时 → 合成值反而是最稳的量（对轴向偏差不敏感）
:::

## 三、先 FFT 还是先合成？顺序做错结果就脏

公开技术资料评论区有个高频问题：计算顺序到底是先对时域数据做合成再 FFT，还是 FFT 之后再合成？Siemens 工程师的回答很明确：**先 FFT，再对频率函数做矢量合成**。VECTOR_SUM 本来就是挂在 Derived（导出通道）体系下的频域函数。

为什么顺序不能反？时域逐点取模是非线性运算。这个公式回答的问题是**"一个正弦信号取模（平方）之后会产生哪些新频率"**——其中 $A^2/2$ 对应物理里平方运算留下的直流分量（平均抬升），$2f_0$ 对应平方产生的二倍频分量：原始信号里根本没有它们，这正是"先取模后 FFT 会造出假线"的数学证据。

以单方向正弦 $x(t)=A\sin(2\pi f_0 t)$ 为例，取模前的平方运算满足

$$
x^2(t) = \frac{A^2}{2}\left[1 - \cos(2\pi \cdot 2f_0 \cdot t)\right]
$$

平方的结果里出现直流项 $A^2/2$ 和二倍频 $2f_0$ 分量——逐点求模再做 FFT，谱上会出现原始信号里不存在的频率成分。

```python
import numpy as np

fs, T = 1024, 1.0                          # 采样率 1024 Hz，时长 1 s
t = np.linspace(0, T, int(fs*T), endpoint=False)
# X 向 30 Hz 4 g，Z 向 80 Hz 3 g：不同方向、不同频率
acc = np.array([4.0*np.sin(2*np.pi*30*t),
                np.zeros_like(t),
                3.0*np.sin(2*np.pi*80*t)])
N = len(t)

# 正确路径：先各自 FFT，再逐谱线三向 RSS（频域矢量合成）
spec = np.abs(np.fft.rfft(acc, axis=1)) * 2 / N
vs_f = np.sqrt((spec**2).sum(axis=0))
print("频域合成 -> 30 Hz: {:.2f} g, 80 Hz: {:.2f} g, 其余最大线: {:.1e}"
      .format(vs_f[30], vs_f[80], np.max(np.delete(vs_f, [30, 80]))))

# 错误路径：先在时域合成模长，再 FFT
vs_t = np.sqrt((acc**2).sum(axis=0))
sp_t = np.abs(np.fft.rfft(vs_t)) * 2 / N
print(f"时域合成 -> 直流分量: {vs_t.mean():.2f} g")
for f in (30, 60, 80, 160):
    print(f"           {f:3d} Hz: {sp_t[f]:.2f} g")
```

运行结果要点：频域路径干净利落——30 Hz 一根 4.00 g、80 Hz 一根 3.00 g，其余谱线在 1e-14 量级（数值零）。时域路径则完全不可用：30 和 80 Hz 的真实谱线几乎消失，代之以 3.38 g 的直流、60 Hz 处 1.25 g 和 160 Hz 处 0.74 g 的**假线**（正弦平方产生二倍频和直流），一个没激励过的频段被凭空填满。

![两条计算路径的谱对比：上为先 FFT 后合成（正确），谱线只出现在 30/80 Hz；下为先取模后 FFT（错误），出现直流与 60/160 Hz 假线](/images/vector-sum/order-comparison-spectra.png)

*（图示：按文中 numpy 示例的输出数值绘制）*

| 对比项 | FFT 后合成（正确） | 时域取模后 FFT（错误） |
| --- | --- | --- |
| **谱线位置** | 真实激励频率（30 / 80 Hz） | 直流加二倍频假线（60 / 160 Hz） |
| **幅值** | 各方向原始幅值逐线保留 | 非线性畸变，单根谱线无物理含义 |
| **宽频段总能量** | 与时域一致（Parseval 定理保证） | 与频域一致 |
| **适用场合** | 一切谱、阶次、剖面分析 | 不应使用 |

值得注意的是最后一行：两条路径算出的全频段总 RMS 完全相等（本例都是 3.54 g）——能量没有丢，只是被搬去了错误的频率位置（Parseval 定理保证了时域与频域总能量一致）。所以如果只看总量级数字，时域合成看起来也对，这恰恰是它危险的地方：报表对得上，谱一细看全是假线。

::: warning 顺序要求
矢量合成的位置在 FFT 之后。对时域数据逐点取模再做谱分析，能量守恒但频率错位：真实谱线塌掉、直流和二倍频假线立起来。Testlab 把 VECTOR_SUM 放在 Derived 频率函数体系里，就是从软件层面固定了这个顺序。
:::

## 四、在 Simcenter Testlab 里怎么设

经典界面（Signature）和新一代界面（Neo）各有一条路，设置入口不同，公式内核一样。

### Signature：Derived 标签里的 VECTOR_SUM

两条时机都能算。测量中实时看：Signature 的 **Online Processing** 工作表，右上角切到 **Derived** 标签。事后补算：**Time Data Processing** 工作表，Channel Processing 区点 **Change Settings**，选 **Derived FS** 标签（这个工作表需要先开 Signature Throughput processing 插件：Tools 菜单的 Add-ins）。

在 Derived 标签里选中 Formula 列首个单元格，点上方的 <strong>F(x)</strong> 按钮，在 Select Function 菜单底部找 VECTOR_SUM——第一次用可能得点一下 New function，让菜单出现三个输入位。函数参数填三向的通道引用，两种写法都行：通道号 CH1 加 CH2 加 CH3，或者测点名加方向写全三向（通道号在 Channel Processing Settings 右上角下拉里可查）。设好后，该三向测点的所有频率函数——谱、自功率谱、阶次、频率剖面——都会自动多出一条合成曲线。

### Neo：Process Designer 里的 Block Calculate

在 Process Designer 里用 **Block Calculate** 方法。例如 Order Sections 先算出 18 阶，X、Y、Z 三向的输出分别是 R1、R2、R3，Block Calculate 的 F1 公式写 vectorsum 括号里放 R1、R2、R3（分号分隔）即可。上游接阶次就得阶次的合成，接谱就得谱的合成，流程搭好后批量处理吞吐数据很顺手。

| | Signature（经典） | Neo（Process Designer） |
| --- | --- | --- |
| **入口** | Online Processing 或 Time Data Processing 的 Derived 标签 | Block Calculate 方法 |
| **函数** | F(x) 菜单选 VECTOR_SUM | 公式 vectorsum 接 R1 R2 R3 |
| **通道引用** | 通道号 CH1 或测点名加方向 | 上游方法的输出编号 |
| **生效对象** | 该测点全部频率函数（谱、自功率、阶次、剖面） | 只算流程里接进来的函数 |
| **时机** | 测量中实时加事后吞吐 | 离线流程 |

::: tip 设置建议
- 现场要看实时趋势 → Online Processing 里就设好，测量中直接看合成曲线
- 数据已经采完 → Time Data Processing 补算，别为一条合成曲线重测
- Neo 里想把合成结果出成瀑布图 → 把 Block Calculate 放在 Order Sections 或谱方法之后，对瀑布数据逐帧合成
:::

## 五、小结

矢量合成的使用边界，三条判断标准：

- **看总量、排序、汇报 → 用**：与方向无关、对轴向偏差稳健，六个方向收成两条线（左右悬置各一条），图表立刻可读
- **查方向、做动画 → 不用**：合成抹掉方向信息，ODS、模态、TPA 一律回三向原始数据
- **顺序只有一个 → FFT 在前**：合成作用在频率函数上；时域取模会造出直流和二倍频假线，虽然总能量分毫不差，谱却已经不能用了

一个数收拢三个方向，换来的是可读性，代价是方向信息——什么时候肯付这个代价，取决于你是要向别人汇报，还是要向数据追问。

## 一句话记住

三个垂直方向各记各的能量账，矢量合成就是平方和开根号把账合拢——大分量说了算、轴向偏差不动摇；合账只合能量不合相位，所以查方向做动画别用它；顺序上永远先 FFT 后合成，时域取模会造出直流与二倍频假线。
