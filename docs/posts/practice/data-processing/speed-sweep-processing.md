# 转速扫掠处理：RPM增量、帧长与扫掠率的耦合

> 同一台设备、同一段升速数据，两位工程师处理出的阶次切线一条平滑一条带着锯齿状缺口——差的不是数据，是处理参数。扫掠工况下做谱分析，RPM 增量、帧长（Framesize）、扫掠率（Sweep Rate）三个量咬合在一起，共同决定了一个界面上看不到的量：重叠率（Overlap）。本文用 Simcenter 官方知识库的三组对照案例，把同一组设置在三档扫掠速度下分别产生 50% 重叠、出现数据空洞、75% 重叠的机制讲透，并给出参数选择的工程判据。

## 一、为什么同一组数据能处理出不同的结果

升速试验（runup）结束后拿到的是一段时域记录：转速从某个值连续爬到另一个值，振动与声学通道跟着一路变化。要在频域看它，软件的做法不是"对整段数据做一次 FFT"，而是**每隔一个 RPM 增量做一次谱分析**，把每个转速点上算出的频谱沿 RPM 轴摞起来，得到瀑布图（waterfall）或彩色图谱（colormap）。

问题就出在"每隔一个 RPM 增量"上。做一次 FFT 需要截取一段时域数据——帧长 2 秒就得用 2 秒的数据；而转速是爬升的，2 秒之内 RPM 已经走过了一段距离。于是三个量被绑在了一起：

- **RPM 增量（RPM Increment）**：每间隔多少转速做一次谱分析。增量 150 rpm，就是每升 150 rpm 出一条谱——这是处理设置，用户可调；
- **帧长（Framesize）**：每次 FFT 用多长的时域数据，频率分辨率是帧长的倒数——这也是处理设置，用户可调；
- **扫掠率（Sweep Rate）**：转速每秒变化多少 rpm——这不是设置，是**数据自身的属性**，由被测对象和试验控制方式决定。

三者相除，就得到一个用户不能直接设置、却直接决定结果质量的量：**重叠率**。Simcenter Testlab 的界面里没有 Overlap 这个输入框，原因正在于此——它由前三个量自动决定。

先看一个具体数字感受耦合的紧密：RPM 增量 150 rpm、帧长 2 秒、扫掠率 150 rpm/s 时，每条谱要用 2 秒数据，而相邻两条谱的转速间隔只花 1 秒就走完了——第二帧和第一帧有一半的数据是重复使用的，重叠率 50%。把扫掠率放慢到 37.5 rpm/s，走完 150 rpm 要 4 秒，2 秒的帧只够覆盖一半，另一半时间的数据**没人处理**——出现空洞。这三档情形正是第三节的三组对照案例。

## 二、三个参数各自的物理角色

::: info 核心概念
- **RPM 增量（RPM Increment）**：相邻两次谱分析之间的转速间隔，决定 RPM 轴上的"采样密度"
- **帧长（Framesize）**：单次 FFT 所用时域数据的长度；频率分辨率 = 1/帧长，帧以该 RPM 增量点为中心取数
- **扫掠率（Sweep Rate）**：转速随时间的变化率（rpm/s），数据的固有属性，不可在软件中设置
- **重叠率（Overlap）**：相邻帧重复使用的数据比例，由增量、帧长、扫掠率共同决定，不可直接设置
:::

把三者的关系写成一个式子之前，先用文字说清楚因果链：帧长决定"每条谱吃多长的数据"，增量与扫掠率共同决定"相邻两条谱的起点在时间上隔多远"——时间步距等于增量除以扫掠率。帧长比时间步距长，帧与帧搭接，产生重叠；短，帧与帧脱开，产生空洞。

这个公式回答的问题是：给定处理设置和扫掠率，相邻两帧到底重复（或漏掉）了多少数据？其中分母一项（RPM 增量除以扫掠率）对应物理里相邻两帧起点的时间步距，公式里的 $T$ 是帧长，比值再被 1 减，就得到重复数据占整帧的比例：

$$
\text{Overlap} = 1 - \frac{\Delta \text{RPM} / SR}{T}
$$

代入第一节的数字验证：增量 150 rpm、扫掠率 150 rpm/s、帧长 2 s，时间步距 1 s，重叠率 $1-1/2=50\%$；扫掠率放慢到 37.5 rpm/s，步距变 4 s，$1-4/2=-1$——负值即帧间脱开 2 秒，数据有空洞；加快到 300 rpm/s，步距 0.5 s，$1-0.5/2=75\%$。三个场景一盘账，与知识库的图完全一致。

需要重叠的另一半理由来自窗函数。谱分析通常加汉宁窗（Hanning window），窗函数把每帧数据的首尾乘到接近零——首尾的信息实际被丢弃了。有了重叠，上一帧被窗函数压掉的数据，在下一帧里位于帧的中部、以完整权重参与计算。重叠不只是"加密采样"，更是**窗函数丢数据的补救机制**。

### 情形一：中速扫掠，50% 重叠

扫掠率 150 rpm/s。第一帧以 1500 rpm 为中心取 2 秒数据，第二帧以 1650 rpm 为中心，第三帧 1800 rpm，直到 3000 rpm。全程 (3000-1500)/150+1 = 11 条谱。相邻帧起点相隔 1 秒、帧长 2 秒，每条谱与下一条重复使用一半数据——重叠率恰好 50%，处理结果完整覆盖整段时间记录。

![中速扫掠（150 rpm/s）：上图转速-时间曲线，下图处理帧的排布，相邻帧 50% 重叠](/images/speed-sweep-processing/fig3.png)

*(图源：Siemens Simcenter Testing Knowledge Base)*

### 情形二：慢速扫掠，出现数据空洞

扫掠率放慢到 37.5 rpm/s。处理设置不变，仍然每 150 rpm 出一条谱。此时走完 150 rpm 需要 4 秒，2 秒的帧只覆盖其中一半——**每两个相邻帧之间有 2 秒的数据从未进入任何一次 FFT**。如果共振、敲缸这类关键事件恰好发生在空洞里，处理结果里就找不到它。

### 情形三：快速扫掠，75% 重叠

扫掠率加快到 300 rpm/s。相邻 150 rpm 增量只需 0.5 秒走完，2 秒的帧与下一帧重复使用 75% 的数据。数据质量没有问题——更多重叠不会引入错误，但计算量与结果数据体积显著增加，而信息增益有限。工程上 50% 到 75% 是常见区间，超过之后边际收益快速衰减。

## 四、参数怎么选：一条设计链

三个案例盘完，选择顺序自然浮出：

1. **帧长由频率需求定死**：分辨率 0.5 Hz 就要 2 秒帧长，没有商量余地——这是频域分析的本钱；
2. **RPM 增量由 RPM 轴密度需求定**：要看共振峰值随转速的移动，增量必须小于共振在 RPM 轴上的宽度；
3. **扫掠率是试验设计变量**：上述两者定了之后，若预估重叠率过低甚至为负，要么放慢扫掠、要么缩短帧长（牺牲分辨率）、要么加密增量——三个旋钮里总得拧一个。

反过来，重叠率过高（大于 75%）时应主动放宽：计算时间与存储都在为重复信息买单。

::: warning 工程注意
- 扫掠率不可后期修改：它是数据采集时的事实，处理阶段只能适配它
- 慢扫掠 + 大帧长 + 稀增量是空洞的高发组合，处理前先按公式心算一遍重叠率
- 报告瀑布图/阶次切线时注明增量与帧长设置，不同设置的结果没有直接可比性
:::

## 五、Python 演示：三档扫掠率下的帧排布

用 numpy 按知识库的规则（增量 150 rpm、帧长 2 s、帧中心对齐增量点）排帧，统计三档扫掠率下的重叠率与未覆盖比例，对照第二节的公式：

```python
import numpy as np

rpm_min, rpm_max, inc, T = 1500, 3000, 150, 2.0
for sr in [150, 37.5, 300]:                    # 三档扫掠率 rpm/s
    centers = np.arange(rpm_min, rpm_max + 1, inc)   # 各帧中心的 RPM
    t0 = (centers - rpm_min) / sr               # 各帧中心时刻 s
    starts, ends = t0 - T/2, t0 + T/2           # 帧起止时刻
    steps = np.diff(starts)                     # 相邻帧起点间隔
    overlap = 1 - steps[0] / T                  # 重叠率（各帧相同）
    lo, hi = max(starts[0], 0.0), ends[-1]       # 只统计被处理覆盖的时间窗
    n = int(round((hi - lo) * 10)) + 1           # 0.1 s 网格
    covered = np.zeros(n)
    for s, e in zip(starts, ends):
        a, b = max(int(round(s*10)), 0), min(int(round(e*10)), n-1)
        if b >= a:
            covered[a:b+1] = 1
    gap = 1 - covered.mean()                     # 帧间空洞占比
    print(f"SR={sr:6.1f} rpm/s  frames={len(centers):2d}"
          f"  overlap={overlap:5.0%}  uncovered={gap:5.1%}")
```

运行输出：150 rpm/s 时 11 帧、重叠率 50%、未覆盖 0；37.5 rpm/s 时 11 帧、重叠率为负（帧间脱开）、处理窗内约 46% 的时间无人处理——即每 4 秒里有 2 秒落在帧外；300 rpm/s 时 11 帧、重叠率 75%、未覆盖 0。重叠率三档 50% / 负值 / 75% 与知识库三组案例的图完全一致，公式与图形互相印证。

## 六、Testlab 操作锚点

- **Throughput Processing 的 Tracking and Triggering 页签**：勾选 speed sweep 分析，设 Min rpm、Max rpm、Increment——情形一的 1500/3000/150 即在此处；
- **FS Acquisition 页签**：频率分辨率与帧长联动设置，0.5 Hz 对应 2 s；
- **在线采集**：Simcenter Testlab Signature 中同一套参数在采集端设置，逻辑与离线处理一致；
- **重叠率无输入框**：它是三个设置与数据扫掠率的导出量，想知道当前值，按第二节公式心算即可。

## 七、小结

扫掠数据的谱处理质量取决于一个界面上看不到的量：重叠率 = 1 - (RPM 增量 / 扫掠率) / 帧长。增量与帧长是处理设置，扫掠率是数据固有属性；三者失配时，快扫掠浪费算力（重叠 75% 以上边际收益趋零），慢扫掠产生数据空洞（关键事件落在帧间直接丢失）。选参链条：帧长定分辨率、增量定 RPM 轴密度、扫掠率做最后平衡；处理任何扫掠数据前，先按公式把重叠率心算一遍。

## 一句话记住

扫掠谱分析里帧长吃时间、增量定步距、扫掠率是先天事实，三者相除即重叠率——大于零才有重叠护住窗函数削掉的数据，为负就是空洞；50% 到 75% 是工程甜点区。
