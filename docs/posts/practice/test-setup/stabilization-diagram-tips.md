# 稳定图进阶技巧：极点选择的工程判断

> 稳定图上明明有一列笔直的字母，FRF 叠加曲线上却找不到对应的峰——这列字母是选还是不选？反过来，谱峰清晰的位置字母却稀稀拉拉，又该怎么办？稳定图入门篇讲的是"找竖直光柱"，真实试验里光柱常常不给面子：局部模态被整体求和稀释、激振器方向不对付、移动加速度计带来的质量漂移，都会让稳定图"长歪"。本文把 Simcenter 官方知识库的进阶技巧展开：分部件过滤重建 FRF 和、激振方向与模态振型的对齐关系、多次搬传感器造成的频率漂移与 multi-run 对策，每一条都对应一种"稳定图不清"的具体病因。

## 一、为什么光柱会失灵：三种典型现场

先看三个来自试验现场的常见场面。

场面一：一台完整车身在台架上做整车模态。稳定图在 38 Hz 附近有一列整齐的字母，但叠加的 FRF 求和曲线在该处平坦无峰。选，怕是计算模态；不选，怕漏掉一阶真实模态——这列字母的来历，需要一条独立的证据链。

场面二：同一根车架，换了一个方向的激振器再测一次。第一次的稳定图里某阶模态位置字母散乱，第二次却出现清晰光柱。结构没变、测点没变，变的只有激励方向——这说明稳定图的清晰程度不仅取决于结构，还取决于激励能不能"喂得进"那阶模态。

场面三：测点 60 个，加速度计只有 20 个，分三轮搬点测完。稳定图上每阶模态位置不再是一列字母，而是一簇字母——同一阶模态"散"成了三四个略有差异的极点。这不是噪声，是试验方法本身引入的系统性问题。

这三个场面分别对应官方知识库总结的三类病因：**局部模态与整体模态混叠**、**激振方向与振型不对齐**、**搬移加速度计的质量漂移**。下面逐一拆解，先从稳定图本身的工作方式说起。

## 二、稳定图在做什么：软件如何"猜"模态

稳定图（Stabilization Diagram）是模态曲线拟合过程的可视化向导。Simcenter Testlab 的拟合器并不知道结构里到底有几阶模态——它从假设 1 阶模态开始，逐步增加假设的模态数，每增加一次就重新拟合一次，把每次得到的极点（频率、阻尼）画到同一频率轴上。当相邻两次假设给出的同一阶模态的频率与阻尼都在很紧的容差之内重复出现，软件就用字母"s"（stable，稳定）标记；"o"则表示这次出现的是上一步没有的新解。

理想情况下，物理模态连成一列"s"，与 FRF 求和曲线的峰对齐——这是"结构里确有这阶模态"的强指示。只需从一列"s"里选一个，因为整列代表的是同一个可重复的解。

![稳定图基本形态：一列 s 字母对准 FRF 求和的峰](/images/stabilization-diagram-tips/fig1.png)

*(图源：Siemens Simcenter Testing Knowledge Base)*

两点入门篇之外的操作细节值得强调。第一，叠加在稳定图上的测量函数只是**视觉辅助**：可以是单条 FRF 求和，也可以叠加全部个体 FRF，但参与字母计算的永远是全部 FRF 数据，求和曲线只帮助解读字母、不参与拟合。第二，Testlab 计算的 FRF 求和是"归一化"的——除以求和所用的 FRF 条数。这不是无关紧要的细节：不同部件的 FRF 条数可能相差一个数量级，不除条数的话，各部件求和曲线的幅值根本不在同一尺度上，没法叠加比较（后文第四节正是靠这一点）。

![叠加求和与叠加全部个体 FRF 两种视图](/images/stabilization-diagram-tips/fig3.png)

*(图源：Siemens Simcenter Testing Knowledge Base)*

但真实试验里，"强光柱 + 清晰峰"的组合并不总出现。接下来的三节各讲一种病因与对策。

## 三、病因一：局部模态被"平均掉"——用部件过滤重建证据

### 现象与机理

结构带小部件时，稳定图会出现"有字母列、无谱峰"的错位。原因在于**全局模态与局部模态的分工**：车架车身这类全局结构参与的模态，几乎每一条 FRF 里都有表现；而某个小部件（转向系统、排气吊钩、子框架）的局部模态，只在布置在该部件上及其附近的少数测点的 FRF 里才看得到。

FRF 求和把所有测点一锅烩：全局模态的贡献条条都在、越加越强，局部模态的贡献只有零星几条、一平均就被洗掉。官方原文的说法是全局模态把局部模态"wash out"（洗掉）了。于是局部模态在字母列上站得住（它毕竟是真实极点，拟合器找得到），在求和曲线上却不成峰——字母与峰的证据链断了。

![带多个子部件的试验结构](/images/stabilization-diagram-tips/fig5.png)

*(图源：Siemens Simcenter Testing Knowledge Base)*

全局弯曲模态几乎每条 FRF 都有贡献，转向盘横向局部模态只在少数测点可见——两类模态在"多少条 FRF 里有表现"上截然不同。

![全局弯曲模态与转向盘局部模态对比](/images/stabilization-diagram-tips/fig6.png)

*(图源：Siemens Simcenter Testing Knowledge Base)*

### 对策：按部件过滤再求和

Testlab 的 Modal Analysis 工作表里，"Modal Data Selection"页有一个 **Point filter**（测点过滤器）字段：

- 留空 = 全部 FRF（例如 375 条）都参与显示与分析；
- 填入部件名或名称片段 = 只选该部件的 FRF，例如填 "eng" 选中发动机相关 18 条、填 "whel" 选中转向轮相关 15 条。

![Point filter 按部件名过滤 FRF](/images/stabilization-diagram-tips/fig7.png)

*(图源：Siemens Simcenter Testing Knowledge Base)*

过滤后切换到 Polymax 拟合页，按 **Save Sum/MIF** 把该部件的 FRF 求和存成一个命名函数；再回到稳定图显示，点顶部 **Data Explorer** 图标，从 Polymax Band 文件夹把存好的求和函数拖进稳定图显示区叠加。

![Save Sum/MIF 保存部件 FRF 求和](/images/stabilization-diagram-tips/fig8.png)

*(图源：Siemens Simcenter Testing Knowledge Base)*

![Data Explorer 把求和拖到稳定图上](/images/stabilization-diagram-tips/fig9.png)

*(图源：Siemens Simcenter Testing Knowledge Base)*

官方案例的效果：全部 375 条 FRF 的总求和（蓝色）与转向盘部件求和（红色）在 38 Hz 都没有峰，而发动机部件求和（绿色）在该处出现明确峰值——这列字母对应的很可能是发动机的局部模态，选它的信心立刻不同。

![发动机部件求和出现总求和看不到的峰](/images/stabilization-diagram-tips/fig10.png)

*(图源：Siemens Simcenter Testing Knowledge Base)*

这里能看出"归一化求和"设计的用意：各部件求和都除以自身条数，绿红蓝三条曲线才能同尺度叠在一张图上比高低。

::: info 核心概念
- **全局模态（Global Mode）**：结构主体参与的模态，几乎在每条 FRF 中都有贡献，求和曲线上成峰
- **局部模态（Local Mode）**：仅子部件参与的模态，只在少数测点的 FRF 中可见，整结构求和会被全局模态"洗掉"
- **Point filter（测点过滤器）**：Testlab Modal Data Selection 中按测点名过滤 FRF 子集的字段，按部件重建求和曲线的证据工具
:::

## 四、病因二：激振方向与振型不对齐——模态"喂不进去"

每阶模态的主运动方向各不相同：有的以左右摆动为主（扭转），有的以垂向运动为主。激励力若与模态振型的主方向不对齐，该阶模态就激励不充分，FRF 数据里它的贡献偏弱，稳定图上字母自然稀疏。

![扭转模态与垂向模态的主运动方向](/images/stabilization-diagram-tips/fig11.png)

*(图源：Siemens Simcenter Testing Knowledge Base)*

官方案例的对照很有说服力：同一结构，只用一个方向的参考激振器时，某阶模态位置没有清晰的"s"列；引入第二个激振器、且其方向与该阶振型方向一致后，同一位置出现强光柱。

![单激振器与双激振器稳定图对比](/images/stabilization-diagram-tips/fig12.png)

*(图源：Siemens Simcenter Testing Knowledge Base)*

要理解"方向对齐"为什么如此关键，可以从留数的构成看。单点激励下第 $k$ 阶模态在某测点的 FRF 留数与振型系数的关系是

$$A_{ijk} \propto \psi_{ik}\,\psi_{jk}$$

即响应点振型系数与**激励点振型系数的乘积**。留数正比于两个振型系数的乘积：激励方向在振型上的投影 $\psi_{jk}$ 直接缩放整阶模态在全部 FRF 中的幅值——投影为零（力打在节点上或垂直于主振方向），整阶模态从数据里消失，字母自然亮不起来。

工程对策：试验前对振型方向有预判（有限元模型、上一轮试验、类似结构经验），布置**多台不同朝向的激振器**。MIMO（多输入多输出）测试的冗余参考点能覆盖各阶模态的主方向，还能借模态参与因子解耦密集模态——这也是为什么整车级模态试验几乎都是 MIMO 配置。

::: tip 试验设计
激振器方向布置原则：至少覆盖结构的三个主运动方向（垂向、横向、纵向/扭转），每个方向上的激振点避开该方向主要模态的节点。稳定图上"某阶模态字母弱"，先检查激励方向与该阶振型的对齐关系，再怀疑结构本身。
:::

## 五、病因三：搬移加速度计的质量漂移——multi-run 对策

### 问题：60 个测点、20 个传感器

测点多于传感器时，只能分批搬点。每次搬动，加速度计（及其安装座、线缆）从结构的一些位置移到另一些位置，结构的质量分布随之小幅改变。固有频率与 $\sqrt{k/m}$ 成比例，质量分布变了，各阶模态的频率在每批数据之间略有不同。

这个漂移常被忽略——"传感器质量相对结构总质量可忽略"。对整车总质量而言确实如此，但对**动态模态**不成立：许多模态是局部的，只有结构总质量的一小部分参与。一枚传感器恰好放在某阶局部模态的"呼吸中心"（如面板呼吸模态的中心），对该阶频率的影响可以很大。

于是稳定图上，每阶模态不再是一列字母，而是一**簇**字母——同一阶模态在几批数据里频率略有差异，各自成列。

![搬点测试的稳定图：字母成簇](/images/stabilization-diagram-tips/fig14.png)

*(图源：Siemens Simcenter Testing Knowledge Base)*

作为对照，若所有 FRF 一次同时测得（无搬点），每阶模态就是干净的一列。

![一次测完的稳定图：字母成列](/images/stabilization-diagram-tips/fig15.png)

*(图源：Siemens Simcenter Testing Knowledge Base)*

### 对策：Multi-Run Modal

已经测完的数据无法事后"拉齐"——频率不一致已固化在 FRF 里。Testlab 的对策是 **multi-run modal**：每一批（每一次搬点）的 FRF **分别**曲线拟合，避免不同批次频率不一致的数据互相污染；然后把各批得到的**部分振型**拼合成一条完整振型，频率取自用户指定的某一批分析结果。

![multi-run 分别拟合再拼合振型](/images/stabilization-diagram-tips/fig16.png)

*(图源：Siemens Simcenter Testing Knowledge Base)*

这个思路的本质：与其让拟合器在"同一阶模态、三套频率"的矛盾数据里强行折中（结果就是字母成簇、阻尼虚高），不如承认每批数据内部自洽、各自拟合，最后只在振型层面拼接。振型是相对量，拼接不引入频率折中问题。

一个实用推论：预算允许时，一次性布够传感器（或分批但每批保留一组公共参考点做衔接）优于事后 multi-run 补救。相关操作细节见官方知识库 "Simcenter Testlab: Multi-Run Modal" 专题。

::: warning 工程注意
簇状字母列不等于噪声大。看到字母成簇，先问试验流程：是否搬过传感器？若每批数据独立拟合时同一阶模态频率整齐，即可确认是质量漂移而非结构问题。把簇当成"阻尼大"的信号去拟合，会得到虚高的阻尼估计。
:::

## 六、numpy 演示：质量漂移如何把一列字母拆成一簇

用最小数值例子复现病因三。两自由度系统，第二自由度代表"局部模态"；在其上附加一枚"加速度计"质量（取主质量的 2%），观察模态频率的移动量。

无阻尼两自由度特征值问题 $\left(\mathbf{K} - \omega^2 \mathbf{M}\right)\boldsymbol{\phi} = \mathbf{0}$，这个方程回答的问题是：给定质量与刚度分布，结构在哪些频率上"自己跟自己共振"？其中 $\mathbf{M}$ 对应物理里的质量分布（含传感器附加质量），$\mathbf{K}$ 是刚度分布。

```python
import numpy as np

# 两自由度系统：m2 为"局部结构"，加速度计装在 m2 上
m1, m2 = 1.0, 0.05                 # 主结构 1 kg，局部结构 50 g
k1, k2, k3 = 4000., 200., 1000.    # 接地刚度与耦合刚度（N/m）
K = np.array([[k1+k3, -k3], [-k3, k2+k3]])

def modes(m2_val):
    M = np.diag([m1, m2_val])
    w2 = np.abs(np.linalg.eigvalsh(np.linalg.solve(M, K)))
    return np.sqrt(w2)/2/np.pi     # 固有频率（Hz）

f0 = modes(m2)                     # 不装传感器
f1 = modes(m2 + 0.001)             # m2 上加 1 g 传感器

print("无传感器: %7.3f Hz %7.3f Hz" % tuple(f0))
print("装传感器: %7.3f Hz %7.3f Hz" % tuple(f1))
print("漂移量  : %7.3f Hz %7.3f Hz" % (f1[0]-f0[0], f1[1]-f0[1]))
print("传感器/局部质量比: %.1f%%" % (100*0.001/m2))
```

实测输出（参数如上）：

```text
无传感器:  13.913 Hz  30.465 Hz
装传感器:  13.711 Hz  30.177 Hz
漂移量  :  -0.202 Hz  -0.288 Hz
传感器/局部质量比: 2.0%
```

1 g 传感器只占局部结构质量的 2%，就把两阶模态频率分别拉低 0.20 Hz 与 0.29 Hz——按稳定图 2% 频率稳定判据（30 Hz 处即 0.6 Hz），搬点批次间这一量级的漂移足以让字母从一列散成一簇。低阶模态以整体运动为主、漂移较小，高阶模态运动集中在传感器安装点附近、漂移更大；实际试验中传感器连同安装座占局部结构质量的比例往往更高（小型支架、薄板件上可达 5% 以上），漂移更显著——这正是 multi-run 存在的理由。

## 七、Testlab 操作锚点汇总

| 问题 | 操作位置 | 动作 |
| --- | --- | --- |
| 局部模态证据不足 | Modal Analysis → Modal Data Selection → **Point filter** | 填部件名过滤 FRF 子集 |
| 重建部件求和曲线 | Polymax 工作表 → **Save Sum/MIF** | 保存命名求和函数 |
| 叠加到稳定图 | 顶部 **Data Explorer** 图标 | 从 Polymax Band 文件夹拖入显示区 |
| 激励方向不对齐 | 试验设计阶段 | 多激振器、多朝向布置（MIMO） |
| 搬点频率漂移 | Modal Analysis → **Multi-Run Modal** | 分批拟合、振型拼接、频率取自指定批次 |

## 八、小结

稳定图的"光柱 + 峰"是理想形态，三种常见病因各有各的解法：局部模态被求和稀释，用 Point filter 按部件重建求和曲线找证据；激振方向与振型不对齐，用多方向 MIMO 配置把模态"喂进去"；搬点造成质量漂移，用 multi-run 分批拟合拼振型。判断顺序建议：先看字母形态（列还是簇），再查试验流程（单次还是搬点），最后动用过滤与重建工具。字母列的来历查清楚了，极点选择才谈得上工程判断而不是碰运气。

## 一句话记住

稳定图上光柱不成形，先查三件事：字母有列无峰查部件（局部模态被洗掉，Point filter 重建求和）；字母稀疏松散查激振方向（留数正比激励点振型投影，MIMO 多朝向补齐）；字母成簇查搬点（传感器质量移动频率，multi-run 分批拟合再拼振型）。
