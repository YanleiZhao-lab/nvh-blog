# 锤击测试实操：力窗、指数窗与双击处理

> 锤击法测 FRF（频响函数）入门容易、测好难：同一把锤子、同一个结构，窗没设对，相干掉一半、阻尼虚高六成。这篇按 Testlab Impact Testing 的实际工作流走一遍：触发、带宽、力窗、指数窗、双击剔除，每一步讲清背后的物理，以及数字到底会怎么错。

## 一、锤击测 FRF：一次敲击同时拿到输入和输出

锤击测试（Impact Testing）的最小配置只要两个通道：力锤敲一下，锤头的压电传感器给出输入力，结构上的加速度计给出输出响应，两者一除就是 FRF。相比激振器，它不用夹具、不用信号源，拎着锤子就能在车间、在整车旁边干，是动力总成悬置支架、车身接附点、副车架模态排查的首选方式。

![锤击测试的最小设备配置：SCADAS 前端 + 力锤 + 加速度计](/images/impact-testing-windows/equip.png)

*（图源：Simcenter Testing Knowledge Base）*

理想很美好，但一次敲击要同时当激励信号和被分析信号用，两头的毛病它都得沾：

- **力信号**：真正的脉冲只占几毫秒，其余全是仪器噪声。噪声没削掉，FRF 分母被抬高，算出来的幅值偏低。
- **响应信号**：小阻尼结构的响应在记录时间内没衰减完，FFT 默认把信号周期化延拓，首尾对不上就是泄漏（Leakage），峰被拉宽、幅值被压低。

力窗和指数窗就是分别对付这两头的。在 Testlab 里它们藏在 Impact Setup 的 Windowing 子表里，配错不报错、只出坏数据，所以值得把原理拆开看。

![Windowing 子表：用一锤实测数据自动推荐窗设置](/images/impact-testing-windows/window-worksheet.png)

*（图源：Simcenter Testing Knowledge Base）*

## 二、敲之前的两件事：触发与带宽

### 触发：别让脉冲前沿被切掉

锤击是单次事件，必须靠触发（Trigger）来抓。Testlab 的做法很省事：Start Scope 后在结构上试敲几下，软件根据实际力信号幅度画一条触发电平线，按 Apply Suggested 即可。同时会自动配一小段预触发（Pre-trigger），把记录起点往前挪，保证脉冲上升沿完整入镜。

预触发给少了，脉冲前沿被切，力谱从源头上就错了，后面窗加得再讲究也救不回来。用自动推荐值，别手贱往下调。

![Trigger 子表：试敲几下，Apply Suggested 自动给出触发电平](/images/impact-testing-windows/trigger.png)

*（图源：Simcenter Testing Knowledge Base）*

### 带宽：先看力谱平不平，再谈锤头

好的输入要求力谱在关心频段内平坦且高出仪器噪声地板。判定标准各公司略有出入：力谱滚落不超过 3~10 dB 算合格。注意频谱顶部 20% 的滚降是 SCADAS 抗混叠滤波器干的，属于正常现象，不是锤头的问题。

如果力谱没铺满分析带宽就掉下去，换锤头。物理逻辑是时域与频域的反比关系：脉冲越短，频谱越宽。锤头从两个方向缩短接触时间：**减质量**（锤头越轻，反弹越干脆）和**增刚度**（橡胶换塑料、塑料换金属）。

![不同刚度与质量的锤头和配重延伸件](/images/impact-testing-windows/tips-selection.png)

*（图源：Simcenter Testing Knowledge Base）*

| 锤头类型 | 接触时间 | 激励频带 | 典型场景 |
| --- | --- | --- | --- |
| **软橡胶** | 长 | 低频段（掉落早） | 车身/整车低阶整体模态 |
| **塑料/尼龙** | 中 | 中频段 | 支架、副车架常用起点 |
| **金属** | 短 | 高频段 | 小部件、高频结构模态 |

锤头太软的直接症状：高频段力谱先塌，FRF 高频部分跟着变成噪声地毯，相干同步掉下去，三线图一起看，一眼定位。

![锤头太软：蓝线力谱高频跌落，红线 FRF 高频全是噪声，绿线相干塌陷](/images/impact-testing-windows/tip-too-soft.png)

*（图源：Simcenter Testing Knowledge Base）*

::: warning 带宽判定顺序
先确认力谱平坦，再去解释 FRF 的高频噪声。力谱不平就换锤头，加平均次数只能把噪声抹平，救不了信噪比本身。
:::

## 三、力窗：把脉冲之外的噪声清零

力窗（Force Window）专治输入通道的杂散噪声。定义非常朴素：**脉冲作用期间取 1，其余时间取 0**，本质是矩形窗的变体，只是取 1 的区间只罩住脉冲那几毫秒。

物理意义拆开看：力信号在脉冲结束后理论上就是零，剩下的都是测量链噪声。加力窗相当于声明脉冲之外的力信号无效，分母里的噪声被清掉，FRF 幅值回归真实水平。脉冲本身在窗内原封不动，不引入畸变，也不附加人工阻尼。

Testlab 里力窗和指数窗成对出现（Force + Exponential），cutoff 参数控制取 1 区间的宽度。锤子敲得干脆、触发和预触发设置得当，力窗可以开得很窄；靠力窗去遮掩一次毛糙的双击敲击，是本末倒置。

## 四、指数窗：给没衰减完的响应补一刀

### 从泄漏说起

FFT 假设记录帧无限周期延拓。锤击响应若在记录时间内完全衰减到零，帧首尾都是零，延拓无缝衔接，理论上加矩形窗就行，这也是 DSP 手册把完全衰减的冲击列为矩形窗适用场景的原因。

麻烦的是小阻尼结构。30 Hz、阻尼比 1% 的模态，时间常数约 5.3 秒，记录窗 2 秒时包络才衰到 68%，帧尾远不是零，泄漏不可避免。指数窗（Exponential Window）就是强行把尾巴按到零：窗函数从 1 开始按指数衰减，保证加窗后的信号在帧尾归零，杜绝泄漏。

### 指数窗的百分比定义

Testlab 用终点衰减百分比描述指数窗，窗函数写作 $w(t) = e^{-\beta t}$，衰减率由终点百分比 $p$ 和记录时长 $T$ 反解：

$$\beta = \frac{\ln(100/p)}{T}$$

**100% 窗终点值仍为 1，等价于不加窗**；50% 窗把帧尾信号压到一半；10% 窗压到十分之一。

![不同百分比的指数窗：100% 即矩形，百分比越小压得越狠](/images/impact-testing-windows/exponential-window.png)

*（图源：Simcenter Testing Knowledge Base）*

### 人工阻尼：每按一下窗，阻尼就被多报一点

指数窗的代价要从自由衰减的包络推导。小阻尼系统的响应包络是 $e^{-\zeta\omega_n t}$，乘上指数窗后：

$$e^{-\zeta\omega_n t} \cdot e^{-\beta t} = e^{-(\zeta\omega_n + \beta)t}$$

包络的衰减速率从 $\zeta\omega_n$ 变成 $\zeta\omega_n + \beta$，信号看起来衰得更快，效果上等于给结构加了阻尼。等效阻尼比是：

$$\zeta_{eff} = \zeta + \frac{\beta}{\omega_n} = \zeta + \frac{\ln(100/p)}{2\pi f_n T}$$

代个数：固有频率 30 Hz、记录 2 秒、10% 窗，人工阻尼约 0.61%。如果结构真实阻尼是 1%，测出来直接变 1.61%，虚高六成。窗压得越狠（p 越小）、频率越低、记录越短，人工阻尼越大。

![加指数窗后信号表观衰减变快，FRF 峰变胖，就是人工阻尼](/images/impact-testing-windows/artificial-damping.png)

*（图源：Simcenter Testing Knowledge Base）*

用 Python 模拟一锤 30 Hz、阻尼比 1% 的衰减信号，加不同指数窗后从包络回归阻尼，人工阻尼直接可见：

```python
import numpy as np

fn, zeta, T, fs = 30.0, 0.01, 2.0, 4096.0   # 30 Hz 模态，阻尼比 1%
t = np.arange(0, T, 1/fs)                    # 2 秒记录窗
sig = np.exp(-zeta*2*np.pi*fn*t) * np.sin(2*np.pi*fn*t)

for pct in (1.0, 0.1):                       # 100% 窗 = 不加窗
    beta = -np.log(pct)/T                    # 由终点百分比反解衰减率
    x = sig*np.exp(-beta*t)                  # 加指数窗
    seg = np.array_split(x, 20)              # 分 20 段算局部 RMS
    rms = np.array([np.sqrt(np.mean(s**2)) for s in seg])
    tc = (np.arange(20)+0.5)*T/20            # 各段中心时刻
    slope = np.polyfit(tc, np.log(rms), 1)[0]  # 对数包络直线拟合
    zeta_est = -slope/(2*np.pi*fn)           # 包络斜率反算阻尼比
    print(f"窗终点 {pct*100:5.1f}%: 回归阻尼比 {zeta_est*100:.2f}%")
```

输出：100% 窗回归阻尼比 **1.00%**（真实值），10% 窗回归阻尼比 **1.60%**，与公式预测的 1.00% + 0.61% = 1.61% 几乎重合，多出来的就是人工阻尼。

::: warning 阻尼提取场景慎用
要做阻尼比识别（3dB 带宽法、模态拟合），优先**加长记录时间**让响应自然衰减、指数窗保持 100%，而不是靠窗硬压。实在非用不可，Testlab 的模态拟合器会读取数据里记录的衰减参数做补偿，但补偿的前提是窗参数随数据一起存了下来，手工后处理时窗参数丢了，人工阻尼就成了永久污染。
:::

## 五、双击与质量控制：别让平均值吃进坏数据

### 双击：锤子反弹的二次敲击

锤头敲击后轻微反弹回敲结构，力信号里出现第二个脉冲，就是双击（Double Hit）。它对 FRF 的杀伤在于相位：两次输入脉冲对应两组输入输出关系，平均到一起，FRF 幅值和相位都被搅乱，常见症状是峰附近相位转不动、相干莫名掉落。

Testlab 在 Measure 工作表的 All Settings 里提供双击与过载的自动检测剔除（detection/rejection），建议默认打开。自动判据不放心的话，每敲一锤都看一眼力波形，第二脉冲一目了然，Reject 掉这一锤比事后任何处理都干净。

### 相干：每锤都要盯的仪表

测量时右下角的相干函数（Coherence）是重复性的实时仪表：接近 1 说明这组敲击激励与响应关系稳定；掉到 0 说明锤与锤之间差异太大。整个频段相干都应该贴着 1，唯一合理的例外是反共振点，那里响应本身接近零，仪器噪声占比大，相干掉落是物理必然，不是操作失误。

![健康的测量：FRF 反共振处相干掉落属正常，其余频段应接近 1](/images/impact-testing-windows/frf-coherence.png)

## 六、窗选择速查

手册给锤击和 FRF 场景的窗选择列了明确清单，直接抄作业：

| 测量对象 | 推荐窗 | 理由 |
| --- | --- | --- |
| **锤击激励（参考）通道** | **力窗** | 脉冲外清零，削噪声不伤脉冲 |
| **锤击响应通道** | **指数窗**（能不用则不用） | 压住未衰减尾巴防泄漏，代价是人工阻尼 |
| **完全衰减的冲击** | **矩形窗** | 帧首尾自然为零，加窗反而引入畸变 |
| **随机激励两通道** | **汉宁窗** | 连续信号防泄漏的通用解 |
| **伪随机激励两通道** | **矩形窗** | 信号在帧内整周期化，无泄漏 |

::: tip 锤击窗设置三步走
- 响应能自然衰减：指数窗保持 100%（等于不加），力窗窄开
- 响应衰减不完：先加记录时间；确实加不动（结构阻尼太小、现场时间有限）再上指数窗，百分比尽量选高
- 窗参数随数据保存，后续模态拟合才有补偿的依据
:::

## 七、小结

锤击测 FRF 的质量链条：触发保证脉冲完整、力谱平坦保证全频段激励、力窗削输入噪声、指数窗只在没有退路时用、双击剔除守住平均的纯度。数字上的判断标准就三条：力谱滚落不超过 3~10 dB（扣除顶部 20% 抗混叠区）、相干全频段贴 1（反共振除外）、阻尼比识别优先加时间而非加窗。指数窗的人工阻尼公式 $\zeta_{eff} = \zeta + \ln(100/p)/(2\pi f_n T)$ 值得记住：它告诉你窗压下去的每一分 dB，都会从阻尼比的准确性里扣回来。
