# SCADAS RS 系统连接全解：Wi-Fi AP/客户端/以太网/SFTP 四条通道

> 路试收车，REC 单元的 SSD 里躺着上百 GB 数据，工程师掏出笔记本想现场先拷一版：连 Wi-Fi，网页能打开，文件夹却怎么也刷不出来；换网线插上，Windows"网络"里还是看不见设备——最后只能抱着机器回办公室干等。这类卡壳多数不是设备故障，而是没搞清 REC 单元对外一共开着几扇"门"、每扇门的门牌号和规矩各是什么。本文把这四条通道当成一辆车的四种进车方式来讲：自带钥匙的 Wi-Fi 接入点（车自己发热点）、配了钥匙去开别人家门的客户端模式、最稳的一把物理钥匙（1 Gb 以太网）、以及公司网络把前三种全锁死时的备用天窗（SFTP）——逐条落到 SSID 规则、IP 行为、发现机制与安全边界上。

## 一、为什么"能连上"却"找不到"

先看一个真实约束：公开技术相关技术手册在系统连接一章写得明白——REC 单元的有线网卡**默认动态 IP**，拆箱后即可与 PC 做首次点对点访问；但要在 Windows 资源管理器"网络"里看见它，前提是 PC 网卡设成"自动 IP"、且 **SSDP 发现服务处于活动状态**。Windows 10 里这个服务默认常常是关的。于是出现了路试场上最典型的错位：Wi-Fi 已经连上、Recorder 网页也打得开（网页走的是 IP 直连），而"网络"文件夹里空空如也（文件共享走的是 SSDP/WS-Discovery 发现协议，是另一套机制）——**"连得上"和"看得见"是两件事**。

这也解释了四条通道的设计逻辑：REC 单元同时要伺候配置（浏览器打开 Web 应用）、采数（Testlab Neo 前端模式）、搬数（文件服务器/SFTP）三类完全不同的访问需求，没有任何一条通道能同时把三件事都做到最好。理解每条通道"擅长什么、忌讳什么"，比背连接步骤重要得多。

::: info 核心概念
- **接入点模式（Access Point，AP）**：REC 单元自己发射 Wi-Fi 热点，客户端设备连上来，适合作业现场无网络的场景
- **客户端模式（Client）**：REC 单元作为无线客户端连入外部已有热点，需配置目标 SSID 与密码，适合接入场地既有网络
- **APIPA（自动私有 IP 寻址）**：DHCP 服务器不可用时操作系统自动为自己分配 IP 的机制——REC 后备 APIPA IP 印在机身物理标签上，是发现机制全部失效时的最后门牌号
- **SSDP/WS-Discovery**：Windows 用来在网络里"发现"设备的协议族；被安全策略禁用时 REC 在"网络"文件夹不可见
:::

## 二、房门钥匙的比方：一扇门配一把钥匙

把 REC 单元想成一栋带四种进法的房子，贯穿全文：

**Wi-Fi 接入点是"自带门禁的院子"**——房子自己发信号（SSID 就是大门上挂的门牌），钥匙统一出厂配发（默认密码），进院子最多带四个人（最多四个客户端）。**客户端模式是"拿着钥匙去开别人家的门"**——房子缩成一间客房，接入别人家的路由器，用的是主人家的门禁（外部 SSID 和密码）。**1 Gb 以太网是"实体钥匙直开正门"**——最快最稳，不受墙体衰减与频段拥挤影响，Testlab Neo 前端模式点名要走这扇门。**SFTP 是"天窗绳梯"**——当楼下保安（公司网络安全策略）把正门、院门全锁死（WS-Discovery/SSDP/NBNS 被禁）时，从天窗照样能进出搬东西，只是要按对方规定的口令（用户名密码）来。

四把钥匙没有高级低级之分，只有"当前在哪种墙里"的适配问题。下文逐扇门细讲。

## 三、门一：Wi-Fi 接入点模式——REC 自己发热点

REC 单元内置符合 IEEE 802.11g 与 802.11ac 标准的 Wi-Fi 接入点，**最多同时服务四个客户端**。任何带标准浏览器的设备——笔记本、平板、手机——连上热点后即可打开车载 Web 应用，不需要安装任何软件。

SSID 的命名规则值得记住：2.4 GHz 频段预设网络名为 `SCADAS-RS-2.4-nnnnnnnnnn`，5.0 GHz 频段为 `SCADAS-RS-5.0-nnnnnnnnnn`，其中 `nnnnnnnnnn` 是这台设备**不重复的出厂序列号**。默认密码 `SCADAS-RS`。一个细节：硬件虽已具备 5.0 GHz 能力，相关技术手册明确"尚未得到支持"——现场排障时不要在 5 GHz 热点上浪费时间。

多台 REC 同场作业时的常见事故是"不知道连上了谁"：两台设备的 SSID 只差序列号尾巴，电脑自动连错了对象。相关技术手册在故障排除表里给的解法很直接——**为 Wi-Fi 接入点配置不重复的名称（重命名设备/SSID）**，开工前把每台 REC 改成"车型-工位-序号"这类一眼可辨的名字。

::: warning 工程注意
接入点模式下 REC 与客户端是点对点的小网络，客户端将失去与公司网络/互联网的连接（除非客户端有第二块网卡）。现场要用平板看数据、又要查邮件时，提前规划好哪台设备走哪张网。
:::

## 四、门二：客户端模式——REC 连进别人的网

客户端模式把方向反过来：REC 单元作为无线客户端，连入外部接入点（场地的路由器、手机热点、测试车间无线网）。此时必须在 REC 上配置目标网络的 **SSID 与密码**，配置后即可从既有网络里访问 REC——适合多台设备共用一张网、或需要远程访问的台架场景。

客户端模式与接入点模式的关键差别在"谁管 IP"：接入点模式下 REC 自己就是网络的核心；客户端模式下 IP 由外部网络的 DHCP 服务器分配。此时相关技术手册追加了一条要求：**网络路由器必须允许新设备入网（DHCP）**——不少公司网对未知 MAC 有准入控制，REC 连上去拿不到地址，症状是"密码明明对的，就是 ping 不通"，排查时应先找 IT 确认准入策略。

从更远的距离看，REC 单元还可以通过 LAN、Wi-Fi 甚至**公共或蜂窝网络**被远程访问——配合 LTE 外部调制解调器（硬件预留）可以把访问半径拉到任意远，但随之而来的安全责任也更重（见第七节）。

## 五、门三：1 Gb 以太网——最快最稳的物理通道

REC 单元面板提供 1 Gb 以太网连接器（UTP 双绞线），是三条数据通道里带宽最实的一条。它同时承担两种角色：

**其一，Testlab Neo 前端模式的数据链路。**需要高级采集与分析时，运行 Testlab Neo 的主机 PC 通过 1 Gb 以太网端口以前端模式连接 REC——数据不经车载应用，直接由 PC 控制整系统，适合台架上做全功能测试。

**其二，SSD 数据搬运的主干道。**存储在内部 SSD（至少 220 GB 用户空间）的数据，通过以太网传到 PC，速度远超 Wi-Fi。差距有多大，用三行数字算一下：

```python
import numpy as np

volumes_GB = np.array([8, 32, 128])      # REC SSD 上待搬运的数据量
wifi_mbs  = 250e6 / 8.0                  # Wi-Fi 有效吞吐 ≈ 250 Mbit/s
eth_mbs   = 940e6 / 8.0                  # 1 Gb 以太网有效吞吐 ≈ 940 Mbit/s
sftp_mbs  = 60e6 / 8.0                   # 保守 SFTP 吞吐 ≈ 60 Mbit/s

print("数据量    Wi-Fi直传    1Gb以太网    SFTP(保守)")
for v in volumes_GB:
    t = v * 1e9 / np.array([wifi_mbs, eth_mbs, sftp_mbs]) / 60
    print(f"{v:>4} GB   {t[0]:>7.1f} min   {t[1]:>7.1f} min   {t[2]:>7.1f} min")
```

实测输出（numpy 2.4.6）：

```text
数据量    Wi-Fi直传    1Gb以太网    SFTP(保守)
   8 GB       4.3 min       1.1 min      17.8 min
  32 GB      17.1 min       4.5 min      71.1 min
 128 GB      68.3 min      18.2 min     284.4 min
```

这张表回答的问题是：收工后想尽快把数据搬回服务器，值不值得去车上找网线——128 GB 的数据，Wi-Fi 要一个多小时，插上网线不到二十分钟。一趟路试回来若有多台 REC 排队拷数，以太网是唯一能保证当晚下班的选择。

**有线通道的规矩**：PC 网卡设"自动 IP"（Windows 默认）；REC 默认动态 IP，若 SSDP 服务活动，几秒内应出现在资源管理器"网络"下；无论如何，REC 都可以通过其后备 **APIPA IP** 访问——这个地址印在机身物理标签上，是所有发现机制都失灵时的兜底方案。若把 REC 接入有线网络，还需路由器允许新设备 DHCP 入网，有疑问先联系 IT 部门。

::: warning 工程注意
相关技术手册用最高级别警告写着：**切勿使用连接到 REC 单元的调节单元把网络或 PC 连进菊花链**——这可能导致系统出错、测量错误或网络/PC 问题。PC 与网络只能从 REC 的以太网口进，不能从链上调节单元"就近搭线"。
:::

## 六、门四：SFTP 与文件服务器——搬数据的两条软通道

存储在 REC 内部 SSD 上的数据有两种软搬运方式。

**方式一：Windows 文件共享（Samba 服务器）。**在 Windows 资源管理器"网络 - 计算机"部分找到 REC 设备、点击后它就像网络里的一台普通电脑，默认用户名 `USER`（大写）、默认密码 `SCADAS-RS`。建议用资源管理器**左窗格**取得文件访问权限；要打开 Recorder 应用程序，则双击右窗格中的 REC 图标。文件服务器需要 Windows 7 或更高版本，账号密码与 Recorder 应用程序一致。

**方式二：SFTP。**相关技术手册在两处明确"还支持 SFTP"——当文件共享这条路走不通时，SFTP 是指定的替补通道。

什么时候必须换 SFTP？故障排除表列出了文件共享失效的完整链条：PC 的 Windows 版本早于 7（无法连接）；WS-Discovery 未发现 Samba 服务器（刷新 F5、在 Windows 搜索框输入 `\\A.B.C.D` 直填 REC 主机端口 IP、或启用 WS-Discovery 服务）；以及最常见的——**公司网络出于安全考虑把 LLMNR、WS-Discovery、SSDP、NBNS 全部禁用**，此时设备可见性与双击访问都会受限，官方给出的兜底方案就是：改用 SFTP 连接 REC 单元。

另一个值得写进班组规矩的细节：相关技术手册明确**不鼓励同时访问文件和进行录制**——拷数与采数抢的是同一块 SSD 的吞吐，边采边拷既拖慢采集又威胁数据完整性。收工流程应该是"停车、停录、再拷数"。

还有一个"存在但别指望"的选项：REC 面板上的 USB 3.0 接口标注可向外部硬盘传输数据，但相关技术手册用脚注注明**"硬件已可用，尚未得到支持"**——与 5 GHz Wi-Fi 同样的状态，规划流程时不要把未启用功能算进产能。

## 七、安全边界：四扇门共用的门禁规则

通道再多，安全规则是同一套。公开技术相关技术手册的要求可以归纳为四条：

1. **Wi-Fi 加密**：无线连接受加密保护，接入必须输网络密码。
2. **账号密码双门槛**：REC 内置文件服务器与 Recorder 应用共用一套用户名密码；密码策略为**至少 8 个字符、至少 1 个特殊字符、至少 1 个大写字母**。密码是防未经授权访问数据的第一道闸，用户有责任妥善管理。
3. **签名固件**：固件更新使用数字签名映像，验证身份认证与完整性，防止刷入被篡改的固件。新固件须用 Recorder 应用程序、经 SCRSA-CABN02（REC 到 PC）电缆附件上传至 REC 单元。
4. **物理访问控制**：系统使用环境的安全性是安全使用设备、保护数据的前提——访问控制要同时覆盖物理区域与数据传输网络。

一个容易忽视的操作风险：相关技术手册警告**拆卸系统时，在系统完全关闭、指示灯不再亮起之前，切勿从 REC 单元上移除菊花链电缆**——搬机器前先确认灯灭了再拔线，否则可能拿数据完整性冒险。

## 八、通道选择速查表

| 场景 | 推荐通道 | 关键动作 |
| --- | --- | --- |
| 现场无网络，平板/手机看数采状态 | Wi-Fi 接入点 | 连 SSID，浏览器开 Web 应用；最多 4 客户端 |
| 场地有无线网，多设备共用 | 客户端模式 | 在 REC 配置外部 SSID 与密码；确认 DHCP 准入 |
| 台架全功能测试（Testlab Neo） | 1 Gb 以太网 | 前端模式连接；PC 网卡"自动 IP" |
| 收工大批量拷数 | 1 Gb 以太网 | 128 GB 约 18 分钟；避免边录边拷 |
| "网络"里看不见 REC | 先查发现服务 | PC 启用 SSDP；或直填机身 APIPA IP |
| 公司网禁用全部发现协议 | SFTP | 用 `\\IP` 直连或 SFTP 客户端 |
| 多台 REC 同场 | 任意通道 | 先重命名设备/SSID 防混淆 |

## 九、一句话记住

REC 单元对外开四扇门：Wi-Fi 接入点自带门牌（SSID 带序列号、默认密码、限 4 客户端）、客户端模式拿钥匙开别人的门（SSID+密码，防 DHCP 准入）、以太网是实体钥匙正门（前端模式与拷数主干道，128 GB 约 18 分钟）、SFTP 是发现协议全被禁时的天窗；"连得上"不等于"看得见"——看不见时先查 SSDP，再试机身 APIPA IP。
