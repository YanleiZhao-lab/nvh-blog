# SCADAS RS 引脚输出与布线：数字IO/脉冲/CAN/GNSS 接口定义

> 为什么转速通道"有信号但读数乱跳"、CAN 总线一挂四条就报错、GNSS 定位漂到隔壁街区？排查一圈传感器没毛病，病根常常在最小被检查的一环——接线。本文以 SCADAS RS 的 REC 与 DI 单元为对象，把数字 IO、脉冲输入、CAN 总线、GNSS 四类接口的引脚定义、布线规则与功率边界一次讲清，给出测试前"对表核查"的可执行清单。

<br>

台架联调前一晚，三件怪事凑到一起：转速通道接的是同一台编码器，DI 单元上读出来却是乱跳的数；CAN 总线刚挂到第四条，Recorder 里整组通道集体消失；GNSS 天线随手拧了个半紧，试车回来看轨迹"漂"出了车道。三件事的排查都绕了远路——编码器拆下来换了一台、CAN 传感器换了两个、定位模块复位了三遍，最后都定位到同一类问题：接线。引脚接错位、终端电阻没考虑、天线没拧到位，这类错误的特点是**设备自检不报、通道看似有数、结果悄悄出错**。数字接口不像模拟通道那样有量程和灵敏度可核对，它的"对错"全藏在引脚表和布线图里——本文把 SCADAS RS 数字侧的接口定义摊开来讲，让每一次接线都有表可对。

## 一、为什么要专门讲数字接口的接线

SCADAS RS 是模块化采集系统：模拟传感器接到 B24/S24/U12 等调节单元，而数字世界的一切——转速脉冲、编码器正交信号、CAN 总线报文、GNSS 定位、台架联锁的数字 IO——全部汇入两个单元：REC（记录仪单元）与 DI（数字脉冲和 CAN 总线调节单元）。

![REC 单元面板：以太网、GNSS、数字 IO、CAN、脉冲输入等连接器布局](/images/rs-pinout-wiring/fig6.png)

*（图源：网络 侵删）*

REC 单元面板上有 12 类连接器：模式按钮、同步连接器（预留）、GNSS 连接器、1 Gb 以太网、数字 I/O、Wi-Fi 天线接口（2x）、USB 3.0、CAN1/2 与 CAN3/4 连接器（2x）、脉冲输入连接器（3x）、USB 2.0（2x，支持摄像机）、电源输出链连接器（4x）、电源输入连接器。DI 单元则提供 3 个带模拟转速功能的数字输入连接器（1P/2P/3P）和 2 个可连接 4 条 CAN 总线的 CAN 连接器。

值得先记住一句话：**CAN 与脉冲这类"计数型"信号，接线错误的症状是数值型的（转速错、丢报文），不是通道报错**。这就是为什么本文值得单独成篇——模拟通道接错多半量级不对、一眼能看出来，数字通道接错却常以"数据看起来正常"的面目混过整个试验。

打个生活里的比方。数字接口的接线像家里配电箱的空开标签：标签贴错位不跳闸、不报警，某天要单独断厨房电时才发现断的是客厅——一切"功能"都还正常，唯独对应关系错了。引脚表就是配电箱里那张正确的标签纸：写明每个孔位"是什么、从哪来、到哪去"。布线图则是走线规范：哪根线走屏蔽、哪根必须成对、哪根要拧到规定力矩。接线前不对表，等于把整箱空开摸黑拨一遍。

## 二、数字通道引脚输出：REC 与 DI 的三张表

数字输入的引脚输出分三组，每组对应一种连接器与所属单元。

![脉冲输入与增量编码器的数字通道引脚定义（15 针连接器）](/images/rs-pinout-wiring/fig2.png)

*（图源：网络 侵删）*

第一组：**脉冲 - 数字、增量编码器**，连接器为 15 针（机箱母头 YCP-TIA15FCG-10FPGZX-000X，插头公头 YCP-TPR15FCX-10MSGEX-076X），REC 与 DI 单元均有。

![CAN 总线连接器的引脚定义（15 针连接器）](/images/rs-pinout-wiring/fig3.png)

*（图源：网络 侵删）*

第二组：**CAN 总线**，连接器同为 15 针（机箱母头 YCP-TIA15ACG-06FPKZX-000X，插头公头 YCP-TPR15ACX-06MSKFX-061X），REC 与 DI 单元均有。

![数字 I/O（TTL 与 UART / RS-232）的引脚定义（15 针连接器）](/images/rs-pinout-wiring/fig4.png)

*（图源：网络 侵删）*

第三组：**数字 I/O**——TTL 电平与 UART / RS-232 串口（15 针：YCP-TIA15BCG-10FPGZX-000X / YCP-TPR15BCX-10MSGEX-076X），仅在 REC 单元上。

三组连接器物理尺寸相同，**这是数字侧最大的接错风险**：三种线缆若外观接近，插错连接器不会损坏硬件（针脚定义不同），但信号全乱。规范做法是接线前按上表核对连接器型号后缀——后缀不同即为不同接口。

::: info 核心概念
- <strong>引脚输出（Pinout）</strong>：连接器每个针位的信号定义表——接线前唯一权威的对表依据
- <strong>增量编码器（Incremental Encoder）</strong>：输出正交脉冲串的旋转位置传感器，A/B 相位差 90 度判方向，参考脉冲定零点
- <strong>TTL / HTL</strong>：两类常见脉冲电平标准，TTL 为 5 V 逻辑、HTL 为 12/24 V 逻辑，接线前须与通道设置一致
- <strong>RS-422 / RS-485</strong>：差分串行接口标准，抗共模干扰强，适合长线传输编码器信号
:::

## 三、脉冲与转速：单端、差分与编码器的布线

数字传感器的布线图给出四种典型接法。以单端脉冲输入（有供电）为基准，手册特别注明：**另有两个单脉冲输入，使用引脚 2 或 4 而非引脚 8**——同一个 15 针连接器上，三个针位各自独立构成一路单端脉冲输入，一个连接器可以同时接三路。

![单端脉冲输入（有供电）的布线图：引脚定义与单元内部供电关系](/images/rs-pinout-wiring/fig5.png)

*（图源：网络 侵删）*

差分脉冲输入则成对使用引脚：标准接法占用引脚 7 和 8，**另有两路用引脚 1 和 2 或 3 和 4**。差分接法把脉冲信号与它的反相版本一起传，接收端做差后共模干扰抵消——车间里长线穿越变频器附近时，差分是默认选择。

增量编码器在此基础上再加方向信息：A、B 两相正交脉冲，加一路参考脉冲定零点。手册的布线注明写着：**如果传感器不提供参考脉冲，可以不连接引脚 4**（单端编码器）或**引脚 3 和 4**（差分编码器）——参考脉冲是可选针位，不是必接项；但要做"基于参考脉冲的零点位置"类测量时，它就是必需的。

转速信号的调节能力边界（REC 与 DI 相同）值得对表：

| 项目 | 能力 |
| --- | --- |
| 脉冲通道数 | 9x |
| 最大脉冲速率 | 高达 1 兆脉冲/秒 |
| 供电输出 | 5 V 与 12 V 直流 |
| 支持电平 | TTL、HTL（单端和差分）、RS-422/RS-485 |
| 编码器类型 | 旋转或线性（参考、旋转感应、脉冲） |
| 转换输出 | 计数（线性/角度位置）与速率（频率、速度、RPM、流量等） |

这里有一条容易踩的供电边界：DI 单元 3 个脉冲输入满负载最多额外增加 8 W 功耗，REC 上同一数字为 8.2 W——多通道、长线、带供电的编码器阵列要在系统功耗预算里预留这一项，否则链上供电余量不足时最先出问题的就是这些"边角通道"。


接线正确之后，读数换算是第二道关。脉冲序列换转速的本质是"数沿、除以时间、再乘每转脉冲数"；正交编码器多送一个 B 相，换来的是四倍分辨率和方向判别。一段自包含的 numpy 演示把两种换算与"B 相接反"的症状走一遍：

```python
# 脉冲/编码器信号到 RPM 的换算：单端计数 vs 正交四倍频 + 方向判别
import numpy as np

fs, pps, rpm_true = 10000, 60, 1800      # 采样率/每转脉冲数/真实转速
t = np.arange(0, 0.5, 1/fs)
dur = 0.5

# 单端脉冲：每转 pps 个 50% 占空比方波，数上升沿
pulse = ((t * rpm_true/60 * pps) % 1 < 0.5).astype(float)
n_rise = int(np.sum(np.diff(pulse) > 0))
print(f"单端计数法: {(n_rise+1)/dur/pps*60:.1f} rpm")

# 正交编码器：B 相滞后 A 相 90 度，状态转移 = 4x 分辨率
phase = t * rpm_true/60 * pps
a = (phase % 1 < 0.5).astype(float)
b = ((phase + 0.25) % 1 < 0.5).astype(float)
states = ((a > 0)*2 + (b > 0)).astype(int)
n_trans = int(np.sum(np.diff(states) != 0))
print(f"正交四倍频: {n_trans/dur/(pps*4)*60:.1f} rpm")

# 方向判别：A 上升沿时看 B 电平（B 滞后则正转为 0）
a_rise = np.where(np.diff(a) > 0)[0]
print("B 相正常时正向占比:", round(float(np.mean(b[a_rise] < 0.5)), 2))
print("B 相接反时正向占比:", round(float(np.mean((1-b)[a_rise] < 0.5)), 2))
```

运行结果：单端计数法 1800.0 rpm、正交四倍频 1799.5 rpm（末尾半个状态周期落在记录之外，属计数法固有的半沿截断误差，记录时间越长占比越小）；方向判别两行输出 0.00 对 1.00——B 相接反时方向指示完全翻转，而转速读数不受影响。这正是数字接线的典型病灶：**数对了，方向反了，设备依然不报任何错**。

## 四、CAN 总线：报文型传感器的接入

CAN 总线的布线要点不在引脚表而在拓扑与负载。REC 与 DI 各提供 2 个 CAN 连接器、合计可接 4 条总线，支持 CAN 2.0B 与 CAN-FD。CAN 是多节点共享总线：每个连接器挂一条总线，一条总线上并联多个传感器节点，用 CANopen 或 OBD 类协议读报文。

两条工程边界直接写进了单元功耗表：**4 条 CAN 总线满负载时，REC 上最多额外增加 10.25 W，DI 上为 10.2 W**。CAN 节点不是"免费"的——每个节点收发器都在耗电，数量多时这一项不能忽略。

另一个隐性规则藏在 REC 面板的注释里：CAN1/2、CAN3/4 连接器标注"不在内部端接"。CAN 总线两端需要 120 欧姆端接电阻，SCADAS RS 内部不提供——端接由外部线缆或传感器侧完成。系统对接入的报文型设备有明确支持范围：TCK8 模块类热电偶扩展（每个 CAN 2 个模块、最多 64 通道）就是走 CAN 接入的典型设备。若总线上出现通信错误，Recorder 的状态页会给出 CAN 错误计数，排查方向按"端接—节点数—波特率—线缆屏蔽"的次序走。

## 五、GNSS：拧紧天线是信号完整性的第一步

GNSS 连接器在 REC 面板上是一个 SMA 接口，支持 GPS、GLONASS 与北斗三系统。手册对它的唯一一句告诫值得抄在工具箱盖上：**注意正确拧入 GNSS 天线，以获得适当的信号完整性，例如使用 SMA 扭矩扳手**。

这句话背后是射频常识：SMA 连接器半拧状态接触电阻不稳定，轻则信噪比下降、定位漂移，重则反射驻波损坏前端。车载试验的振动环境会放大这个问题——台架上手拧的"差不多紧"，跑完坏路就变成"松了"。GNSS 信号本身极弱（到达地面约 -130 dBm 量级），天线连接的一点损耗都是雪上加霜。

定位数据的增强手段是 RTK（实时运动学）技术，通过基准站改正数把米级定位提到厘米级——做道路试验的轨迹对齐、事件按位置触发时是必备项。GNSS 数据与模拟数据在 REC 内合并为单一数据流，时间戳同源，这是"振动事件与位置可对表"的基础。

## 六、数字 IO 与 UPS 远程开/关：把采集系统接进台架

REC 的数字 I/O 连接器支持 TTL 电平开关量与 UART / RS-232 串口两类用途。工程上最典型的用法是台架联锁：台架的安全继电器输出一对触点接到数字输入，采集系统据此感知"试验允许运行"；反向的数字输出可以把"采集中"状态回传给台架 PLC，实现互锁。

UPS 单元的远程开/关连接器则是另一个"数字接线"高发区。3 芯接口，两种接法：

- **外部电压源（6.5 V..60 V）**：电压加在引脚 1（开/关）与引脚 2（接地）之间——有电压为开，无电压为关
- **无电位开关**：开关接在引脚 1 与引脚 3（电源输出）之间——开关闭合且有外部直流电源时系统开机

逻辑上有一条兜底规则：**如果没有可用电源（无外部直流输入且内部缓冲器电量极低），UPS 不会开机或正常关机**。远程开/关的输入阈值同样有明确边界：高于 6.5 V 低于 60 V 视为"开"，低于 4.5 V 视为"关"——用台架 PLC 的 24 V 输出驱动它正好落在窗口内。

## 七、接线前的对表清单

把上述内容压成一张可执行的核查表，接线前逐项打勾：

1. **连接器型号核对**：三种 15 针连接器后缀不同（脉冲 FCG/ACG/BCG 系列），插之前对后缀，防"同尺寸不同功能"
2. **引脚表打印在手**：单端脉冲记"引脚 8 为主、2/4 备用"；差分记"7+8 为主、1+2、3+4 备用"；编码器参考脉冲针位（4 或 3+4）按需接
3. **电平制式一致**：通道设置里的 TTL/HTL/RS-422 与传感器实际输出对齐
4. **CAN 负载与端接**：节点数计入功耗（4 总线满载约 +10 W），端接电阻外部解决，通信异常先查端接
5. **GNSS 天线力矩**：SMA 按规定力矩拧紧，车载试验前后各检查一次
6. **数字 IO 用途登记**：接台架联锁的，在试验大纲里写明触点逻辑与阈值窗口（6.5–60 V）
7. **功耗汇总**：脉冲 +8 W、CAN +10 W、USB +3.3/+5.9 W、数字 IO +0.5 W，与 UPS 缓冲能力对账
8. **热边界**：所有插头和电缆耐热至少 +65 摄氏度；未用连接器全部加盖防尘防潮

## 八、小结

数字接口的可靠性不来自设备自检，而来自接线前的对表。引脚输出表回答"每个针位是什么"，布线图回答"传感器怎么接"，功耗表回答"能接多少"。三者合起来，数字通道才能像模拟通道一样"设置即所得"。转速、CAN、GNSS、数字 IO 四类接口的故障模式各有不同，但预防手段是同一个：把对表做成接线的固定工序。

## 一句话记住

数字接线无自检、错位不报警：15 针连接器先对后缀再插（脉冲/CAN 总线/数字 IO 三种）、单端脉冲主针 8 备用 2/4、差分成对 7+8 与 1+2、3+4，CAN 四总线满载多耗 10 W 且端接在外、GNSS 天线按力矩拧紧——接线前对表 8 项打勾，胜过事后查三天。
