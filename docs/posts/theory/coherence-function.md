# 相干函数：测量质量的照妖镜

> 锤击模态测试做完，频响函数（FRF）曲线看起来像模像样，你怎么知道它可信？相干函数（Coherence Function）就是干这个的：它逐频率告诉你，输出信号里有多大比例的能量能被测到的输入线性解释。相干高，FRF 数据敢用；相干低，曲线再漂亮也是垃圾。

## 一、相干函数到底在算什么

单输入单输出系统里，激励 x(n) 与响应 y(n) 的**常相干（Ordinary Coherence）**定义为：

γ²(f) = |Sxy(f)|² / [Sxx(f) · Syy(f)]

其中 Sxy 是互功率谱平均，Sxx、Syy 是两个信号各自的自功率谱平均。它的取值范围是 0 到 1——这是数学上的必然，不是巧合：互谱幅值受柯西–施瓦茨不等式约束，永远不可能超过两个自谱几何平均。

物理上可以把它读成：**输出能量中，能被测到的输入经由线性关系解释的比例**。γ²=1 意味着输出完全由该输入通过线性系统引起；γ²=0.5 意味着一半输出能量另有来源——要么是没测到的第二个振源，要么是噪声，要么是系统根本不线性。

注意定义里的"平均"二字。相干函数必须建立在谱平均之上：只采一帧数据时 |Sxy|² 恒等于 Sxx·Syy，相干永远等于 1，什么也照不出来。这正是它叫"照妖镜"的前提——得有多帧数据让它做统计。

::: info 核心概念
- **常相干（Ordinary Coherence）**：单个输入与单个输出之间的线性相关程度，γ²=|Sxy|²/(Sxx·Syy)
- **平均**：相干只在多帧谱平均下有意义，单帧计算恒为 1
- **可信判据**：工程上常要求关心频段内 γ²>0.8，共振峰附近尤其要看
:::

## 二、四种相干各管什么

Simcenter Testlab 里相干函数有四种，对应四类不同的工程问题：

| 类型 | 输入侧 | 典型用途 | 数值特征 |
| --- | --- | --- | --- |
| **常相干** | 单个参考信号 | 评估单输入 FRF / 传导函数质量 | [0,1]，单帧恒为 1 |
| **重相干（Multiple Coherence）** | 一组参考信号 | 检验输出中噪声含量：所有测到的输入加起来能解释多少 | ≥ 同输出的任何常相干 |
| **偏相干（Partial Coherence）** | 排除其它信号影响后的单输入 | 多源贡献排位：剥离已测其它路径后，这条路径还剩多少线性贡献 | [0,1]，条件化的常相干 |
| **虚拟相干（Virtual Coherence）** | 主分量（Principal Components） | 多参考工况下分离不相关独立源（如左右轮激励） | 与所有主分量之和 ≤ 1 |

选型逻辑很直接：单输入试验看常相干；MIMO 试验看重相干判断整组输入够不够；传递路径分析（TPA）里排查"到底哪条路径主导"用偏相干；多个不相关源混在一起、又不想逐个测量时，用虚拟相干配合主分量分析把它们拆开。

## 三、低相干的五大嫌疑人

相干曲线掉下来，原因无非这几类，按现场出现频率排：

1. **漏测输入**。输出端混进了没测的振源——旁边工位的风机、路面激励、另一台运转的设备。这是最常见也最隐蔽的原因。
2. **信噪比不足**。反共振区、频响函数的谷底，响应信号本身小，传感器本底噪声占比上升，相干自然掉。所以模态试验里反共振区相干低往往是正常的，重点看共振峰。
3. **平均次数不够**。谱平均是统计估计，帧数少方差大。锤击试验通常 5～10 次平均起步。
4. **系统非线性**。螺栓连接松动、橡胶件大变形、碰撞间隙。输出里产生了输入谱中没有的谐波成分，线性模型解释不了。
5. **时延/时变**。旋转机械升速工况下转速在漂，或两通道之间有采样不同步的时延，相干会被系统性拉低。

::: warning 工程注意
相干高不代表系统线性，只代表"输出能量能被线性解释"——两个不相关的信号各自经过强非线性再叠加，有时也会给出漂亮的相干。反过来，共振峰处相干低先别怀疑非线性，最先查的是力锤敲击一致性、传感器增益档和触发设置。
:::

## 四、Python 演示

**演示一：噪声如何同时压低相干、抬高 H1 估计误差。** 构造一个 200 Hz 单自由度系统，白噪声激励，在输出端叠加噪声，看三个频率点的相干与 FRF 幅值误差如何联动：

```python
import numpy as np

rng = np.random.default_rng(0)
fs, N, M = 1024, 1024, 40                  # 采样率、每帧点数、平均帧数
f = np.fft.rfftfreq(N, 1/fs)
f0, zeta = 200.0, 0.05                     # 固有频率 200 Hz、阻尼比 5%
w, w0 = 2*np.pi*f, 2*np.pi*f0
H = w0**2/(w0**2 - w**2 + 2j*zeta*w*w0)    # 单自由度频响函数
x = rng.standard_normal(M*N)               # 白噪声激励
X = np.fft.rfft(x.reshape(M, N), axis=1)
yk = np.fft.irfft(X*H, N, axis=1).ravel()  # 无噪声输出
y = yk + 0.5*rng.standard_normal(M*N)      # 输出端叠加测量噪声
Y = np.fft.rfft(y.reshape(M, N), axis=1)
Sxx = (np.abs(X)**2).mean(axis=0)          # 自谱、互谱按帧平均
Syy = (np.abs(Y)**2).mean(axis=0)
Sxy = (np.conj(X)*Y).mean(axis=0)
g2 = np.abs(Sxy)**2/(Sxx*Syy)              # 常相干
H1 = np.abs(Sxy)/Sxx                       # H1 估计
print(" 频率   |H|   相干   H1幅值误差")
for ft in [200, 350, 500]:
    k = np.argmin(np.abs(f-ft))
    print(f"{ft:>4} Hz {np.abs(H[k]):5.2f}  {g2[k]:.3f}  {(H1[k]/np.abs(H[k])-1)*100:+6.1f}%")
```

最值得看的是联动关系：200 Hz 共振峰处 |H|=10，信噪比高，相干 0.997，H1 误差不到 1%；到了 500 Hz，|H| 只剩 0.19，同样强度的噪声把相干压到 0.19，H1 幅值偏差 15%——**相干低的频段，FRF 幅值基本不能用**。

**演示二：漏测第二个振源，相干当场"报警"。** 座椅导轨响应 = 发动机经悬置路径（有 200 Hz 共振）+ 路面直接传上来（频响平坦，忘了测）：

```python
import numpy as np

rng = np.random.default_rng(1)
fs, N, M = 1024, 1024, 40
f = np.fft.rfftfreq(N, 1/fs)
def coh(x, y):                             # 常相干估计
    X = np.fft.rfft(x.reshape(M, N), axis=1)
    Y = np.fft.rfft(y.reshape(M, N), axis=1)
    return (np.abs((np.conj(X)*Y).mean(axis=0))**2
            / ((np.abs(X)**2).mean(axis=0)*(np.abs(Y)**2).mean(axis=0)))
def through(x, H):                         # 信号经频响函数 H 输出
    return np.fft.irfft(np.fft.rfft(x.reshape(M, N), axis=1)*H, N, axis=1).ravel()
f0, zeta = 200.0, 0.05
w, w0 = 2*np.pi*f, 2*np.pi*f0
Hp = w0**2/(w0**2 - w**2 + 2j*zeta*w*w0)   # 路径1：动力总成悬置（有共振峰）
Hr = np.full_like(Hp, 2.0+0j)              # 路径2：路面激励（频响平坦）
x1 = rng.standard_normal(M*N)              # 已测输入：发动机
x2 = rng.standard_normal(M*N)              # 漏测输入：路面
y = through(x1, Hp) + through(x2, Hr)      # 座椅导轨总响应
for ft, name in [(200, "共振区  "), (400, "共振区外")]:
    k = np.argmin(np.abs(f-ft))
    g_leak = coh(x1, y)[k]                 # 只拿发动机当参考
    g_fix  = coh(x1, y - through(x2, Hr))[k]
    print(f"{ft} Hz {name}: 漏测路面 → 相干 {g_leak:.3f}，剥离后 → {g_fix:.3f}")
```

400 Hz 处最说明问题：悬置路径在此几乎不传能量（|Hp|≈0.33），响应主要由漏测的路面贡献，常相干掉到 0.03——尽管此时系统的"真实"传函没有任何问题。把路面贡献剥离后相干回到 1.000。低相干指向的是**测量方案**缺了输入，而不是结构出了毛病。

## 五、现场判断流程

拿到一条 FRF 先看相干，按这个顺序处理：

| 相干表现 | 首先怀疑 | 处置 |
| --- | --- | --- |
| **共振峰高、峰谷低** | 正常现象 | 直接用，反共振区数据不用作模态拟合 |
| **全频段普遍低** | 平均次数不足 / 通道噪声 | 加平均；查传感器和增益档 |
| **某频段突然塌陷** | 漏测输入或干扰 | 排查周边振源，补参考通道或加窗隔离 |
| **共振峰处也低** | 锤击一致性差 / 非线性 / 双击 | 重敲对比；检查连接件状态 |
| **重相干高但常相干低** | 多输入场景 | 正常，改用 H1 矩阵估计或偏相干分诊 |

::: tip 实用建议
- 单输入试验：关心频段 γ²≥0.8 再谈数据质量，模态拟合只用共振峰附近的高相干区
- MIMO/TPA：常相干低先看重相干——重相干高说明输入组完整，是"分家"问题而非漏测
- 相干曲线别只看一眼均值，逐频段对照 FRF 峰谷位置读，信息量在细节里
:::

相干函数不产生新的振动数据，它只对已有的谱做质量审计。养成"FRF 与相干同屏、先相干后 FRF"的读图习惯，能挡掉一大半模态试验返工。
