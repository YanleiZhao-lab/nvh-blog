# 风洞里 8 小时花掉 35 万，工程师为什么还嫌不够用？——声学风洞试验：从阵列成像到现场决策

> 路噪有路、动力噪声有台架，唯独风噪——车身上每一处后视镜、A 柱、密封条的湍流分离，只有在稳定可复现的人造风里才能逐项归因。可声学风洞是全行业最贵的试验设施之一：一轮 8 小时试验约 35 kEuro，一位风洞工程师原话是"我们两班倒仍然不够，正在考虑排第三班、还要去别处租时段"。本文讲清楚风洞里到底测什么（外部阵列成像、车内定位、表面声压、相干归因）、为什么"现场出结果"值钱到值得把 22 小时的阵列反演压到 1.2 分钟，以及一条完整的现代试验战役怎么排：风速×偏航角矩阵、试验中改状态、数据当场比对。

一台新车型风噪开发到验收前夜，评审会上常出现这样的争执：主观评价说"高速呼呼声偏大"，台架数据一切正常，路试又找不出稳定的复现条件——自然风永远在变，湍流分离对来流角度的敏感度以度计。要回答"到底是后视镜涡、A 柱分离，还是底盘湍流经密封条漏进来的"，只有一种设施能给出可归因的答案：声学风洞。它用稳定可调的风速、可旋转的偏航角（模拟侧风）与低背景噪声环境，把"风"变成了一个可控的试验变量。但这份可控极其昂贵——8 小时 35 kEuro 的价位意味着每一个工况都必须物尽其用，而经典流程恰恰做不到：固定计划测完、回办公室后处理数周、发现问题再约下一轮风洞。一场风噪优化拖成 5 轮试验、150 k$ 的开销，其中约 120 k$ 花在"信息到场太晚"这一件事上。

## 一、为什么风噪只能在风洞里测

风噪的物理源头是湍流分离：气流在车身不连续处（后视镜根部、A 柱、天线、底盘突出件）脱附成涡，涡破碎产生的宽带压力脉动一部分直接向外辐射（车外风噪），一部分经车身结构与密封间隙传入舱内（车内风噪）。它的麻烦在于三个"离不开"：离不开车速（100~160 km/h 是主观抱怨集中区）、离不开来流角度（偏航角 ±20° 内逐度变化，侧风工况的进气格栅噪声可能与 0° 差出数 dB）、离不开复现条件（道路上自然风的风速与湍流度每秒都在变，同一段路跑两遍拿不到可比数据）。

这三条正好对应风洞的三项能力：风速程控稳定、转台给定偏航角、气流品质可标定。也正因如此，仿真路线（CFD 气动噪声计算）目前只能覆盖概念阶段的方案筛选：公开技术资料显示，单个工况的高精度计算超过一周、可算频率上限有限、且无法识别泄漏——密封条漏不入 CFD 的网格，但漏得进乘客的耳朵。原型车一旦到位，绝大多数风噪优化仍然要在风洞里完成：8 小时试验窗口里塞进 200~300 次测量迭代是常态。

::: info 核心概念
- **声学风洞（Aero-acoustic Wind Tunnel）**：在气动风洞基础上降低风扇与洞体噪声、并在试验段布置声学处理的设施，使被测车辆的风噪不被背景噪声淹没

- **湍流分离（Flow Separation）**：边界层在尖锐不连续处脱附成涡的现象，风噪的源头
:::

## 二、风洞里测什么：四类测量构成的归因链

现代声学风洞的测量布局可以按"源—路径—接收端"拆成四层，与公开技术资料给出的技术分类图一一对应。

![声学风洞测量技术总览：外部源识别（阵列/直接测量）、表面声压、车内测量与定位](/images/aero-acoustic-wind-tunnel/tech-overview.png)

*（图源：网络 侵删）*

第一层是**车外源识别**：在试验段两侧、顶部、地面布置多个麦克风阵列（acoustic array），对车身周围的压力分布做空间反演成像——哪个部件在哪个频段"发亮"，一目了然。阵列结果支持批处理比对：不同频率、不同偏航角、不同风速的结果几步点击即可并排，风速与偏航角作为试验条件自动记录归档，不必事后人工核对工况标签。

第二层是**表面声压测量**：在车身表面直接贴表面麦克风（surface microphone），直接量到作用在蒙皮上的湍流压力谱——这是结构传播路径的激励输入，也是验证气动仿真的基准数据。

第三层是**车内直接测量**：人工头（binaural head）在驾驶员/乘客耳位录双耳信号，直接对应主观感受；机器人驾驶员与底架附加传感器补齐无人化与底盘工况。

第四层是**车内声源定位**：用球形声学相机（如 54 传声器的固体球阵列）在舱内扫描，配合几何扫描把声源定位到真实部件位置——泄漏、孔缝、密封不良在图上直接现形。后处理可叠加等效源模型（ESM）与贝叶斯聚焦扩展低频能力，宽频率范围内给出稳定的定位结果。

![54 传声器球形声学相机用于车内噪声源定位与泄漏检测](/images/aero-acoustic-wind-tunnel/acoustic-camera-sphere.png)

*（图源：网络 侵删）*

四层单独看都是"图"，合起来才是"链"：车外阵列找出候选源，车内定位确认泄漏点，表面麦克风给出路径激励，耳位数据对上主观量。而把链闭合的关键一环，是下面这层相干分析。

## 三、归因的钥匙：外部阵列与车内耳位的相干分析

四类测量各拍各的"图"，工程师真正要回答的问题却是因果性的：车外几十处源都在响，哪一个真正进了驾驶员的耳朵？

工具就是相干函数（coherence）——两个信号在逐个频率上的线性相关程度，取值 0~1。把外部阵列的每个成像格点与车内耳位信号做相干，γ² 接近 1 的格点说明该处压力脉动与耳位噪声同源：它就是"漏点"或"传播贡献大的源"；γ² 接近 0 的格点再亮也只是车外热闹、车内听不见，不值得投入优化。公开技术资料把这一步称为能量流分析：哪个外部源漏进车里、从哪漏，一张相干叠加图说清。

这个公式回答的问题是：两个信号之间，一个能用线性系统解释另一个的比例有多大？

$$\gamma_{xy}^2(f) = \frac{|S_{xy}(f)|^2}{S_{xx}(f)\,S_{yy}(f)}$$

其中 $S_{xx}$、$S_{yy}$ 是两信号的自功率谱，$S_{xy}$ 是互谱。相干是归因统计量而非因果证明——它只回答"多大的耳位噪声份额可以线性归到这个源"，方向由物理布置（源在车外、耳在车内）保证。

![外部阵列与车内耳位的相干分析：定位真正传入车内的外部源](/images/aero-acoustic-wind-tunnel/coherence-array-interior.png)

*（图源：网络 侵删）*

配对使用时还有一条工程捷径：把人工头双耳信号与阵列成像同屏显示，响度的时间历程（单位 sone）随试验状态切换实时更新——封堵底盘前后两条 95 百分位响度曲线当场分叉，比事后翻报告直观得多。

<details>
<summary>数值实验：涡脱落谱线与背景带的相干对比（点击展开）</summary>

```python
import numpy as np

rng = np.random.RandomState(3)
fs, L = 2048.0, 4096                    # 采样率与帧长
N = 20*L                                # 20 帧 Welch 平均
t = np.arange(N)/fs
# 车外信号: 后视镜涡脱落 300 Hz 单频 + 湍流宽带
ext = 1.0*np.sin(2*np.pi*300*t) + 0.6*rng.randn(N)
# 车内耳位: 同源分量经路径衰减相移 + 独立内饰背景
inn = 0.25*np.sin(2*np.pi*300*t + 0.4) + 0.5*rng.randn(N)
w = 0.5 - 0.5*np.cos(2*np.pi*np.arange(L)/L)   # 汉宁窗
Sxx = np.zeros(L//2+1); Syy = np.zeros(L//2+1)
Sxy = np.zeros(L//2+1, dtype=complex)
for k in range(20):
    A = np.fft.rfft(ext[k*L:(k+1)*L]*w)
    B = np.fft.rfft(inn[k*L:(k+1)*L]*w)
    Sxx += np.abs(A)**2; Syy += np.abs(B)**2; Sxy += A*np.conj(B)
g2 = np.abs(Sxy)**2 / (Sxx*Syy)         # 逐频率相干
f = np.arange(L//2+1)*fs/L
i300 = np.argmin(np.abs(f-300))
print(f"300 Hz 涡脱落谱线 γ² = {g2[i300]:.3f}")
bg = np.r_[g2[i300-40:i300-20], g2[i300+20:i300+40]]
print(f"两侧背景带平均 γ²     = {bg.mean():.3f}")
```

```text
300 Hz 涡脱落谱线 γ² = 0.996
两侧背景带平均 γ²     = 0.039
```

同源单频成分的相干接近满值 1，而不相关宽带背景被多帧平均压到接近 0——阵列逐格点与耳位算一遍这个量，"谁真正进了耳朵"就从主观印象变成了逐频率的数值排序。值得注意的是相干值依赖平均次数：帧数不足时背景带的 γ² 会被抬高，比较不同数据集务必核对统一的平均设置。

</details>

## 四、为什么"现场出结果"值钱：计算时间的账

归因链的道理不复杂，难的是把它塞进 8 小时的窗口。经典流程的瓶颈在后处理：以阵列成像为例，整车 5 cm 分辨率约 4000 个格点、400~10000 Hz 共 480 条谱线、10 秒数据，2012 年的多核工作站上单工况反演约 22 小时——试验日结束，图还没出来。工程师只能按预定计划测完收工，回去处理两周，发现"偏航角 -10° 时后视镜根部的成像异常"，再约下一轮风洞验证。一轮 8 小时、约 30~35 k$ 的窗口就这样被信息延迟吃掉一轮又一轮。

破局路线是公开技术资料列出的四步：CPU 算法优化、计算迁移到 GPU、GPU 算法优化、数据调度优化。同一参考算例（4000 格点、480 谱线、10 s 数据）的累计耗时从 22 小时压到 1.2 分钟，约 1100 倍加速。10 秒出图意味着什么？试验进行中，每个工况结束后处理结果已并排显示在控制室屏幕上——"10 秒与 5 分钟差在哪"的答案在于量变引起质变：一场试验动辄上百个工况，处理时间按工况数线性累积，5 分钟/工况在 36 个工况的矩阵上就是 3 小时的空转，而 10 秒/工况的总账不到 7 分钟，"边测边看"从口号变成默认工作方式。

speeds = np.array([100, 120, 140, 160])       # 风速档位 km/h

处理快只是必要条件，还要选得准、比得快。批处理界面允许按配置、风速、偏航角、频率范围、方法筛选要算的数据集，每个任务在 GPU 上后台排队执行、状态用颜色标注，测量一结束自动触发或在分析间隙手动提交；结果查看端任何两个数据集几次点击即可并排对比。这两件事共同支撑了流程上的真正分水岭：**试验计划从"固定脚本"变成"现场演化"**——测完第一批偏航角扫描，看图发现 -10° 附近密封条成像异常，当场把后续计划改成该角度附近的细扫与封堵对比，而不是回去写报告等下一轮。

## 五、一条完整的试验战役

把前面四节的能力串成时间线，一场现代声学风洞战役长这样。

**第一步：定义试验计划。** 风速×偏航角矩阵（100~160 km/h、±20°、5° 步长的 36 工况是典型起点），加上计划考察的状态修改：换后视镜、贴密封胶带、封堵底盘——往往一次战役里要测许多项修改。

![试验计划定义：风速与偏航角构成工况矩阵，状态修改穿插其间](/images/aero-acoustic-wind-tunnel/test-schedule.png)

*（图源：网络 侵删）*

**第二步：全自动采集。** 风洞控制系统把风速、偏航角调到目标值，采集自动开始，人工头、车内阵列、外部阵列、表面麦克风同步记录——同步由同一套系统保证，相干分析才站得住。控制室与多个屏幕实时显示各通道的声品质指标与成像结果。

**第三步：现场决策。** 上一节的"边测边看"在这里兑现：响度曲线分叉说明修改有效，相干图指认下一个疑点，试验计划当场调整。试验结束时数据、处理结果、工况标签已经归档成套，回去直接写报告。

**集成化的价值在细节里**：外部四阵列、车内球形相机、人工头、表面麦克风、机器人与底架传感器全部挂在一套采集与分析系统上，与风洞控制器联动（风速、偏航角自动入档），批处理与对比工具覆盖全场数据——工程师面对的是一个系统而不是一堆设备。经验丰富的风洞工程师的评价值得原文引用："能不能在试验现场分析和查看高级处理结果，是一个系统最关键的元素——它决定了你当场测对的东西，还是之后花大价钱重测一遍。"

**向前延伸**，试验战役之前是仿真迭代（概念阶段方案筛选），之后是闭环：试验数据标定仿真模型（如声学模态测试给舱内声腔模型提供基准），下一轮开发周期里仿真承担更多筛选、风洞只验证关键决策。研究侧的前沿同样围绕这条链展开：湍流边界层的随机数值重构与半经验建模、随机激励下舱内声振响应的仿真、风噪传递路径分析、上下车身与舱内的声学成像。设施侧的注脚来自 FKFS：其新一代声学风洞采用 300+ 通道麦克风阵列的集成方案，客户"每次试验获得的信息量超出预期"。

## 六、小结

风洞的价值不在"有一股风"，而在归因：外部阵列定位源、表面麦克风给路径激励、车内定位抓泄漏、耳位数据对主观——相干分析把四张图接成一条因果链。这条链能不能在 8 小时窗口里跑起来，取决于处理速度与流程设计：22 小时压到 1.2 分钟的阵列反演让"现场决策"成为默认工作方式，成本从 5 轮 150 k$ 降到 1 轮 30 k$。规划风洞战役时的三个判断标准：工况矩阵覆盖风速与偏航角两个维度再谈归因；状态修改与自动采集绑定，别把时间浪费在等风稳；数据、结果、工况标签一体归档，试验结束即报告就绪。

## 一句话记住

风洞试验按小时烧钱，省钱的方式不是少测，而是当场出结果：阵列成像压到分钟级、相干归因现场指认泄漏点、下一锤直接敲在图上最亮的地方——8 小时内闭环一轮，好过 5 轮 150 k$ 的事后诸葛亮。
