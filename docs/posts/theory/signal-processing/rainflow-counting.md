# 雨流计数：把随机载荷折算成疲劳损伤的会计方法

> 台架上做出来的 S-N 曲线是等幅对称循环的产物，而整车路试采回来的载荷谱是一团乱麻——大小循环叠在一起，均值还在漂。雨流计数（Rainflow Counting）就是把这团乱麻拆成一个个"等幅循环"的会计方法：拆完的账本可以直接代入 Miner 准则算累计损伤，进而预估构件寿命。本文从一维计数讲到雨流的四点法与残数处理，配上可运行的 numpy 演示，把耐久圈这套基本功讲透。

![典型的载荷-时间历程](/images/rainflow-counting/load-time-history.png)
*（图源：Simcenter Testing Knowledge Base）*

## 一、疲劳分析为什么不用频谱

NVH 工程师的直觉是"看谱"：FFT、自功率谱、colormap。但频率成分对疲劳几乎无关——材料的损伤累积不看载荷每秒振荡多少次，而看每一次幅值反复（reversal）有多大、处于什么水平。手册里说得很直接：做疲劳分析时，**特殊事件的出现率比载荷的频率成分更重要**。

所以耐久数据处理走的是另一条路：浏览时间历程，找出产生疲劳的典型事件并统计其发生概率。手册图 14-2 标出了三类基本事件：

- **规定量级的峰值出现率**——峰、谷落在哪个载荷档位（峰值计数）；
- **超越规定量级的出现率**——信号向上/向下穿越某条线多少次（跨越量级计数）；
- **幅值变化超过某量级的出现率**——相邻峰谷之间的落差（值域计数）。

整个处理分两步走：第一步**计数**，把时间历程压缩成事件序列；第二步**直方图**，把事件按量级分箱统计出现次数。时间波形从此退场，剩下的就是一本"载荷事件账"。

![数据迹线中的典型事件](/images/rainflow-counting/typical-events.png)
*（图源：Simcenter Testing Knowledge Base）*

::: info 核心概念
- **事件（Event）**：时间历程中一次产生疲劳损伤的基本动作，如一个峰、一次跨级、一个值域
- **计数（Counting）**：浏览历程、记录事件出现率的过程，输出峰-谷序列或矩阵
- **直方图（Histogram）**：对事件按量级分箱的统计结果，疲劳评估的输入
- **值域（Range）**：相邻峰谷之间的幅值差，升为正、降为负
:::

## 二、一维计数：三个各管一段的土办法

### 峰值计数

把数据迹线的折返点分成峰（极大）与谷（极小），统计各载荷量级上的出现次数，可以只统计峰、只统计谷或两者都统计。这是最朴素的"数峰"。

![峰-谷计数](/images/rainflow-counting/peak-valley-counting.png)
*（图源：Simcenter Testing Knowledge Base）*

### 跨越量级计数

统计信号幅值跨越不同量级线的次数，分向上（正）跨越与向下（负）跨越。它和峰值计数有严格的换算关系：**正向跨越某量级的次数，等于高于该量级的峰数减去高于该量级的谷数**——跨级计数完全可以从峰-谷计数导出。

![跨越量级计数](/images/rainflow-counting/level-crossing.png)
*（图源：Simcenter Testing Knowledge Base）*

### 单值域计数：对毛刺的灾难

统计连续峰谷之间的差值。问题在手册图 14-9 里暴露无遗：一个大循环上叠着小纹波时，单值域计数会把历程拆成一串小值域，直方图堆在低值域端——大循环被"偷"走了。把小变化滤掉再算，结果完全变样。**对小变化极端敏感**是它的死穴。

::: warning 一维计数的通病
峰值、跨级、单值域都只记"单一事件"，丢掉了事件之间的配对关系：一个 200 MPa 的峰跟着 -50 MPa 的谷，与跟着 +150 MPa 的谷，在直方图里长一个样，损伤贡献却差得远。二维计数法就是为补上这一维而生。
:::

## 三、二维计数：From-to、Range-mean 与雨流

### From-to 与 Range-mean：把配对关系记进矩阵

**From-to 计数**统计"j 量级的峰伴随 i 量级的谷"这类成对事件，结果放进马可夫矩阵 $A[i,j]$：元素 $a_{ij}$ 给出 j 级峰伴随 i 级谷的次数，左下三角装正向转变、右上三角装负向转变。同样是 C 到 A 的落差，谷 A 至峰 C、谷 B 至峰 D 会被记进不同的格子里——值域相同，路径不同，账分着记。

**Range-mean 计数**则把每一对极值折算成值域 $R = C - A$ 与均值 $m = (A+C)/2$ 两个数，落进一张值域-均值二维直方图。均值这一维在疲劳里不可省略：平均应力拉则折寿、压则延寿，Goodman 修正全靠它。

![Range-mean 计数直方图](/images/rainflow-counting/range-mean-counting.png)
*（图源：Simcenter Testing Knowledge Base）*

### 雨流计数：三步走的完整流水线

"值域对-值域"计数在日本被独立开发成著名的"雨流法"，两者结果完全相同。它的本质，是把历程理解为一个**主体变化（主值域）与叠加其上的小循环（值域对）**，逐一剥离：信号被分解为各有特定值域与均值的循环，结果可直接代入 Miner 准则做累计损伤计数，乃至简单的裂纹扩展计算。全过程三步：

**第 1 步：压缩成峰-谷序列。** 计数只看峰谷值，先做值域滤波（设置门坎 R）：某峰之后信号回落超过 R 才算有效峰，随后的谷要回升超过 R 才算有效谷。手册图 14-14 里 $e_3$ 被剔除，是因为信号降到 $e_4$ 时回落量不够——它只是主变化背上的一个小纹波。

![值域滤波：载荷历程压缩为峰-谷序列](/images/rainflow-counting/range-filter.png)
*（图源：Simcenter Testing Knowledge Base）*

**第 2 步：全序列值域对扫描（四点法）。** 取连续四个极值点，检查中间两个（$s_2$、$s_3$）构成的值域是否被两端（$s_1$、$s_4$）覆盖——判据写成：

$$|s_3 - s_2| \le |s_2 - s_1| \quad \text{且} \quad |s_3 - s_2| \le |s_4 - s_3|$$

满足则中间两点构成一个**闭合的值域对**（完整循环），计数后从序列中剔除，并用剔除后相邻的新四点组继续检验；不满足则窗口向前滑动一点。正是"剔除后回头重扫"这一步，把雨流与一锤子买卖的单值域计数区别开来。

**第 3 步：残数处理。** 扫描结束剩下的峰谷叫**残数（Residue）**——形如"发散段接收敛段"的一段挂账，其中包含全程最大值域（最低谷到最高峰）。残数按单值域计为**半循环**参与损伤。最大值域只能以半循环身份出现并不奇怪：如果最低谷在一段超长循环的起点、最高峰在其末端，把这两点硬凑成一个"完整循环"在物理上本来就牵强——账本对此保持诚实。

手册给了一个六极值的例子：从 $s_1$ 开始的四点组不满足判据，滑到 $s_2$、$s_3$ 仍不满足，直到 $s_3$ 到 $s_6$ 才计出第一个值域对；剩下四点再也拆不出"对"，成为残数，按 from-to 记单个半循环。

![雨流扫描示例：找出第一个值域对](/images/rainflow-counting/rainflow-example-scan.png)
*（图源：Simcenter Testing Knowledge Base）*

![雨流示例：残数按单值域计数](/images/rainflow-counting/rainflow-example-residue.png)
*（图源：Simcenter Testing Knowledge Base）*

::: tip 为什么叫"雨流"
把载荷历程旋转 90 度（时间轴竖直向下），想象雨滴沿峰谷"屋檐"流淌：小屋顶上流下的雨滴构成小循环，能一路流过大起伏的构成大循环。雨滴的每条流径就是一个循环——名字来自 Matsuishi 与 Endo 的原始比喻，四点法判据是它的算法化。
:::

## 四、从循环账本到寿命：Miner 准则

雨流输出的是一张"值域、均值、次数"三列的账。折算成损伤要走 Palmgren-Miner 线性累积：构件在等幅应力幅 $S_a$ 下寿命为 $N_f$，则一个整循环耗掉 $1/N_f$ 的寿命份额；损伤线性叠加，总和 $D=\sum n_i/N_i$ 到 1 时判失效。

寿命 $N_f$ 从 Basquin 型 S-N 曲线来。从定义出发分两步推导：

S-N 曲线在双对数图上是直线，即 $\lg S_a$ 每增加 1，$\lg N_f$ 线性下降 $1/k$（$k$ 是双对数斜率的倒数，钢在 HCF 区常取 8 上下）。写成直线方程：

$$\lg N_f = -\frac{1}{k}\,\lg S_a + b$$

把斜率截距换成幂律形式，$S_a$ 的 $-1/k$ 次方提到指数上：

$$N_f = C\,S_a^{-1/k \cdot k} = \left(\frac{S_C}{S_a}\right)^k$$

其中 $S_C$ 是 $N_f = 1$ 循环对应的参考强度（ Basquin 系数）。物理意义：应力幅每翻一倍，寿命缩到原来的 $2^{-k}$——k=8 时就是 1/256。这就是为什么大循环主宰账本：k 在指数上。

对每个雨流循环取 $S_a = R/2$（值域的一半，暂不做均值修正），代入得 $N_f$，再取倒数求和：完整循环记 $1/N_f$，残数半循环记 $0.5/N_f$。$k$ 差 1、寿命差一个量级——S-N 参数才是这套计算的命门。

::: warning 别让残数背黑锅
残数里躺着全程最大值域的半循环。若测段太短、最大事件没在段内"闭合"，半循环的损伤贡献被系统性低估。工程做法：用足够长的代表性工况段；或对残数半循环做敏感性分析；跨段拼谱时让残数进入下一段继续配对，而不是每段各算各的。
:::

## 五、Python 演示：亲手跑一遍雨流

### 从峰谷提取到值域滤波

```python
import numpy as np

def turning(x):
    """提取峰-谷序列：符号变化点即折返点"""
    d = np.sign(np.diff(x))
    i = np.where(d[:-1] != d[1:])[0] + 1
    return x[np.r_[0, i, len(x)-1]]

def range_filter(seq, R):
    """值域滤波：落差不足 R 的转折合并，极值保留更极端者"""
    out = [seq[0]]
    for p in seq[1:]:
        if abs(p - out[-1]) >= R:
            out.append(p)
        elif len(out) > 1 and out[-1] > out[-2]:
            out[-1] = max(out[-1], p)   # 峰候选：留更高
        else:
            out[-1] = min(out[-1], p)   # 谷候选：留更低
    return np.array(out)

rng = np.random.default_rng(3)
t = np.linspace(0, 330, 100000)
# 模拟实测应变信号：慢大循环 + 快小循环 + 噪声（单位 MPa）
sig = 300*np.sin(2*np.pi*0.02*t) + 120*np.sin(2*np.pi*0.9*t) \
      + 15*rng.standard_normal(len(t))

pv  = turning(sig)
pvf = range_filter(pv, 30.0)
print(f"原始峰谷 {len(pv)} 点 -> 值域滤波 R=30 后 {len(pvf)} 点")
```

运行结果要点：66350 个原始峰谷被 R=30 MPa 的门坎压到 21574 点——67% 的转折是噪声纹波，不滤掉它们，雨流账本会被小循环淹没。

### 四点法雨流 + Miner 损伤

```python
import numpy as np

def rainflow(pv):
    """四点法雨流：返回(完整循环, 残数半循环)，各为(值域, 均值)"""
    stack, cyc = [], []
    for p in pv:
        stack.append(p)
        while len(stack) >= 4:
            a, b, c, d = stack[-4:]
            # 中间值域被两端包含 -> 闭合小循环，剔除后回扫
            if abs(c-b) <= abs(b-a) and abs(c-b) <= abs(d-c):
                cyc.append((abs(c-b), (b+c)/2))
                del stack[-3:-1]
            else:
                break
    half = [(abs(stack[i+1]-stack[i]), (stack[i+1]+stack[i])/2)
            for i in range(len(stack)-1)]
    return cyc, half

cyc, half = rainflow(pvf)
print(f"完整循环 {len(cyc)} 个，残数半循环 {len(half)} 个")

# Basquin: S_a^8 * N = 1000^8 (MPa)，损伤 D = sum n_i / N_i
k, S_C = 8.0, 1000.0
r_full = np.array([r for r, _ in cyc])
r_half = np.array([r for r, _ in half])
D = np.sum((r_full/2/S_C)**k) + 0.5*np.sum((r_half/2/S_C)**k)
print(f"单块损伤 D = {D:.2e}，预期寿命约 {1/D:.0f} 块")
```

运行结果要点：21574 个峰谷拆出 10782 个完整循环加 9 个残数半循环；k=8 的 S-N 下单块损伤 1.25e-03，预期寿命约 802 块。值得盯的对比：值域 800+ MPa 的主循环只出现百余次，1 万个小循环的损伤贡献加起来还不到它的一半——**k 在指数上，大循环永远主宰账本**。

## 六、工程上怎么用、坑在哪

Testlab 里这条流水线对应 Time Data Processing 的疲劳预处理：转折点检测（Peak-Valley）、值域滤波（Range Filter）到雨流矩阵（Rainflow Matrix），输出的值域-均值直方图可直接送 TecWare 做疲劳寿命预估。整车耐久里典型的三个坑：

- **量程与门坎**。值域滤波门坎 R 常用量程的 1% 到 5% 起步。好消息是手册的明确结论：增大 R 只是删掉小于新 R 的转折点，**计数结果对 R 并不敏感**——R 从 R0 加到 3R0，From-to 矩阵里落差小于 3R 的元素才清零。门坎不必反复调，量程档位倒是要紧（参考量程与量化那篇）。
- **测段长度与残数**。见上文 warning，残数半循环的处理方式要在报告里写明，别让审校的人猜。
- **均值漂移**。路面谱常有静载偏置，Range-mean 矩阵的均值维别扔：做 Goodman/平均应力修正时它是输入，扔掉等于假设全部对称循环，偏保守也偏失真。

| 计数方法 | 记录的事件 | 输出形式 | 主要用途 | 短板 |
| --- | --- | --- | --- | --- |
| **峰值计数** | 峰/谷落在各量级的次数 | 一维直方图 | 快速看载荷分布 | 丢配对关系 |
| **跨越量级计数** | 上/下穿越各量级次数 | 一维直方图 | 与峰值计数互相校验 | 无幅值配对 |
| **单值域计数** | 相邻峰谷落差 | 一维直方图 | 简单值域统计 | 对小变化极敏感 |
| **From-to 计数** | 谷 i 至峰 j 的成对事件 | 马可夫矩阵 | 保留转变路径 | 不直接出循环 |
| **Range-mean 计数** | 值域 + 均值 | 二维直方图 | 平均应力修正输入 | 不拆嵌套循环 |
| **雨流计数** | 完整循环 + 残数半循环 | 值域-均值矩阵 | **疲劳损伤/寿命预估** | 依赖测段代表性 |

::: tip 选择原则
- 算疲劳寿命、裂纹扩展 -> 雨流计数，没有之二
- 要做平均应力修正 -> 雨流或 Range-mean，保住均值维
- 只是快速摸底载荷分布 -> 峰值/跨级计数，便宜快
- 数据带毛刺 -> 先值域滤波再雨流；门坎按量程 1% 到 5% 起步，不必精调
:::

## 七、小结

雨流计数的价值在于把"随机"翻译成"等幅"：嵌套的大小循环各归各账，残数诚实地挂着半循环的名。它是连接实测载荷谱与 S-N 曲线的桥梁，Miner 损伤和的每一分都从这本账上来。判断标准三条：疲劳数据处理用雨流而非一维计数；值域滤波门坎不敏感、量程和测段长度才是要盯的；均值维保留，寿命预估前的平均应力修正靠它。
