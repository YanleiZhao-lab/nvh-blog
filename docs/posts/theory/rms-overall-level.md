# RMS 与总级：从时域到频域的能量守恒

> 同一段信号，时域算出来的 RMS 和频谱里所有谱线平方和开根号，理论上分毫不差——这就是 Parseval 定理保证的能量守恒。但工程现场经常对不上：忘了能量校正、谱线不是 RMS 格式、或者拿平方单位的自功率谱直接硬算。这篇把 RMS 幅值格式、谱的总级（Overall Level）、跟踪总级三层概念拆开，并给出手动复算时最容易漏的三件事。

## 一、为什么平均值为零的信号也有能量

声压波在正负帕斯卡之间振荡，一个周期平均下来是零。如果零就代表"没有"，麦克风岂不是白工作了？问题出在"平均值"不是衡量能量的正确统计量。

真正代表信号做功能力的是**均方根值（Root Mean Square, RMS）**：把波形平方（负半周翻上来）、平均、再开根号。对峰值幅度 A 的单一正弦波，RMS = A 除以根号 2，约 0.707A。这个数的物理含义是：一个幅度为 0.707A 的稳定直流，与该正弦波等效发热——所以 RMS 又叫**等效稳态值**。

频谱里的每条谱线本质上都是一个正弦波，因此谱线也有 Peak、RMS、Peak-Peak 三种幅值格式。峰值 1.000 g 的谱线，换成 RMS 格式就是 0.707 g——同一条数据，换了把尺子量而已。

::: info 核心概念
- **RMS**：信号平方平均后开根号，代表振荡信号的等效稳态能量，正弦波为峰值的 0.707 倍
- **幅值格式（Amplitude Format）**：谱线幅值的单一线性表达方式，分 Peak / RMS / Peak-Peak 三种，属显示层概念，不改变数据本身
- **总级（Overall Level）**：一个频段内全部谱线平方求和再开根号得到的单一数值，就是一个频谱的 RMS
:::

## 二、谱的 RMS：把所有谱线的能量加回去

整条频谱的 RMS 是一个数：对关心频段内的每条谱线平方求和、开根号（Root Sum Square）。它回答的问题是"这个频段里总共装了多少能量"，与某根谱线多高是两回事——一条平坦低矮的宽带谱，总级可能超过一根高耸的窄带线。

为什么平方和可以直接相加？因为不同频率的正弦波相互**正交**，互不贡献能量，各谱线能量简单叠加——这与分贝一篇里"能量叠加"是同一条物理。理论根基是 **Parseval 定理**：时域平方的积分等于频域各分量平方之和，时域算 RMS 与频域算总级殊途同归：

$$X_{rms} = \\sqrt{\\sum_{k=0}^{K} A_k^2}$$

手动复算时有三个前置条件，缺一个数字就不对：

| 前置命令条件 | 错误做法 | 后果 |
| --- | --- | --- |
| **谱线必须是线性单位** | 拿 Pa 平方或 g 平方单位（自功率谱）直接开算 | 单位混乱，结果无意义，须先开根号变回 Pa / g |
| **谱线必须是 RMS 格式** | 拿 Peak 格式谱线平方求和 | 结果偏大 1.414 倍（约 +3 dB） |
| **必须施加能量校正** | 加了汉宁窗却未乘 1.633 | 总 RMS 系统性偏低 |

Simcenter Testlab 替用户挡掉了这些坑：无论屏幕上显示的是 Peak 还是幅值校正格式，后台计算 RMS 时一律自动转换成**线性、RMS、能量校正**数值。所以会出现"两条曲线面积肉眼可见不同、图例里 RMS 读数却一样"的现象——不是 bug，是软件在幕后换了正确的尺子。

::: warning 工程注意
从别的软件或自编脚本导出的谱，没有这层后台保护。三个前置条件逐一核对：单位开根号了吗？Peak 还是 RMS？加窗了吗、能量校正乘了吗？最常见的翻车是拿汉宁窗幅值校正谱直接算总级——谱峰好看，能量偏大 22%，详见[窗函数修正系数](./window-correction-factors.html)。
:::

## 三、跟踪总级：让能量随转速走

怠速抖、巡航吵、加速轰——整车的 NVH 问题几乎都随工况变化。单看某一次平均的频谱回答不了"哪个转速能量最大"，于是有了**跟踪总级（Tracked Overall Level）**：按转速或时间切片，每个增量算一次频谱及其 RMS，再把一串 RMS 对转速画成曲线。

比如从 3500 到 4000 RPM 每 25 rpm 取一片，每片算一个总级，连成曲线后，能量异常的转速区间一目了然——哪个峰值对应哪阶激励、与主观感受的"轰鸣点"是否吻合，判断就有了定量依据。这比彩色云图上肉眼扫一遍客观得多，也是阶次切片、传递路径分析定位前的常规第一步。

在 Testlab 里的路径：测量模式设为 **Tracked**，Section Settings 里 Overall Level 标签页勾选 Overall level，数据存到 Sections 目录下的 Overall Level 文件夹。图上取总级则更简单：图例右键 Options 里 Calculated Content 加 RMS（全频段），或双光标框住频段后右键 Calculations 里 RMS（部分频段）。

## 四、Python 演示：时域、频域、格式转换三处对账

用一段可复现的合成信号验证：时域直接算的 RMS、按前置条件正确合成的频域总级、以及故意犯错（拿 Peak 格式硬算）的结果，三者摆在一起。

```python
import numpy as np

N, fs = 8192, 8192.0
t = np.arange(N) / fs
# 怠速进气噪声风格: 300 Pa 峰值正弦 + 宽带随机
x = 300.0*np.sin(2*np.pi*180.0*t) + 90.0*np.random.RandomState(7).randn(N)

rms_time = np.sqrt(np.mean(x**2))              # 时域直接算 RMS（真值）
w = 0.5 - 0.5*np.cos(2*np.pi*np.arange(N)/N)   # 手写汉宁窗
eng = np.sqrt(N / (w**2).sum())                # 能量校正系数（应为 1.633）

X = np.abs(np.fft.rfft(x*w)) * 2/N * eng       # 加窗+能量校正，单边 Peak 格式谱
X[0] = np.abs(np.fft.rfft(x*w))[0] / N * eng   # 0 Hz 谱线无镜像配对，不乘 2
X_rms = X / np.sqrt(2)                         # 谱线换算成 RMS 格式

overall_ok  = np.sqrt((X_rms**2).sum())        # 正确: RMS 格式谱线合成总级
overall_err = np.sqrt((X**2).sum())            # 犯错: 拿 Peak 格式硬算

print(f"时域 RMS（真值）      = {rms_time:8.3f} Pa")
print(f"频域总级（RMS 格式）  = {overall_ok:8.3f} Pa  偏差 {abs(overall_ok-rms_time)/rms_time*100:.2f}%")
print(f"频域总级（Peak 硬算） = {overall_err:8.3f} Pa  偏差 {(overall_err/rms_time-1)*100:+.1f}%")
```

运行结果要点：时域真值与按规矩合成的频域总级偏差不到 1%，残余误差来自汉宁窗能量校正后谱线间的能量插值；而拿 Peak 格式谱线硬算的那行，结果正好偏大 1.414 倍即 +3.0 dB——表格里第二条前置条件的代价，一眼可见。

## 五、小结

RMS 是能量的语言：单条谱线谈 RMS 格式，整条谱谈总级，随工况变化的谱谈跟踪总级。判断标准就四条——比较能量永远用 RMS；手动合成总级前核对线性单位、RMS 格式、能量校正三件事；Testlab 图例里的 RMS 可信，后台已自动换算；能量随转速怎么变，用 Tracked 模式的 Overall Level 曲线回答，别在彩色云图上用肉眼估。
