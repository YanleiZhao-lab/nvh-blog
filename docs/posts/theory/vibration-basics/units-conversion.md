# 单位制换算：EU 体系与常见陷阱

> 同一次振动测试，两份报告一份写 5.2 g、一份写 52 g，相差整整 10 倍——传感器没换、数据没重采，差的只是通道设置里一行灵敏度。数据采集链里的单位换算像换汇：采集卡记下的电压是一笔外币存款，灵敏度就是汇率，汇率录错，账面本币整体偏多偏少，外币本身分毫未动。本文从 SI 参考单位与工程单位（EU）的换算链讲起，盘点 g 与 m/s²、dB 参考、有限元单位制、模态参数量纲四类高发陷阱，并给出测量链各环节的核对方法。

## 一、为什么同一份数据能差出 10 倍

先看一个真实到不能再真实的场景。一台设备测点加速度计输出电压峰值 0.52 V，灵敏度 100 mV/g。交接班后同事新建了通道组，灵敏度一栏照抄了上一批小量级传感器的 10 mV/g——电压还是那个电压，软件按 10 mV/g 一除，读数从 5.2 g 变成 52 g。这份数据若进入报告，等效于把振动严酷度夸大 10 倍；若用于疲劳分析，损伤按幅值的幂律放大，结论完全失效。错误不在测量，而在“汇率”：电压这笔存款一分没动，换算成本币的账面数字却翻了 10 倍。

把这件事想透，需要先接受一个看似多余的事实：**采集系统真正“看见”的从来不是加速度，而是电压**。压电加速度计把加速度变成电荷，电荷放大器把电荷变成电压，ADC 把电压变成数字。整条链上物理量换了三次“货币”，每一次兑换都需要一个汇率——灵敏度。软件最终展示给你的那个带单位的数（g、m/s²、Pa），是电压经汇率换算后的账面值，业内称为工程单位（Engineering Unit, EU）。

既然是换汇，就有两问：汇率从哪来、账本以什么本位记账。前者是通道校准，后者是单位制——测试与分析软件几乎都以国际单位制（SI）为本位：长度 m、质量 kg、时间 s、电流 A、温度 K、角度 rad、发光强度 cd 七个参考单位，其余单位全部由此组合。理解了“一个本位、多次兑换”，后面所有陷阱都只是这两问的具体变形。

::: info 核心概念
- <strong>工程单位（Engineering Unit, EU）</strong>：由传感器电压按灵敏度换算得到的带物理单位的量值，如 g、m/s²、Pa，是数据账面上的“本币读数”
- <strong>参考单位（Reference Unit）</strong>：单位制的基本量纲单位。测试分析软件内部与数据库一律采用 SI 参考单位，组合单位按 SI 规则由参考单位构成
- <strong>灵敏度（Sensitivity）</strong>：传感器输出的电压（或电荷）与被测物理量之比，如 100 mV/g、4.3 pC/g，是电压到 EU 的“汇率”
:::

## 二、EU 换算链：从一个电压到一个带单位的数

### 2.1 账面读数怎么来

这个公式回答的问题是：电压这笔“外币”按什么规则换成工程单位的“本币”——读数等于电压除以灵敏度，其中 $V$ 是采集到的电压，$S$ 是通道灵敏度（如 100 mV/g），$x$ 即账面上的工程单位量值。

$$x_{\mathrm{EU}} = \frac{V}{S}$$

汇率录错 10 倍，账面就读错 10 倍——第一节 5.2 g 与 52 g 的分歧就是这个式子最直接的注脚。反过来，它也给出修正路径：不需要重测，只要把错误的汇率改正后重算一遍，账面即可恢复（多数分析软件支持对已存数据重校准）。

### 2.2 本位制：七个参考单位组合一切

SI 本位并不是七个单位的简单罗列，而是一套组合规则：任何组合单位的量纲都能拆回参考单位的幂次积。加速度是长度除以时间平方（m/s\u00b2），力是质量乘加速度（kg·m/s\u00b2，即 N），声压是力除以面积（kg/(m·s\u00b2），即 Pa）。下表是相关技术手册给出的参考单位一览，测试软件内部数据结构与数据库存储均以此为准。

*（图源：网络官方公开资料）*

![一切工程单位都由 SI 参考单位组合而成：加速度、力、声压、功率谱密度的量纲链](/images/units-conversion/fig2-dimension-chain.png)
*（图源：网络官方公开资料）*

这张量纲链的价值在于排错：当两个数相乘除得到一个新量时，把单位按链拆开核对一遍，量纲对不上必然有错。功率谱密度（PSD）的单位 $(m/s^2)^2/\mathrm{Hz}$ 看起来陌生，拆开就是“加速度的平方每赫兹”——随机振动的能量按频率分布的密度，量纲链一步就能还原它的物理含义。

## 三、四类高发陷阱

### 陷阱一：g 与 m/s\u00b2——差一个 9.80665

最频繁也最隐蔽的错误是重力单位与 SI 单位的混用。标准重力加速度 1 g = 9.80665 m/s\u00b2，0.5 g 即 4.90 m/s\u00b2。单次换算很少出错，出错的是**多层嵌套**：PSD 从 $(m/s^2)^2/\mathrm{Hz}$ 换到 $g^2/\mathrm{Hz}$ 要除以 $9.80665^2$——是除一次还是除两次、还是取平方根，三个选项总有人选错。而 dB 域还有第三层：两者相差 $20\lg 9.80665 \approx 19.8$ dB，随机振动规范里写 $-33.8\ \mathrm{dB\ re}\ 1\ g^2/\mathrm{Hz}$ 的谱，换到 SI 域就是 $0.04\ (m/s^2)^2/\mathrm{Hz}$，总均方根值 $\sqrt{0.04 \times 500} = 4.47\ m/s^2$，即 0.456 g_rms。单位在 g 与 m/s\u00b2 之间来回切换时，每一次都值得在纸面写一遍量纲。

![对数轴上 g 与 m/s²一一对应：换算只差一个因子，嵌套换算才是出错高发区](/images/units-conversion/fig3-g-ms2-ruler.png)
*（图源：网络官方公开资料）*

### 陷阱二：dB 的参考下标——同一个“dB”不可比

这个公式回答的问题是：分贝数与线性幅值比怎样互算——比值取十为底的对数再乘 20（场量）或 10（功率量），其中 $a$ 是线性比。

$$L = 20\lg\frac{a}{a_0}\ \ (\text{场量}), \qquad L = 10\lg\frac{P}{P_0}\ \ (\text{功率量})$$

dB 本身只是比值：+6 dB 约两倍，+20 dB 十倍。但工程语境里 dB 后面永远拖着一个参考——声压级 re 20 μPa、声功率级 re 1 pW、加速度谱密度 re 1 g\u00b2/Hz。两个都叫“dB”的数，参考不同就不可比：94 dB re 20 μPa 与 94 dB re 1 pW 是完全不同的物理量。报告里 dB 值若不带参考下标，这个数就是悬空的。

![分贝与线性比的换算锚点：+6 dB 约 2 倍，+20 dB 恰好 10 倍](/images/units-conversion/fig4-db-linear.png)
*（图源：网络官方公开资料）*

### 陷阱三：有限元的 mm-t-s 单位制——刚度差出 1000 倍

试验数据对接有限元模型时，单位制的坑从测试侧挪到了仿真侧。FE 软件不强制单位制，只要求**自洽**：长度用 mm、应力用 MPa，则质量必须用吨、密度必须是 t/mm\u00b3。钢的参数在两套本位下分别是 $E = 2.1\times10^{11}\ \mathrm{Pa}$、$\rho = 7850\ \mathrm{kg/m^3}$（SI）与 $E = 210000\ \mathrm{MPa}$、$\rho = 7.85\times10^{-6}\ \mathrm{t/mm^3}$（mm-t-s）。参数混用一套本位——比如长度 mm 配密度 kg/m\u00b3——算出的固有频率会差 $\sqrt{1000}$ 倍量级，模态对标时“频率全对不上”的第一嫌疑人就是它。相关技术手册在结构修改一节同样强调：质量、刚度、桌架元件的截面、弹性模量、密度等参数“均应按统一的单位制来表示”。

### 陷阱四：模态参数的量纲——留数有量纲，振型没有

前三类陷阱是“数换算错了”，第四类更根本：**有些量的单位本身就取决于标尺的选取**。模态分析中，极点与频率的量纲是时间倒数（Hz）；模态振型系数本身无量纲——它只描述各点振动的相对大小；而留数是有量纲的，其量纲与测得的 FRF 一致，由比例常数赋予。相关技术手册特别提醒：留数等于振型系数之积乘以比例常数，这个常数取决于振型标尺的设定；采用质量归一化标尺时，模态质量扮演比例常数角色。因此两份模态分析结果若振型标尺不同，直接比较留数幅值没有意义——必须先统一标尺（如都归一到驱动点），这正是修改预测与模型对标前必做的一步。

## 四、numpy 演示：把四类陷阱各算一遍

下面这段代码自包含地复现本文所有关键数值，可粘贴运行核对：

```python
import numpy as np

g0 = 9.80665                                # 标准重力加速度

# 陷阱一：EU 换算与灵敏度错误
V, sens_t, sens_w = 0.52, 0.100, 0.010      # 电压 V；正确/错误灵敏度 (V/g)
print(f"正确 100 mV/g: {V/sens_t:.1f} g | 误用 10 mV/g: {V/sens_w:.1f} g")

# PSD 嵌套换算：(m/s^2)^2/Hz -> g^2/Hz -> dB
psd_si = 0.04
psd_g = psd_si / g0**2
print(f"PSD {psd_si} (m/s^2)^2/Hz = {psd_g:.6f} g^2/Hz "
      f"= {10*np.log10(psd_g):.1f} dB re 1g^2/Hz")   # -33.8
print(f"总 RMS: {np.sqrt(psd_si*500):.2f} m/s^2 = "
      f"{np.sqrt(psd_si*500)/g0:.3f} g_rms")          # 4.47 / 0.456

# 陷阱二：dB 与线性比
for r in (0.5, 2, 10, 100):
    print(f"线性比 {r:>5} -> {20*np.log10(r):+.0f} dB")

# 陷阱三：两套自洽单位制
E, rho = 210e9, 7850.0
print(f"SI:     E={E:.1e} Pa, rho={rho} kg/m^3")
print(f"mm-t-s: E={E*1e-6:.0f} MPa, rho={rho*1e-9:.3g} t/mm^3")
```

运行输出与正文一致：5.2 g 对 52 g、PSD 换算 -33.8 dB、0.456 g_rms、两套单位制的参数对照。数字过一遍手，比读十遍提醒都管用。

## 五、测量链上的核对方法与 Testlab 落地

![测量链五个环节，每一环都是单位出错的高发点](/images/units-conversion/fig5-pipeline-risks.png)
*（图源：网络官方公开资料）*

单位问题的难处在于它从不报错——软件不会提示“你的灵敏度差了 10 倍”，它只是安静地给出一个错误的账面值。对策是把核对嵌入流程：

1. **通道层**：在 Testlab 的 Channel Setup 中逐通道核对灵敏度与 EU，校准器现场校准（如声级校准器 94 dB/1000 Hz 对声通道、激振台已知加速度对振动通道）是唯一闭环；通道复制上一批配置时，灵敏度是最该盯的一行。
2. **显示层**：工作表中同一通道可在 m/s² 与 g 之间切换显示，软件按内部 SI 本位换算——切换显示不改变存储数据，但报告截图务必带上单位。
3. **导出层**：导出 CSV/UFF 时列名与单位必须成对检查；UFF 格式自带单位字段，文本导出则靠人工，是“数字与单位脱节”的高发口。
4. **对标层**：FE 对接前先做单位制三问（长度、力、质量各用什么），再取一根梁的解析解（如悬臂梁一阶频率）验证模型单位自洽；模态数据对标先统一振型标尺再看留数。

一个低成本的全程校验习惯：任取一段稳态数据，人工用电压除灵敏度手算一个点位的 EU，与软件读数比对；再取总均方根值，用 $\sqrt{\sum \mathrm{PSD}\cdot\Delta f}$ 手算一遍与报告值比对。两处都对，整条换算链基本无虞。

## 一句话记住

采集卡只认电压、软件只存 SI：EU 是电压按灵敏度换来的账面值——g 差 9.80665、dB 差在参考下标、FE 差在单位自洽、留数量纲差在标尺；换算嵌套处手算一遍，胜过十遍提醒。
