# 雨流计数进阶：Range-Mean 与 From-To 两种矩阵差在哪

> 同一段载荷历程、同一套雨流算法，两份报告一份给"值域-均值"矩阵、一份给"自…至"矩阵，拿去做寿命预估结果对不上——差不在算法，在矩阵记的是两本不同的账。本文用一组转折点的具体例子把两种计数拆开对表：From-To 记"从哪来、到哪去"的路径账，Range-Mean 记"落差多大、中心在哪"的循环账；两者可以互相换算、各有不可替代的用途。就像快递单只写"从北京发往上海"，行程单写"全程 1200 km、途经济南"——一张管路线归属，一张管里程与驻点。

疲劳数据分析做到深处，几乎人人都会遇到同一个岔路口：雨流计数做完了，软件让选输出矩阵的形式。选 Range-Mean，得到一张"值域-均值"二维直方图；选 From-To，得到一张"起点-终点"的转移矩阵。看起来只是排布不同，但把同一份路试数据分别按两种矩阵送进寿命预估，结果会有出入；想解释这个出入，就得回到两种计数法记的到底是不是同一件事。这篇就从一维计数的短板讲起，把两种二维矩阵的定义、换算关系与工程取舍一次讲清。

## 一、为什么一维计数不够：同是 6 级落差，账却记飞了

先看一个具体场景。某 SUV 后悬架控制臂的路试载荷历程里，载荷从谷 -2 级爬到峰 +4 级的翻转出现了一批，从谷 +1 级到峰 +7 级的翻转也出现了一批。做单值域计数时，这两批事件全部落进"值域 6"的同一根直方柱——计数值翻倍。但直觉就知道这两批事件对疲劳的"杀伤"不同：前者中心在 +1 级（拉压各半），后者中心在 +4 级（整段都泡在拉伸区），平均应力一拉一压，寿命差出数倍。直方图把这层信息压扁丢掉了。

![典型的载荷-时间历程](/images/cycle-counting-methods/fig1-load-history.png)

*典型的载荷-时间历程：330 秒车辆部件实测，疲劳分析关心的是事件出现率而非频率成分（图源：网络官方公开资料）*

这不是单值域计数独有的毛病。峰值计数只记"峰落在哪一级"，谷和峰的配对关系丢了；跨越量级计数只记"穿过哪一级几次"，同样不知道每次穿越连着多长的值域。一维计数把"单一事件的出现率"统计得很好，但疲劳损伤是由**一对极值（一个谷带一个峰）**共同决定的，一维直方图天生记不下"成对"信息。要把配对关系留下来，就得升到二维：这就是 From-To 与 Range-Mean 两种矩阵的出发点。

::: info 核心概念
- **值域（Range）**：一对相邻峰谷的落差，峰减谷，恒为正
- **均值（Mean）**：同一对峰谷的中点，(峰+谷)/2，代表这一段循环的静态偏置
- **From-To 计数（自…至…计数，From-To Counting）**：二维计数法，记录"j 级峰伴随 i 级谷"这类成对事件的出现次数，结果存入马可夫矩阵
- **Range-Mean 计数（值域-均值计数，Range-Mean Counting）**：二维计数法，把每对极值折算成值域与均值两个数再计数，结果存入值域-均值二维直方图
:::

打个贯穿全文的比方。把载荷历程想成**一个人在山谷间徒步的足迹**：谷是海拔低点、峰是高点。From-To 矩阵像一本**路线日志**——每次爬坡都记"从哪个营地出发、登上了哪座峰"，从 A 营地到 C 峰和从 B 营地到 D 峰哪怕高差一样，也分两页记，因为它关心走的是哪条路；Range-Mean 矩阵像一本**体能日志**——每次只记"这一趟爬升多少米、平均海拔多少"，至于从哪儿出发，翻篇不问。同一段足迹可以誊出两本日志：路线日志页数多、能反推地形结构，体能日志直奔主题、直接对接训练强度（疲劳损伤）。后面所有差异，都能用这两本日志讲清楚。

## 二、From-To 计数：把路径记进马可夫矩阵

From-To 的计数对象是"成对事件"。相关技术手册给的定义：像 j 量级的峰伴随 i 量级的谷这样的组合，逐一计数，结果放进马可夫矩阵 $A[i,j]$——元素 $a_{ij}$ 记录"j 级峰伴随 i 级谷"的次数。

![From-To 计数](/images/cycle-counting-methods/fig3-fromto.png)

*From-To 计数：谷 A 至峰 C 与谷 B 至峰 D 值域相同，但记入矩阵不同元素（图源：网络官方公开资料）*

关键在配图里这个例子：谷 A 至峰 C 的转移、谷 B 至峰 D 的转移，两组事件值域完全相同（C−A = D−B），但因为**出发地不同**，进了不同的格子。这正是"路线日志"的特性：同样 6 级的落差，从 -2 到 +4 与从 +1 到 +7 在矩阵里是两个元素，各自计各自的次数。

这个公式回答的问题是：**每一对"谷到峰"的转移，该落到矩阵的哪一格、怎么读出来？** 行坐标给终点（峰的量级），列坐标给起点（谷的量级），一对转移落一格，矩阵把整段历程的所有转移全额收纳。

$$a_{ij} = \sum_t \mathbf{1}\!\left[\,\text{峰}(t)=j\ \text{且}\ \text{谷}(t)=i\,\right]$$

式中 $a_{ij}$ 是矩阵元素，$i$ 为谷的量级（起点），$j$ 为峰的量级（终点），$\mathbf{1}[\cdot]$ 为指示函数——条件成立记 1、否则记 0，对全程求和就是该组合出现的总次数。

![From-To 计数结果：马可夫矩阵](/images/cycle-counting-methods/fig7-fromto-matrix.png)

*From-To 计数结果存入马可夫矩阵：左下三角为正向转变、右上三角为负向转变，两侧附加列为峰、谷单独计数（图源：网络官方公开资料）*

矩阵的读法有讲究：**左下三角装正向转变**（谷到峰，载荷上升），**右上三角装负向转变**（峰到谷，载荷下降）。两侧附加列分别写入特定量级上峰和谷的计数，由上、下三角直接求和即得——峰谷计数可以从 From-To 矩阵导出，反向不行。

From-To 矩阵的价值在"路径保真"：它保留了历程的转移结构，做时域信号重构、极值序列重建、马尔可夫链载荷建模时，它是唯一能还原"下一步去哪"的矩阵。代价也直白：它不直接给出循环——一个完整循环要一升一降两次转移配对才成立，From-To 矩阵本身不完成这个配对。

## 三、Range-Mean 计数：把路径折算成循环

Range-Mean 走另一条路：不问从哪来，直接把每对极值折算成两个数——值域与均值。设谷为 $A$、峰为 $C$：

![Range-Mean 计数](/images/cycle-counting-methods/fig4-rangemean.png)

*Range-Mean 计数：取代 A、C 实际量值，只记值域 C−A 与均值 (A+C)/2（图源：网络官方公开资料）*

这组公式回答的问题是：**一对"谷-峰"转移，能不能折算成两个直接用于疲劳评估的数？** 可以——值域定"幅值杀伤力"，均值定"静态偏置"，S-N 数据与平均应力修正要的输入恰好就是这两个量。

$$R = C - A, \qquad m = \frac{A + C}{2}$$

式中 $R$ 为值域（落差），$m$ 为均值（中点），$A$ 为谷值、$C$ 为峰值。对照徒步类比：$R$ 是"这一趟爬升多少米"，$m$ 是"平均海拔多少"。

![Range-Mean 计数直方图](/images/cycle-counting-methods/fig5-rangemean-hist.png)

*Range-mean 计数结果：值域、均值与出现次数的三维直方图（图源：网络官方公开资料）*

值域、均值与出现次数的关系用三维直方图表示：横轴值域、纵轴均值、高度出现次数。第一章那批"同是 6 级落差"的事件，在 Range-Mean 直方图里分道扬镳——中心 +1 级的落进均值 +1 的一格，中心 +4 级的落进均值 +4 的另一格，杀伤力的差异被保留下来。均值维在疲劳评估中不可省略：平均应力拉则折寿、压则延寿，Goodman 修正以它为输入。

但 Range-Mean 也有它的盲区。它记的是"一对极值折算出的一个量"，历程里若存在嵌套——大循环里套着小循环（比如一次大爬升途中折返了两小段），Range-Mean 会把大折返与小循环各自的"值域-均值"分别记下，却**不记录它们谁套着谁**。想知道"哪次大循环载着哪批小循环"，得回到 From-To 的路径账，或者用雨流计数把嵌套关系拆出来。

## 四、两种矩阵对表：同一段历程两本账

把两种矩阵并排放，差异一目了然：

| 对比项 | From-To 矩阵 | Range-Mean 矩阵 |
| --- | --- | --- |
| **记录单元** | 一次转变（谷→峰或峰→谷） | 一对极值折算的值域+均值 |
| **矩阵形状** | 量级×量级的方阵（马可夫矩阵） | 值域×均值的二维直方图 |
| **同值域不同起点** | 记入不同元素 | 均值不同则分开、均值相同则合并 |
| **路径信息** | 完整保留（可重构时域） | 丢失（只剩折算量） |
| **嵌套关系** | 隐含在序列中 | 不显式给出 |
| **疲劳预估** | 需再配对成循环 | 值域-均值直接查 S-N/平均应力修正 |
| **典型用途** | 载荷重构、马尔可夫建模、转变统计 | 疲劳寿命预估、平均应力修正 |

两种矩阵有明确的换算关系。从 From-To 到 Range-Mean 是"多对一"：把每个元素 $(i,j)$ 按公式折算出 $(R, m)$ 后累加即可，信息只减不增；反过来，从 Range-Mean 无法唯一还原 From-To——同一组值域-均值可以来自不止一种"起点-终点"组合，路径信息在折算时已经丢了。这正对应徒步类比：体能日志能从路线日志誊出来，路线日志没法从体能日志倒推回去。

那么工程上怎么选？**做疲劳寿命预估，Range-Mean（或雨流矩阵的值域-均值形式）是首选**——S-N 曲线要幅值、平均应力修正要均值，这两个输入它直接给；**做载荷重构、编制程序块谱、研究转变统计，用 From-To**——保路径才能保时序结构。多数耐久软件两者都输出：From-To 留作数据溯源与重构，Range-Mean 进疲劳计算流水线。

## 五、雨流矩阵：两种计数的合流

单独讲两种矩阵，绕不开它们的"合流点"——雨流计数。值域对-值域计数法（雨流法）把值域对计数原理与单值域计数原理相结合，从信号中提取同样的值域对和值域，本质是把历程分解为各有特定值域与均值的循环，结果可直接按 Miner 准则做累计疲劳损伤计数。

![值域对计数](/images/cycle-counting-methods/fig2-range-pair.png)

*值域对计数：把主值域与叠加的小循环（值域对）分开记（图源：网络官方公开资料）*

雨流计数的第一步是把载荷历程压缩为峰-谷序列，配值域滤波器（门坎 R）：只有当信号从前一峰降低至低于 R 给定的域值时该峰才被认可，随后寻找有效谷，以此剔除小纹波。

![载荷历程压缩为峰-谷序列](/images/cycle-counting-methods/fig6-peak-valley.png)

*值域滤波：门坎 R 剔除小幅转折，载荷历程压缩为有效峰-谷序列（图源：网络官方公开资料）*

计数结果通常也以值域-均值矩阵的形式输出（雨流矩阵），残数（含全程最大值域的发散-收敛段）按单值域原理以半循环参与。到这里能看清两种二维计数的分工：**From-To 回答"历程怎么走"，Range-Mean 回答"每一程多大、多偏"，雨流在 Range-Mean 的账本上补上"大循环套小循环"的嵌套拆分**，三者共同把一维直方图丢掉的配对信息找了回来。雨流算法的完整四点法流程与残数处理，见本站雨流计数入门篇，此处不再重复。

## 六、Python 演示：同一历程两种矩阵

下面用一段 12 个转折点的短历程，把 From-To 与 Range-Mean 两种矩阵算出来对表（自包含，可直接运行）：
```python
import numpy as np

# 一段峰谷交替的载荷历程（单位：级，等间隔采样已抽为转折点）
turns = [0, 4, -2, 3, 1, 6, -1, 2, -3, 5, 0, 2, -2]

# --- From-To 计数：每次转变记 (起点, 终点) ---
levels = np.arange(-4, 8)                    # 量级刻度 -4..7
FT = np.zeros((len(levels), len(levels)), int)
for a, b in zip(turns[:-1], turns[1:]):
    FT[b + 4, a + 4] += 1                    # 行=终点, 列=起点
print("From-To 矩阵（行=至，列=自），非零元素：")
for (to, frm), n in np.ndenumerate(FT):
    if n: print(f"  从 {levels[frm]:+d} 到 {levels[to]:+d}: {n} 次")

# --- Range-Mean 计数：每对极值折算 (值域, 均值) ---
RM = {}
for a, b in zip(turns[:-1], turns[1:]):
    R = abs(b - a); m = (a + b) / 2          # 值域与均值
    RM[(R, m)] = RM.get((R, m), 0) + 1
print("\nRange-Mean 计数（值域 R，均值 m），非零元素：")
for (R, m), n in sorted(RM.items()):
    print(f"  R={R:2d}, m={m:+.1f}: {n} 次")

# 对表：信息去向不同
print(f"\nFrom-To 非零元素 {np.count_nonzero(FT)} 个 vs Range-Mean {len(RM)} 种")
print("同为 R=5 的转变：From-To 按起点分开，Range-Mean 按均值分开")
```

运行结果：12 次转变，From-To 记 12 个非零元素——"从 0 到 +4"与"从 +1 到 +6"、"从 -2 到 +3"与"从 -3 到 +5"各自一格，起点不同就永不合并；Range-Mean 这段短历程里恰好也是 12 种组合，但坐标轴换成了值域与均值——值域同为 5 的四次转变分别落在 m=−0.5、+0.5、+2.5、+3.5 四个格子里，按"中心海拔"归队。短历程里两者格子数恰好打平，差别要在重复事件出现时才拉开：一旦历程里出现两批"值域、均值都相同、但起点不同"的转变，Range-Mean 合并计数、From-To 仍分开记账——这就是"路线日志"与"体能日志"在数据层面的分野。

## 七、工程应用要点

- **报告里写清矩阵类型**。两份耐久报告对不上，先核对输出的是 From-To 还是 Range-Mean（或雨流矩阵）——矩阵形状相似（都是二维），记的账不同，直接对比没有意义。
- **均值维不要丢**。路面谱常有静载偏置，Range-Mean 的均值维是平均应力修正的输入；丢弃均值维等于假设全部对称循环，结果偏保守也偏离实际。
- **值域滤波门坎不必精调**。相关技术手册的结论明确：计数结果对门坎 R 不敏感，R 从 R0 增至 3R0 才影响 From-To 矩阵中落差小于 3R 的元素。量程档位与测段长度才是更值得盯的变量。
- **测段长度影响残数**。最大值域出现在最低谷与最高峰之间（半循环），若两者分居超长记录的两端，应考虑物理上是否该把这样的事件组合在一起。

在 Testlab 的 Time Data Processing 中，From-To 与 Range-Mean 矩阵同在雨流结果页输出：雨流矩阵（值域-均值形式）直接送疲劳寿命流程，From-To 矩阵保留路径信息供载荷重构使用——软件同时给两本账，正是为了两条下游流水线。

## 八、小结

From-To 与 Range-Mean 不是竞争关系，而是同一历程的两本账：From-To 按"起点-终点"记路径，保转移结构、可重构时域，是载荷建模的原料；Range-Mean 按"值域-均值"记循环属性，直接对接 S-N 曲线与平均应力修正，是疲劳计算的输入。前者到后者多对一可换算、反向不可逆。判断要点三条：寿命预估用值域-均值（或雨流矩阵）、载荷重构用 From-To；报告必须写明矩阵类型；均值维保留，丢弃即引入系统性偏差。

## 一句话记住

From-To 是路线日志（从哪到哪、可倒推时域），Range-Mean 是体能日志（落差多大、中心多偏）；前者保路径供重构，后者直接对接 S-N 与 Goodman；多对一可换算，反向不可逆——对表先对账本。
